**症状** (100% 复现):

- `jhyy_v2_built.exe.exe` (Stage 2 binary, jhyy_v1 编 main.jhyy 出) 跑 `compile` → **SEGV exit 139, 0-byte output**（任何**非 `--help`** 的调用都会先读 `argv[1]`,故 `--help` 是唯一躲得开的路径）

**gdb smoking gun** (live attach jhyy_v2_built.exe.exe compile):
```
Thread 1 received signal SIGSEGV, Segmentation fault.
0x00007ff6b52939a9 in main_jhyy ()
=> 0x7ff6b52939a9 <main_jhyy+1097>:	mov    %eax,(%r8)
   r8 = 0x7ff6b5293919  (code address = main_jhyy+1063, ≈ code section 中某位置)
rax = 0x20c48349
rbp = 0x5ffdd0
```

`mov %eax,(%r8)` 把 32-bit eax 写到 r8 指向的 4 字节处, 但 r8 = code section 地址 (无写权限) → SEGV。

**binary disasm 揭示** (objdump -d /tmp/jhyy_v2_built.exe, main_jhyy 函数 at 0x140153560):

main.jhyy line 1709 `let argv_arr = argv as **u8;` (argv scan loop 入口) emit 后, argv_arr slot (`-0x2368(%rbp)`) 装 `lea -0x2008(%rbp),%rax` (= stack array 基址, size 0x2008 = 1024 entries * 8 bytes), 而非 argv 值。

后续 argv scan loop (line 1730-1778):
- `iter_val = argv_arr[0]` (read)
- argv_arr[0] 实际是 stack_array[0] (永远从 stack_array 基址 read, 不是 argv + iter_val*8)
- 写: `argv_arr[0] = new_iter_val` (write)
- argv_arr[0] 永远写 stack_array[0]
- iter 1024 次后, stack_array[iter_val] 越界 (出 stack frame 0x2008 范围) → 写 code section → SEGV

**真根因 = jhyy-side codegen 处理 `ptr_add_u8(struct_ptr, (field_b - 1) * 8)` multi-field-access 表达式 emit wrong**:

1. `argv as **u8` cast 在 jhyy-side codegen 走 `NODE_CAST` 路径 → `cg_convert_arg` no-op (cast 类型同 qbe_type L, return arg) — 正确
2. 但 `let argv_arr = argv as **u8;` (NODE_LET 路径) 在 jhyy-side codegen 走 **alloc stack slot 路径** (line 1851: `if (*d).is_mutable != 0 || is_array != 0 || is_struct != 0`) — **bug**: `is_array` check 对 `**u8` 类型 (KIND_POINTER) 应该 = 0, 但 emit 走 alloc path
3. alloc path 调 `ir_emit_alloc(slot, sz2)` where `sz2 = type_size(sym_t) = 0x2008` — **bug**: `type_size` 对 `**u8` 类型应该 = 8 (单一指针), 但返回 0x2008 (1024 entries * 8)
4. emit `lea -0x2008(%rbp),%rax; mov %rax,-0x2368(%rbp)` — argv_arr slot 装 `&stack_array` 而非 argv
5. 后续 `(*argv_arr)` 间接 dispatch 走 address-holder pool — 但 address-holder 已被 attempt #7 修独立 pool, 而 argv_arr slot 装 `&stack_array`, `*(argv_arr + iter_val*8)` 永远写 stack_array[0] (because argv_arr slot holds stack_array base, not argv base)

**W-097 entry 描述的 "ptr_add_u8((*cg).per_fn_max, ((*cg).cur_fn_idx - 1) * 8) multi-field-access 表达式 emit wrong" 是同根因 family** — emit 错让 per_fn_max 数组基址计算错 (emit 错 `lea` + `mov` 序列) + `cur_fn_idx - 1` 算式 emit 错 (e.g. 漏 emit `sub $0x1, %rax`)，结果 per_fn_max 数组 lookup 走 garbage offset → 后续所有 `per_fn_max[cur_fn_idx]` read 都 garbage → `cg_offset_for_temp_with_target(high_temp_id)` lookup 错位 → argv scan loop 写到 code section SEGV。

W-101 attempt #7 fix 让 Stage 1 (jhyy.exe 编 main.jhyy) frame_size 正确 + address-holder pool 独立 (物理 disjoint), **但 jhyy-side codegen 表达式 emit wrong 触发面仍存在** — attempt #7 是"绕开"触发面 (改 frame_size formula), 不是"真修" emit 路径。

**fix direction** (per W-097 audit checklist 第 146 行):
> W-097 真修: audit `emit_func_header` line 519/529/551 multi-field-access. Likely fix: hoist `(cur_fn_idx - 1) * 8` to a local var first, then `ptr_add_u8(per_fn_max, local_var)`.

具体: **emit 改写 = multi-step emit**:
1. emit local temp_var 算 `(field_b - 1) * 8` 表达式

### Step 1 — 1-iter RCA 验证 fix direction (per `feedback_rca_first_root_cause`)

**假设:** jhyy-side codegen 处理 `ptr_add_u8(struct_ptr, complex_expr)` 时, complex_expr 含 multi-field-access (e.g. `(*cg).field_b - 1`) emit 错。Hoist complex_expr 到 local var 后, emit 走 `local_var = (*cg).field_b - 1` (simpler pattern, no multi-field) + `local_var = local_var * 8` (simple mul) + `result = ptr_add_u8(struct_ptr, local_var)` (simple binop with local_var) — 触发面物理 disable。

**验证方法 (1-iter):**

1. **Read `codegen.jhyy:4230+` (emit_binop / emit_ptr_add) 段** — 当前 jhyy-side codegen 如何 emit `ptr_add_u8(struct_ptr, expr)` 调用
2. **Read `codegen_amd64_emit_ctrl.jhyy:519,529,551` (`emit_func_header` 段)** — W-097 trigger 25 sites 之一 (per audit checklist)
3. **Read `codegen.jhyy:1851` (NODE_LET alloc path)** — `is_array` check bug 对 `**u8` 类型误判
4. **Read `types.jhyy:355` (`type_size`)** — `**u8` 类型 size 应 = 8, 但 binary emit 走 0x2008 → bug 在 type_size 或 caller 误传

**verify min repro:** jhyy_v2 (Stage 2 binary) 跑 main.jhyy → SEGV (per 1-iter RCA 验证), fix direction apply 后 → EXIT 0 (Stage 2 path 真跑通, argv0 deref + jh_paths_init 跑通)。
