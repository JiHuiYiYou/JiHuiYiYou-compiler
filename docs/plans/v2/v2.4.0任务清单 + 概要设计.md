## Stage 2: byte-equal 三件套脚本

### 2.1 范围

#### 2.1.1 byte_equal.sh 新建
- `compiler/tests/bootstrap/byte_equal.sh`（新, ~180 行）：
  - 三个 byte-equal 检查:
    - `[1/3] .il byte-equal`: jhyy_v1 编 hello.jhyy 产 .il vs jhyy_v2 编同源产 .il byte-equal (closure gate, primary)
    - `[2/3] .s byte-equal`: 同上 .s (closure gate, QBE IL emit 确定性)
    - `[3/3] .exe byte-equal`: INFORMATIONAL 兜底 (V1 frozen predates recipe; 同 binary 两次现 byte-equal 但 cross-version V1↔V2 .exe diff — 标 INFO 不影响退出码)
  - 用 `compile --target=amd64_win <file>` 形式 (--target 在 compile 后, V1+V2 都支持)
  - 验证 5/5 PASS on target test (per `feedback_fix_evaluation_rule`)

#### 2.1.2 jhyy link line D26 recipe (`-g0 -Wl,--build-id=none` + `SOURCE_DATE_EPOCH=1234567890`)
- `compiler/src0/main.jhyy:link_with_gcc`（改, ~12 行新增）:
  - gcc cmd line 前置 ` -g0 -Wl,--build-id=none ` (禁 random build-id / debug info / timestamp 嵌入)
  - jh_run 前调 `jh_setenv("SOURCE_DATE_EPOCH", "1234567890")` 修 linker timestamp
- `compiler/src0/jhyy_helpers.c`（改, ~19 行新增）:
  - 加 `jh_setenv(name, value)` helper: Win32 `SetEnvironmentVariableA` (env 进 Win32 env block, child 经 CreateProcessW 继承) + POSIX `setenv` fallback
- `compiler/src/main.c`（仅注释更新, 无功能改动）:
  - 加注释说明 C-side `compile()` 只被 `jhyy_stage0.exe` 用 (构建时 tool, 不需 byte-equal), D26 recipe 实现在 src0/main.jhyy

### 2.2 依赖
- Stage 1 (dispatcher CLI 完整化)
- v2.0.0 ✅ shipped (target dispatcher)
- v2.1.0 ✅ shipped (ABI 抽离, byte-equal .il + .s 是 v2.1.0 验收的延续)

### 2.3 验收
1. **byte-equal 5/5 PASS**: `byte_equal.sh` 在 5 个 target test (`hello` / `struct_val_pass` / `fib_renamed` / `nested_struct_deep` / `big_test`) 上 5/5 PASS (.il + .s 各 5/5 = 10/10, .exe 5/5 INFO)
2. **same binary .exe byte-equal**: 同一 jhyy.exe 跑 hello.jhyy 4 次 → byte-equal .exe (sha=70f9667adb28d08e...)
3. **regress 持平**: `regress.py` 104/104 PASS, 0 failed, 4 skipped

### 2.4 风险
- **byte-equal deterministic output 难做**: v2.4.0 期间走 QBE 工具链 (byte-equal 稳定性靠 QBE 自身保证); v2.x 中期自写后端时 byte-equal 难度升级
- **.exe byte-equal 跨 V1↔V2 diff**: V1 frozen predates main.c D26 recipe → INFO 不影响 closure gate (.il + .s 才是 D26 primary invariant)
- **byte-equal 验证环境配置**: PATH 同时包含 jhyy_v1.exe.exe (v1.x shipped) + jhyy.exe (v2.4.0 编出); regress.py 用 JHYY_V1/JHYY_V2 环境变量
- **MinGW env propagation**: jhyy 走 `jh_run` (CreateProcessW), child 继承 parent env block. `_putenv` 也行但 `SetEnvironmentVariableA` 更明确 Win32 语义

## Stage 3: regress.py 集成

### 3.1 范围

#### 3.1.1 regress.py 集成 byte-equal 检查
- `compiler/build/bin/regress.py`（改, ~90 行新增）:
  - 加 `--byte-equal` argparse flag (opt-in; 不影响默认 `regress.py` 104/104 baseline)
  - 加 `test_byte_equal(tests=None)` 函数: subprocess 调 `bash byte_equal.sh` 跑 5 个 default tests
  - `shutil.which("bash")` 取 full path (Windows 上 bare "bash" 被解析到 WSL installer alias, 不是 MSYS2 bash)
  - `text=True, errors="replace"` 防 bash output 非 UTF-8 bytes crash reader thread
  - try/except 包 `subprocess.run`: timeout + generic exception → FAIL (per regression test 原则, 不静默吞错)
  - 5/5 PASS 必须 (per `feedback_fix_evaluation_rule`)

### 3.2 依赖
- Stage 1 + 2 (dispatcher CLI + byte-equal 三件套脚本)

### 3.3 验收
1. **regress.py 集成 byte-equal**: `python regress.py --byte-equal` 跑 byte-equal 检查, 5/5 PASS
2. **byte-equal 5/5 PASS**: 在 5 个 target test 上 byte-equal 5/5 PASS (per `feedback_fix_evaluation_rule`)
3. **总 regress 通过**: `python regress.py` (no flag) 104/104 PASS + `python regress.py --byte-equal` 5/5 PASS

### 3.4 风险
- **Stage 3 跨 Stage 1+2 集成**: Stage 3 是集成阶段, byte-equal + regress 任何回归都会反映
- **byte-equal 验证环境配置**: 双 jhyy binary 在 PATH 里要明确; 用户跑 regress.py 前文档化 JHYY_V1/JHYY_V2 环境变量
- **regress 退步**: Stage 3 第一步跑 regress.py 兜底, 跟 v2.3.0 baseline 对比; 退步立刻回滚
- **Windows bash 解析**: `subprocess.run(["bash", ...])` 在 Windows 上会被 App Execution Alias 解析到 WSL; 必须用 `shutil.which("bash")` 取 full MSYS2 路径
