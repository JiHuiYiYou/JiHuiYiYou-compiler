## Stage 1: abi_amd64_win 抽离

### 1.1 范围

#### 1.1.1 新建 abi_amd64_win.jhyy
- 从 `compiler/src0/codegen.jhyy` 抽离 Windows x64 ABI 逻辑到 `compiler/src0/target/abi_amd64_win.jhyy`：
  - `const ARG_REGS_WIN: [i32; 4] = [0, 2, 8, 9]`（rcx/rdx/r8/r9，per MS x64）
  - `const SHADOW_SPACE_SIZE: i64 = 32`（per MS x64）
  - `fn emit_win_func_prologue(ir, name, n_args)`：push rbp / mov rbp rsp / sub rsp / 保存非易失寄存器
  - `fn emit_win_func_epilogue(ir, n_args)`：mov rsp rbp / pop rbp / ret
  - `fn emit_win_call(ir, name, args, n_args)`：按 ARG_REGS_WIN 顺序放参数 + call
  - `fn classify_arg_win(t: *Type) -> ArgClass`：per v0.4 ABI 锁（i32/i64/ptr → register; struct > 8 bytes → sret）

```jhyy
// compiler/src0/target/abi_amd64_win.jhyy

// 4 参数寄存器（per MS x64 / Windows x64 ABI）
const ARG_REGS_WIN: [i32; 4] = [0 /* rcx */, 2 /* rdx */, 8 /* r8 */, 9 /* r9 */];

// Shadow space 32 字节（per MS x64）
const SHADOW_SPACE_SIZE: i64 = 32;

type ArgClass = enum {
    Reg(i32),    // 寄存器索引（rcx=0, rdx=2, r8=8, r9=9）
    Sret,        // 隐藏指针（rcx 指向返回结构 buffer）
    Stack,       // 栈传递
}

fn emit_win_func_prologue(ir: *IRBuf, name: [*]u8, n_args: i32) {
    // push rbp; mov rbp, rsp; sub rsp, <locals_size + shadow_space>
    // 保存非易失寄存器（rbx/rsi/rdi/r12-r15）如果函数用
}

fn emit_win_func_epilogue(ir: *IRBuf, n_args: i32) {
    // mov rsp, rbp; pop rbp; ret
}

fn emit_win_call(ir: *IRBuf, name: [*]u8, args: [*]IRVal, n_args: i32) {
    // 把参数按 ARG_REGS_WIN 顺序放到 rcx/rdx/r8/r9
    // call <name>
}

fn classify_arg_win(t: *Type) -> ArgClass {
    // per v0.4 ABI: i32/i64/ptr → register; struct > 8 bytes → sret
    // 返回 ArgClass::Reg(idx) / ArgClass::Sret / ArgClass::Stack
}
```

#### 1.1.2 codegen.jhyy 抽离调用
- `compiler/src0/codegen.jhyy`（改）：
  - 删除原 emit 函数体（prologue / epilogue / call / classify）
  - 改调 `abi_amd64_win` 提供的函数
  - codegen.jhyy 行数应减少（emit 函数体移到 abi_amd64_win.jhyy）

### 1.2 依赖
- v2.0.0 ✅ shipped（target dispatcher 基础设施就位）

### 1.3 验收
1. **行为 byte-equal**: `diff jhyy_v1.il jhyy_v2.il` byte-equal（同一 hello.jhyy）
2. **行为 byte-equal**: `diff jhyy_v1.s jhyy_v2.s` byte-equal（同上 .s）
3. **regress 持平**: `regress.py` 50/53 PASS, 0 failed, 3 skipped
4. **codegen.jhyy 行数减少**: 抽离后 codegen.jhyy 行数减少 ≥ 200 行（ABI 函数体移到 abi_amd64_win.jhyy）

### 1.4 风险
- **ABI 抽离 regress**: Stage 1 第一步保留 `emit_win_*` 函数行为不变（纯重构）；每个 ABI 函数抽离后立即跑 regress.py + byte-equal

- **ABI 函数命名冲突**: `emit_win_func_prologue` 等命名可能跟现有函数冲突；改名 `abi_win_emit_func_prologue` 等避免冲突

## Stage 2: abi_amd64_win_freestanding 新建

### 2.1 范围

#### 2.1.1 新建 abi_amd64_win_freestanding.jhyy
- `compiler/src0/target/abi_amd64_win_freestanding.jhyy`（新）：
  - 复用 MS x64 ABI（per D-GUI-12 + `feedback_uefi_x64_conventions`）：emit_freestanding_func_prologue 调 emit_win_func_prologue
  - `fn emit_freestanding_no_crt_init(ir)`：不 emit `__security_cookie` / `__report_rangecheckfailure` / `__chkstk` / `__main` / `__do_global_ctors` 等 ucrt/vcruntime 引用
  - `fn emit_freestanding_entry(ir, entry_name)`：emit `.section .text.boot` + `global <entry_name>`
  - `fn classify_arg_freestanding(t: *Type) -> ArgClass`：复用 `classify_arg_win`（ABI 相同）

```jhyy
// compiler/src0/target/abi_amd64_win_freestanding.jhyy

// 复用 MS x64 ABI（per D-GUI-12）
fn emit_freestanding_func_prologue(ir: *IRBuf, name: [*]u8, n_args: i32) {
    // 跟 Windows x64 相同（MS x64）
    emit_win_func_prologue(ir, name, n_args);
}

fn emit_freestanding_func_epilogue(ir: *IRBuf, n_args: i32) {
    // 跟 Windows x64 相同
    emit_win_func_epilogue(ir, n_args);
}

fn emit_freestanding_call(ir: *IRBuf, name: [*]u8, args: [*]IRVal, n_args: i32) {
    // 跟 Windows x64 相同（EFI 规范 = MS x64）
    emit_win_call(ir, name, args, n_args);
}

fn classify_arg_freestanding(t: *Type) -> ArgClass {
    // 复用 classify_arg_win（ABI 相同）
    return classify_arg_win(t);
}

// 但 freestanding 不 link ucrt/vcruntime:
fn emit_freestanding_no_crt_init(ir: *IRBuf) {
    // 不 emit __security_cookie / __report_rangecheckfailure / __chkstk 等 ucrt 引用
    // 不 emit __main / __do_global_ctors 等 vcruntime 引用
}

fn emit_freestanding_entry(ir: *IRBuf, entry_name: [*]u8) {
    // emit `.text.boot:` section + `global <entry_name>` + `extern main` 留空
    // 用户自己写 `fn efi_main(...)` / `fn _start(...)`, jhyy 编进去
}
```

#### 2.1.2 codegen.jhyy 抽离调用
- `compiler/src0/codegen.jhyy`（改）：
  - `emit_amd64_win_freestanding_stub`（v2.0.0 占位）改实为 `emit_amd64_win_freestanding`
  - 调用 `abi_amd64_win_freestanding` 提供的函数
  - 删 stub 报错

### 2.2 依赖
- Stage 1（abi_amd64_win 抽离完成）

### 2.3 验收
1. **行为 byte-equal**: `diff jhyy_v1.il jhyy_v2.il` byte-equal（同一 hello.jhyy，freestanding target）
2. **freestanding 无 ucrt 引用**: `nm hello-freestanding.obj | grep ucrt` 空
3. **regress 持平**: `regress.py` 50/53 PASS
4. **freestanding 编 .obj 通过**: `jhyy --target=amd64_win_freestanding hello.jhyy` 编出 PE/COFF .obj（**不要求 lld-link 链通 + OVMF 启动，那是 v2.3.0 范围**）

### 2.4 风险
- **freestanding binary 残留 ucrt 引用**: Stage 2 末验证 `nm hello-freestanding.obj | grep ucrt` 必须空；不空则 emit_freestanding_no_crt_init 修补
- **MS x64 ABI 跟 UEFI 规范细节差异**: shadow space / 参数寄存器顺序 / struct pass-by-value 严格按 UEFI spec 2.10 + MS x64；任何偏差走 spec patch

## Stage 3: codegen 抽离调用 + ABI 单元测试

### 3.1 范围

#### 3.1.1 codegen.jhyy 全部 emit 函数走 ABI 抽离调用
- `compiler/src0/codegen.jhyy`（改）：
  - 所有 emit 函数（prologue / epilogue / call / classify / no_crt_init / entry）走 ABI 抽离调用
  - 确认 codegen.jhyy 不再有任何 ABI 逻辑代码（仅 dispatch）
  - 行数应进一步减少

#### 3.1.2 ABI 单元测试
- `compiler/tests/examples/abi_amd64_win/abi_test.jhyy`（新）：
  - `test_arg_regs_win`：4 参数 → 4 个寄存器（rcx/rdx/r8/r9）
  - `test_shadow_space_win`：函数 prologue 含 `sub rsp, 32`（shadow space）

### 3.2 依赖
- Stage 1 + 2（abi_amd64_win + abi_amd64_win_freestanding 完成）

### 3.3 验收
1. **行为 byte-equal**: `diff jhyy_v1.il jhyy_v2.il` byte-equal（同一 hello.jhyy）— **5/5 PASS**（per `feedback_fix_evaluation_rule`，5 个 target test 都 byte-equal）
2. **行为 byte-equal**: `diff jhyy_v1.s jhyy_v2.s` byte-equal（同上 .s）— 5/5 PASS
3. **regress 持平**: `regress.py` 50/53 PASS, 0 failed, 3 skipped
4. **ABI 单元测试通过**: `abi_test.jhyy` 3 个 test 函数都通过（test_arg_regs_win / test_shadow_space_win / test_struct_sret_win）
5. **codegen.jhyy 行数减少**: 抽离后 codegen.jhyy 行数减少 ≥ 300 行（总抽离效果）

### 3.4 风险
- **Stage 3 跨 Stage 1+2 集成**: Stage 3 是集成阶段，所有 ABI 函数走抽离调用，任何 ABI 函数回归都会反映到 regress

- **codegen.jhyy 抽离行数不达预期**: 如果 ABI 函数体不够大，codegen.jhyy 抽离后行数减少不明显；不影响验收（功能 byte-equal 是硬指标）
