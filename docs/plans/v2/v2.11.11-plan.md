**根因 (T4-g v2.11.11 调研取证, 2026-09-13)**:

`compiler/src0/codegen_amd64_lexer.jhyy:1212-1258` 的 'c' branch compare-op sub-dispatcher 有 2-stage guard:
```jhyy
// Line 1212 (stage 1: prefix letter)

    let n2 = lex_peek_byte_at(s, 2 as i64);
    let n3 = lex_peek_byte_at(s, 3 as i64);
    let n4 = lex_peek_byte_at(s, 4 as i64);
    // Line 1218 (stage 2: type suffix at index 4)
    if n4 == (119 as i32) || n4 == (108 as i32)
        || n4 == (115 as i32) || n4 == (100 as i32) {
        // 5-char compare op consume (csltw / cslew / csgtw / csgew)
```

**Stage 1 漏 'n' (110) → `cnew` 直接 stage 1 reject** (return -1)。
**Stage 2 只查 `n4` (idx 4) → `ceqw` 跟 `cnew` 是 4-char op,type suffix 'w' 在 `n3` (idx 3),`n4` 是 ws/EOF → stage 2 reject** (return -1)。

`next_token` return -1 → `lex_il` 外层循环 (`codegen_amd64_lexer.jhyy:1478-1482`) silent skip 1 byte:
```jhyy
if rc < (0 as i32) {
    // error: skip 1 byte,继续(避免死循环)
    let cc = lex_peek_byte(s);
    if cc == 0 { done = 1 as i32; }
    else { let _x = lex_next_byte(s); }
}
```

整个 `%t65 =w cnew %t63, %t64` 行被 byte-by-byte 撕碎 (5-7 个 silent skips),后续 `jnz %t65, ...` 因 cursor offset shift 同样失效 → emit_jnz 永不调用 → jnz emit 跟 cnew emit 跟 %t65 dst store **全部 cascading vanish**。big_test_run.s 65 个 missing setXX emit (11 ceqw + 54 cnew) 即此根因。
