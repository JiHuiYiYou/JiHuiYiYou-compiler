## Stage 1: EFI struct 定义

### 1.1 范围

#### 1.1.1 efi.jhyy 新建
- `compiler/tests/examples/hello-freestanding/efi.jhyy`（新）：
  - UEFI spec 2.10 § 4.3 EfiSystemTable struct 定义
  - UEFI spec 2.10 § 12.4 EfiSimpleTextOutputProtocol struct 定义
  - 函数指针类型（EFIAPI = MS x64）

```jhyy
// compiler/tests/examples/hello-freestanding/efi.jhyy

// per UEFI spec 2.10 § 4.3 EFI_SYSTEM_TABLE
type EfiSystemTable = struct {
    hdr: EfiTableHeader,
    firmware_vendor: *u8,
    firmware_revision: u32,
    // ... (省略 EFI 规范里的其他字段, jhyy 端只关心 con_out)
    con_out: *EfiSimpleTextOutputProtocol,  // offset = 0x40
}

type EfiTableHeader = struct {
    signature: u64,
    revision: u32,
    header_size: u32,
    crc32: u32,
    reserved: u32,
}

// per UEFI spec 2.10 § 12.4 EFI_SIMPLE_TEXT_OUTPUT_PROTOCOL
type EfiSimpleTextOutputProtocol = struct {
    reset: EfiTextReset,
    output_string: EfiTextOutputString,
    // ... (省略其他函数指针)
}

// 函数指针类型（per EFI spec = EFIAPI = MS x64）
type EfiTextOutputString = fn (this: *EfiSimpleTextOutputProtocol, string: *u8) -> u64;
type EfiTextReset = fn (this: *EfiSimpleTextOutputProtocol, extended_verification: bool) -> u64;
```

### 1.2 依赖
- v2.1.0 ✅ shipped（freestanding target + ABI 抽离）

### 1.3 验收
1. **EFI struct 编译通过**: jhyy 编 `efi.jhyy` 通过（不调用 .efi，只验证 struct 定义）
2. **EfiSystemTable.con_out offset 正确**: per UEFI spec 2.10 § 4.3, con_out 在 offset 0x40；结构体字段顺序对齐
3. **函数指针类型匹配 EFIAPI**: per EFI spec = MS x64（4 参数寄存器 + shadow space）

### 1.4 风险
- **EfiSystemTable struct layout 错（offset 算错）**: Stage 1 第一步对照 UEFI spec 2.10 § 4.3 layout；跳过的中间字段用占位 `u64` 保留 offset
- **函数指针签名错**: EFI protocol 函数指针签名严格按 spec；任何偏差 OVMF 启动调用错
- **jhyy 当前 struct 布局限制**: jhyy struct 字段按声明顺序连续布局（无 packing 选项）；按 UEFI spec 默认对齐 8 字节字段 OK

## Stage 2: hello-freestanding + lld-link 链

### 2.1 范围

#### 2.1.1 hello-freestanding.jhyy 新建
- `compiler/tests/examples/hello-freestanding/hello-freestanding.jhyy`（新）：
  - UEFI entry point (`efi_main`)
  - printk stub（走 EFI_SIMPLE_TEXT_OUTPUT_PROTOCOL.OutputString）

```jhyy
// compiler/tests/examples/hello-freestanding/hello-freestanding.jhyy

import efi;

// UEFI entry point (per EFI spec 2.10 § 4.3)
fn efi_main(image_handle: u64, system_table: *EfiSystemTable) -> u64 {
    let con_out = (*system_table).con_out;
    let hello = "Hello from jhyy freestanding!\n";
    (*con_out).output_string(con_out, hello);  // EFIAPI call (MS x64)
    return 0;  // EFI_SUCCESS
}
```

#### 2.1.2 link.ld 新建
- `compiler/tests/examples/hello-freestanding/link.ld`（新）：
  - Minimal EFI linker script（`.text.boot` + `.data` + `.bss` + `.reloc`）

```
SECTIONS {
    . = 0x100000;  /* UEFI 默认加载地址 */

    .text ALIGN(0x20) : {
        *(.text)
        *(.text.*)
    }

    .data ALIGN(0x20) : {
        *(.data)
        *(.data.*)
    }

    .bss ALIGN(0x20) : {
        *(.bss)
        *(.bss.*)
    }

    /DISCARD/ : {
        *(.note.GNU-stack)
    }
}
```

#### 2.1.3 build_efi.sh 新建
- `compiler/build/bin/build_efi.sh`（新）：
  - jhyy 编 → .obj (PE/COFF format)
  - lld-link → .efi（`/SUBSYSTEM:EFI_APPLICATION` + `/ENTRY:efi_main` + `/MACHINE:X64`）

```bash
#!/usr/bin/env bash
set -euo pipefail

INPUT="${1:?usage: build_efi.sh <input.jhyy>}"
OUTPUT="${INPUT%.jhyy}.efi"
INPUT_BASE="${INPUT%.jhyy}"
JHYY="${JHYY:-jhyy}"

# Step 1: jhyy 编 → .obj (PE/COFF format)
$JHYY --target=amd64_win_freestanding -c "$INPUT" -o "${INPUT_BASE}.obj"

# Step 2: lld-link → .efi
lld-link \
    /SUBSYSTEM:EFI_APPLICATION \
    /ENTRY:efi_main \
    /MACHINE:X64 \
    /OUT:"$OUTPUT" \
    "${INPUT_BASE}.obj"

echo "Built: $OUTPUT"
```

### 2.2 依赖
- Stage 1（EFI struct 定义完成）
- v2.1.0 ✅ shipped（freestanding target）
- **lld-link 可用**: per Sprint A 风险表，sprint A 第一步验证 lld-link 可用；本 stage 复用验证结果

### 2.3 验收
1. **hello-freestanding.obj 编出**: `jhyy --target=amd64_win_freestanding -c hello-freestanding.jhyy -o hello-freestanding.obj` 成功
2. **hello-freestanding.efi 编出**: `build_efi.sh hello-freestanding.jhyy` 编出 PE32+ format .efi
3. **PE32+ format 验证**: `file hello-freestanding.efi` 输出 "PE32+ executable (EFI application) x86-64, for MS Windows"
4. **freestanding 无 ucrt 引用**: `nm hello-freestanding.obj | grep ucrt` 空

### 2.4 风险
- **lld-link subsystem 配置**: 必须 `/SUBSYSTEM:EFI_APPLICATION` + `/ENTRY:efi_main` + `/MACHINE:X64`；配错 link 报 "unresolved external"
- **EFI 协议调用 ABI**: ConOut->OutputString 走 EFIAPI（MS x64），4 参数寄存器（rcx/r8/r9/r10）+ shadow space 32 字节
- **hello-freestanding.obj 残留 ucrt 引用**: Stage 2 末验证 `nm hello-freestanding.obj | grep ucrt` 必须空

## Stage 3: OVMF 启动 + printk

### 3.1 范围

#### 3.1.1 run_ovmf.sh 新建
- `compiler/build/bin/run_ovmf.sh`（新）：
  - QEMU + OVMF 启动脚本（`-bios OVMF.fd -kernel hello-freestanding.efi -nographic -serial stdio`）

```bash
#!/usr/bin/env bash
set -euo pipefail

EFI="${1:?usage: run_ovmf.sh <input.efi>}"
OVMF_FD="${OVMF_FD:-RELEASEX64_OVMF.fd}"

# 验证 OVMF.fd 存在 + checksum
if [[ ! -f "$OVMF_FD" ]]; then
    echo "Error: OVMF.fd not found at $OVMF_FD"
    echo "Download from: https://github.com/tianocore/edk2/blob/UDK2018/OVMF/RELEASEX64_OVMF.fd"
    exit 1
fi

# QEMU + OVMF 启动 (UEFI 模式)
qemu-system-x86_64 \
    -bios "$OVMF_FD" \
    -kernel "$EFI" \
    -nographic \
    -serial stdio \
    -monitor none

# 期望输出 (UEFI ConOut -> QEMU serial):
# Hello from jhyy freestanding!
```
