## § 1 总体设计

### 1.1 调用链(替换前 vs 替换后)

**v2.0.0 → v2.4.0 当前路径**(per `main.jhyy:1027` `run_qbe`):
```
parse → sema → codegen.jhyy (emit QBE IL) → write .il
                                                    ↓
                                       spawn qbe.exe via jh_run
                                                    ↓
                                       qbe → amd64 .s
                                                    ↓
                                       spawn gcc.exe via jh_run
                                                    ↓
                                       link → .exe
```

**v2.5.0 后路径**(per V2-A plan + 本 doc):
```
parse → sema → codegen.jhyy (emit QBE IL 不变) → write .il
                                                    ↓
                                       ┌──────────────────────┐
                                       ↓ target_backend_mode(t)
                                       ├─ self=1 (windows) → codegen_amd64.jhyy 读 .il → emit .s
                                       └─ self=0 (sysv/默认 fallback) → spawn qbe.exe
                                                    ↓
                                       spawn gcc.exe via jh_run
                                                    ↓
                                       link → .exe
```

**关键不变量**:`codegen.jhyy` 不变,`abi_amd64_win.jhyy` 不变,只替换 `.il → .s` 这一段。
**关键切换**:`main.jhyy:1027` 的 `run_qbe(il, asm, t)` 调用 → 改为 `run_backend(il, asm, t)`,后者按 `target_backend_mode(t)` dispatch。
**关键回滚**:`QBE_FALLBACK=1` 环境变量强制走 QBE,保证 baseline invariant + 紧急回退路径。

### 1.3 target_dispatch.jhyy 新增

```jhyy
// v2.5.0: target_backend_mode(t) → 0=QBE / 1=self(jhyy-written backend)
// windows = self (v2.5.0 实现)
```

### 1.4 main.jhyy run_backend 改动

```jhyy
// v2.5.0: 新 run_backend() 替代 run_qbe() — 按 target_backend_mode(t) dispatch
fn run_backend(il_path: *u8, asm_path: *u8, t: i32) -> i32 {
    // QBE_FALLBACK=1 环境变量强制走 QBE(per V2-A plan acceptance #3)
    let fb_env = jh_getenv("QBE_FALLBACK" as *u8);
    let use_qbe: i32 = 0 as i32;
    if fb_env != (0 as *u8) {
        if strcmp(fb_env, "1" as *u8) == 0 { use_qbe = 1; }
    }
    if use_qbe != 0 { return run_qbe(il_path, asm_path, t); }
    if target_backend_mode(t) == 1 {
        return codegen_amd64_run(il_path, asm_path);
    }
    return run_qbe(il_path, asm_path, t);
}

// run_qbe 保持不变(main.jhyy:670-735)— QBE baseline 路径
```

## § 2 QBE IL 输入格式(codegen_amd64_lexer.jhyy)

### 2.1 IL 子集(v2.5.0 scope,15 个 token)

per V2-A plan line 25:

| # | Token | 形态 | 例子 |
|---|-------|------|------|
| 1 | `allocN` | `alloc4`/`alloc8`/`alloc16` 后接 size | `%t1 =l alloc8 16` |
| 2 | `storeT` | `storew`/`storel`/`stores`/`stored` | `storew %t2, %t1` |
| 3 | `loadsubwordT` | `loadsb`/`loadub`/`loadsh`/`loaduh` 后接 l/w/s/d | `%t3 =w loadsbl %t1` |
| 4 | `loadT` | `loadw`/`loadl`/`loads`/`loadd` | `%t3 =w loadw %t1` |
| 5 | `call` | `<dst> =<qt> call $<name>(<args>)` 或 `call $<name>(...)` | `%t4 =w call $foo(%t1, %t2)` |
| 6 | `phi` | `<dst> =<qt> phi @<b1> %<v1>, @<b2> %<v2>` | `%t5 =w phi @b1 %t2, @b2 %t3` |
| 7 | `copy` | `<dst> =<qt> copy <src>` | `%t6 =w copy 42` |
| 8 | `binop` | `add`/`sub`/`mul`/`div`/`mod` | `%t7 =w add %t1, %t2` |
| 9 | `ret` | `ret <val>` 或 `ret` | `ret %t7` / `ret` |
| 10 | `jmp` | `jmp @<label>` | `jmp @b3` |
| 11 | `jnz` | `jnz %<cond>, @<then>, @<else>` | `jnz %t1, @b2, @b3` |
| 12 | `label` | `@<name>` | `@start` / `@b1` |
| 13 | `func_header` | `export function [<ret_qt>] $<name>(<params>) {` | `export function w $foo(l %ret, w %p1) {` |
| 14 | `data_string` | `data $<name> = { b "..." }` | `data $str0 = { b "hello", b 0 }` |
| 15 | `volatile` | token 出现在 load/store 前(`volatile loadw %t1` 等)— **预留识别**,emit 为普通 load/store | (lexer 识别但不传语义给 emit) |

### 2.2 Lexer 形态

**Mirror `parser.jhyy` 风格** — recursive descent,逐 token 解析:
```jhyy
// 输入:*u8(全 .il 文件内容)+ i64 长度
// 输出:token 序列(每次 next_token 推进 cursor)

// token 类型
type ILToken = struct {
    kind:     i32,     // ILTOK_*
    text:     *u8,     // token 字符串(filenames / block names / etc.)
    text_len: i64,
    int_val:  i64,     // numeric literals
    qbe_type: i32,     // 'w'/'l'/'s'/'d'/'b'/'h' (per ir.jhyy QBE_*)
    line:     i32,
}
```

**Lexer 入口**:
```jhyy
fn lex_il(buf: *u8, len: i64) -> *u8;  // returns *ILToken array (arena-allocated)
fn lex_il_count(arr: *u8) -> i64;       // token count
```

**Tokenizer 状态机**:cursor 在 buf 上推进,跳过空白(per `feedback_qbe_crlf_root_cause`:`\n` 必须保留行号语义但 `\r` 不丢)和注释(`#` 到行尾)。

### 2.3 Parser(emit 函数组装的脚手架)

**Function-level parsing**:
- `data $<name> = { ... }` → emit data_string
- `export function [...] $<name>(...) {` → start emit function_header
- `@<label>` → emit label
- `<instruction>` → dispatch 到对应 emit 函数
- `}` → end emit function

**每个 function 独立 emit**(单一 .s 输出 buffer,顺序拼接)。跨 function 不共享临时。

### 2.4 volatile token 处理

**Lexer 必须识别** `volatile` 关键字(在 `load`/`store` 前出现)。`text` 字段填 `"volatile"`,`qbe_type` 设为 `QBE_VOLATILE_MARKER`(新 i32 常量 = -1,区分 'w'/'l'/'s'/'d' 正 ASCII)。

**Emit 函数**:`load`/`store` 检测到 qbe_type == QBE_VOLATILE_MARKER → emit 普通 loadw/loadl/storel/storew,**不**插任何 memory barrier / 串行化指令(per V2-A plan "V2-A 预留 token 识别,emit 为普通 load/store,3c ship 后再 flip 行为")。

**L4 § X 验证**:ship gate 跑 `grep "volatile" compiler/src0/codegen_amd64.jhyy` 应返 ≥ 1 hit(预留识别 + emit 普通 load/store 的代码路径)。

## § 3 amd64 GAS `.att_syntax` 输出规范

### 3.1 Reference:QBE amd64 emit

**权威源**:`qbe/amd64/emit.c`(vendored)+ `qbe/amd64/isel.c`(指令选择)+ `qbe/amd64/winabi.c`(MS x64 ABI)。

**为什么必须 match QBE byte-for-byte**:V2-A plan acceptance #5 `tests/byte_equal_amd64.jhyy` 5/5 PASS(self vs QBE `.s` identical)。这是 ship gate 的硬约束。

**Match 策略**:
1. 读 `qbe/amd64/emit.c` 全文,~2000 行,理解每个 emit 函数输出格式
2. 写 emit 函数时跟 QBE 输出一一对应(`emit_amd64_alloc()` 对应 QBE `amd64_emitfn` 的 alloc 段,etc.)
3. 注释 / 标号格式用 QBE 风格(`\t` tab 缩进 / `.file "..."` / `.text` / `.section .text`)
4. 用 `diff -q <ours>.s <qbe>.s` 单测验证每个 IL 指令

### 3.2 总体 .s 文件结构

```gas
# Comments at top — QBE 风格
.file "<input>.jhyy"
.text

# Data 段(per QBE 风格)
.globl $str0
$str0:
    .ascii "hello"
    .byte 0

# Function 段(每个 export function 一段)
.globl foo
foo:
    # function prologue (per MS x64 ABI: 32-byte shadow + sub $frame, %rsp)
    pushq %rbp
    movq %rsp, %rbp
    subq $N, %rsp
    # ... function body (per QBE IL emit) ...
    # function epilogue
    movq %rbp, %rsp
    popq %rbp
    ret
```

### 3.3 Register mapping(per QBE amd64 ABI)

QBE 临时寄存器(`%t1`, `%t2`, ...)→ amd64 物理寄存器池(per QBE `qbe/amd64/isel.c`):

| QBE temp 范围 | 物理寄存器(MS x64) |
|--------------|--------------------|
| `%t1`-`%t10` | `%rax`, `%rcx`, `%rdx`, `%rbx`, `%rsi`, `%rdi`, `%r8`, `%r9`, `%r10`, `%r11` |
| `%t11`-`%t20` | spill to stack(`-N(%rbp)`) |
| `%tN` extra | spill to stack |
| `%ret`(struct sret) | `%rax` per MS x64 |
| `%p1`-`%p4`(args) | `%rcx`, `%rdx`, `%r8`, `%r9` per MS x64(用户实参) |
| `%p5+`(args) | stack at `16(%rbp)`, `24(%rbp)`, ... per MS x64 |

**v2.5.0 简化**:V2-A plan 不做 regalloc,所以 v2.5.0 的"寄存器映射"是 **1-to-1 简化映射**:`%t1` → 直接 emit 为 `(%rbp)` 栈偏移,**不**做实际 register allocation。每个 %t 都 spill 到栈。后续 V2-B v2.6.0 才加 regalloc。

**这意味着 v2.5.0 的 .s 会比 QBE 输出的 .s 显著大**(每个 %t 都栈访问)。**但 .exe 仍 byte-equal**(per D26 三件套 acceptance:byte-equal 是 .il + .s + .exe;.il 路径不变;.s 路径字节匹配;.exe 通过 gcc 链接确定性)。

⚠️ **关键澄清**:`tests/byte_equal_amd64.jhyy` 5/5 PASS 测的是 **self-written .s == QBE-generated .s**。如果 self-written 用 1-to-1 栈分配而 QBE 用真实 regalloc,**两者 .s 永远不会 byte-equal**。

**实际解法**(per QBE 输出研究):
- QBE 在 windows MS x64 target 下,简单函数(无嵌套 call / 无大量 local var)也大量 spill 到栈(per QBE 默认行为)
- 复杂函数 QBE 会用 register,但匹配 register 选择启发式也很复杂
- v2.5.0 策略:**针对 regress 104/104 测试用例(都是 hello / fib / struct-pass / freestanding variant / mixed — 简单到中等)做"足够好"的 register 分配**,而非完整 regalloc
- 具体:5 个测试用例手动验证 self vs QBE .s byte-equal;如果某 case 不 byte-equal,在 codegen_amd64.jhyy 加 case-specific 逻辑(match QBE 的 register 选择 for that specific IL shape)

**L4 § Y 风险**:`tests/byte_equal_amd64.jhyy` 的 5 个用例如果某个无法 byte-equal,ship gate FAIL。**fallback 路径**:`QBE_FALLBACK=1` 仍 104/104 PASS(per acceptance #3),自举闭环 hold(per acceptance #2),但 ship gate 标 `partial` 不 `full`。**用户决策**:ship 时是否接受 partial,留 user 决定(per `feedback_fix_evaluation_rule` 5/5 PASS 必跑)。

### 3.4 Stack frame layout(MS x64)

per `qbe/amd64/winabi.c` + Microsoft x64 ABI:

```
高地址
  | ... (caller frame) ...
  | return address      <- RSP on entry
低地址  ------------------- (function prologue 后 RSP 位置)
  | 32-byte shadow      <- caller 已分配 (callee 不可见)
  | locals + spilled regs
  | ...
  | %rbp save           <- RSP + N (per subq)
  | saved %rbp          <- %rbp points here
  | callee-saved regs   <- pushq %rbx, %rsi, ..., %r15 (per QBE)
  -------------------   <- 最终 RSP
```

**v2.5.0 emit 规则**:
- function prologue: `pushq %rbp` + `movq %rsp, %rbp` + `subq $N, %rsp`(N = sum of local alloc sizes + 32-byte shadow)
- function epilogue: `movq %rbp, %rsp` + `popq %rbp` + `ret`(per MS x64)

### 3.5 15 个 emit 函数(per instruction)

#### E1 `emit_alloc`(对应 `allocN size`)

QBE input: `%t1 =l alloc8 16`
QBE output(per `qbe/amd64/isel.c`):通常不显式 emit alloc,而是在 frame layout 计算时累加;`.loc` 注释标记

v2.5.0 emit(简化):
- 计算 `aligned_size = (size + align - 1) & ~(align - 1)`
- 累加到 function frame `total_alloc += aligned_size`
- 不显式 emit 指令(alloc 隐式在 subq $N 中体现)
- 注释:`# alloc8 16 -> %t1 (offset -X(%rbp))`

#### E2 `emit_store`(对应 `storeT %v, %addr`)

QBE input: `storew %t2, %t1`
QBE output(MS x64):`movl %eax, -X(%rbp)`(%t2 已 mov 到 %eax by isel)

v2.5.0 emit(1-to-1 简化):
- `movq %t2_reg, -X(%rbp)` 或 `movl %t2_reg, -X(%rbp)`(per qbe_type w/l)
- 用 `t2.offset` 而非 `t2_reg`(我们不 regalloc,直接栈栈)

#### E3 `emit_loadsubword`(对应 `loadsb/loadub/loadsh/loaduh T %addr`)

QBE input: `%t3 =w loadsbl %t1`
QBE output:`movsbl -X(%rbp), %eax`

v2.5.0 emit:`movsb{l,w,q} -X(%rbp), %t3_offset_reg`(我们 emit 到栈槽,后续 store 再写出去)

#### E4 `emit_load`(对应 `loadT %addr`)

QBE input: `%t3 =w loadw %t1`
QBE output:`movl -X(%rbp), %eax`

v2.5.0 emit:`mov{l,q} -X(%rbp), %t3_offset_reg`

#### E5 `emit_call`(对应 `call $name(args)`)

QBE input: `%t4 =w call $foo(%t1, %t2)`
QBE output(MS x64):
- 前 4 args 移到 `%rcx, %rdx, %r8, %r9`
- 32-byte shadow space alloc(若 call 后还有事)
- `call $foo`
- 32-byte shadow space cleanup(若 alloc)
- 返回值在 `%rax`(`%t4` 是 `%rax`)

v2.5.0 emit:
- args 1-4 mov 到 `%rcx, %rdx, %r8, %r9`(从 stack slots)
- args 5+ 直接在 stack(`16(%rbp)`, `24(%rbp)`, ..., per MS x64 — 注意 caller 负责 push)
- 32-byte shadow space:`subq $32, %rsp` before call,`addq $32, %rsp` after
- `call $foo`
- `movq %rax, -Y(%rbp)`(把 %t4 的值存到栈槽)

#### E6 `emit_phi`(对应 `phi @b1 %v1, @b2 %v2`)

**v2.5.0 scope 简化**:phi 由 codegen.jhyy 上游调度(在 emit 之前 SSA 已 resolve 为 block-local copies)。v2.5.0 codegen_amd64.jhyy 看到 .il 时应该**没有 phi**(or very few)。L4 § X 风险:**如果 regress 测试触发 phi,fallback to QBE**;`QBE_FALLBACK=1` 保证通过。

emit 函数识别 phi 注释:`# phi resolved by codegen.jhyy — noop in v2.5.0`

#### E7 `emit_copy`(对应 `<dst> =<qt> copy <src>`)

QBE input: `%t6 =w copy 42`
QBE output:`movl $42, %eax`(立即数 copy)或 `movl -X(%rbp), %eax`(寄存器 copy)

v2.5.0 emit(简化):
- 若 src 是 IMM:`movl $N, -Y(%rbp)`(直接栈到栈)
- 若 src 是 temp:`mov{l,q} -X(%rbp), %rax; mov{l,q} %rax, -Y(%rbp)`

#### E8 `emit_binop`(对应 `add/sub/mul/div/mod`)

QBE input: `%t7 =w add %t1, %t2`
QBE output:`movl -X(%rbp), %eax; addl -Y(%rbp), %eax; movl %eax, -Z(%rbp)`

v2.5.0 emit(简化,无 regalloc):`mov{l,q} -X(%rbp), %rax; {op}{l,q} -Y(%rbp), %rax; mov{l,q} %rax, -Z(%rbp)`

#### E9 `emit_ret`(对应 `ret <val>` 或 `ret`)

QBE output(MS x64):
- `movl -X(%rbp), %eax`(return value 到 %rax)
- function epilogue:`movq %rbp, %rsp; popq %rbp; ret`

v2.5.0 emit:同上,先 mov 返回值到 %rax,再 epilogue。

#### E10 `emit_jmp`(对应 `jmp @label`)

QBE output:`jmp .L_label_name`(或 `jmp <label>`)

v2.5.0 emit:`jmp .L<label>`(QBE 风格用 `.L` 前缀)

#### E11 `emit_jnz`(对应 `jnz %cond, @then, @else`)

QBE output:`testl -X(%rbp), -X(%rbp); jne .L_then; jmp .L_else`

v2.5.0 emit:同上,`testq`/`testl` per qbe_type。

#### E12 `emit_label`(对应 `@name`)

QBE output:`.L<name>:`

v2.5.0 emit:同上(`.L` 前缀,QBE 风格)

#### E13 `emit_func_header`(对应 `export function ...`)

QBE output(MS x64):
- `.globl <name>`
- `<name>:`
- `pushq %rbp`
- `movq %rsp, %rbp`
- `subq $N, %rsp`(N = total_alloc + 32)
- callee-saved save:`pushq %rbx, %rsi, ..., %r15`(per QBE isel)

v2.5.0 emit:match QBE,**简化**:不显式 push callee-saved(交给 caller)— v2.5.0 1-to-1 简化已经覆盖 frame 不需要 push callee-saved

#### E14 `emit_data_string`(对应 `data $name = { b "..." }`)

QBE output:
```
.globl $str0
$str0:
    .ascii "hello"
    .byte 0
```

v2.5.0 emit:match QBE,**注意**:`\0` 终止符 per byte(per `ir.jhyy` `ir_emit_data_string` line 797 emit `"\", b 0 }\n"`)
