## RCA 重新 verify (post v2.11.22 attempt 经验 + audit 2026-09-17)

### 关键 RCA 修正 (v2.11.22 → v2.11.23)

v2.11.22 RCA claim 是 "slot 和 region 物理共享 rbp-0x30" — audit 指出 **部分错**:
- v2.11.8 (W-074.7.8 真修) 已 explicit SKIP `cg_record_temp_slot` (state.jhyy:251 API + temp_slot_for_id[256] table 都在,但 emit_alloc L287-322 不调它)
- pointer-slot 走 formula `-(32+t*8)` 物理位置跟 region (cg_alloc_slot next_offset) **在同 frame 内** — formula pool 跟 region pool 都从 0 起负方向增长
- 例子:t2 = alloc16 16 → region = -48 (cg_alloc_slot next_offset advance)。formula `-(32+2*8) = -48` — 同样 -48 → **t2's pointer-slot == t2's region**
- v2.11.8 comment author 检查 t6 (formula = -80, region = -48, 不 collision) 就以为 OK — 漏了 t2 (formula = -48, region = -48, **collision**)
- v2.11.22 RCA 把这归类为 "slot 跟 region 物理共享" — 不准确;准确 framing 是 "**formula pool 跟 region pool 在同 frame 内 collision**"

### Real root cause (V.2.11.23 修正版, audit verify 通过)

**2 个 emit calls 缺失,3 LOC 修**:

1. **`emit_alloc` (emit_mem.jhyy:280-350) 缺失 `cg_record_temp_slot(state, dst, off - 8)` call**:
   - v2.11.5 design: `cg_record_temp_slot(state, dst, off=region)` — 写 dst's pointer-slot = region offset
   - v2.11.5 broken (self-referential bug) — `mov %rax, -<off>(%rbp)` 写 address 到 region 本身
   - v2.11.8 真修: SKIP `cg_record_temp_slot` (走 formula `-(32+t*8)`) — 避开 self-referential
   - **但 formula 在某些 t 上 = region offset** (e.g. t2:formula -48, region -48) → 新 collision
   - **真修**: 调 `cg_record_temp_slot(state, dst, off - 8)` — 写 pointer-slot = region 下面 8 字节 (物理上 region "下面" = stack offset 更负)。`cg_offset_for_temp_with_target:639-660` tier-1 lookup 返 `off - 8` (覆盖 formula)。Region at `off`, pointer-slot at `off - 8`, **物理分离,无 self-referential 风险 (pointer-slot 不 = region)**。
   - **1 行 fix**: emit_mem.jhyy:322 (`let _had = cg_record_temp_holds_address(state, dst);`) 之后加 1 行。

2. **`emit_binop` (emit_call.jhyy:1653-1700) 缺失 `cg_alloc_slot(8) + cg_record_temp_slot` for derived address-holders**:
   - 当前 (v2.11.22 attempt 2c): 调 `cg_record_temp_holds_address(state, dst_id)` 标 dst 为 address-holder
   - 但 dst's slot 走 formula `-(32+dst*8)` 跟 src1's region element 物理 collision (big_array bug:t21 = t1 + 200, formula = -(32+21*8) = -200 = arr[50] region address -400+4*50=-200)
   - **真修**: 追加 `cg_alloc_slot(state, 8)` + `cg_record_temp_slot(state, dst_id, derived_slot)` — 给 derived 走 dedicated slot (跟所有 region/formula 物理分离)
   - **1 行 fix**: emit_call.jhyy:1684 (`let _ad = cg_record_temp_holds_address(state, dst_id);`) 之后加 2 行。

### Frame size impact

- `frame_size = (max_temp_id + 1) * 8` (emit_ctrl.jhyy:522-526)
- Phase 1 加 1 个 8-byte pointer-slot per alloc + Phase 2 加 1 个 8-byte derived-slot per `add t_alloc, off` → frame_size 可能变
- **但是** `max_temp_id` 已经覆盖到 t = max temp id used → `frame_size >= (max_temp_id+1)*8` 通常够大,新加的 8-byte slot 落在 max_temp_id 之前 (因为 `cg_alloc_slot` 用 next_offset advance,不分配新 temp id)
- **兜底**:frame_size 加 1 行 `frame_size = max(frame_size, |state.next_offset|)` 覆盖 alloc pool 大 case (big_array 400B + 8B pointer-slot + ~50 derived-slot 8B × N = 可能 800B → 超过 max_temp_id 60 * 8 = 488B → 需兜底)

### 跟 v2.11.21 RCA / v2.11.22 RCA 的关系

- v2.11.21 RCA claim: "big_array = 2-pass slot alloc (~80-120 LOC); for_in_slice_nested = REVERT v2.11.20 RC-1 + retighten (~5 net)" → **v2.11.22 验证偏了** (audit 命中第 3 次 RCA agent hallucination pattern — 没 grep 现有 infra 是否能用)
- v2.11.22 RCA claim: "slot-vs-region overlap 物理共享 rbp-0x30" → **部分偏了** (实际是 formula pool 跟 region pool 同 frame 内 collision,不是 slot/region 本身共享 — audit 第 1 处 fatal 命中)
- v2.11.23 正确 RCA: **emit_alloc 应该调 existing `cg_record_temp_slot` API (state.jhyy:251, v2.11.5 design 写好的, v2.11.8 SKIPped by mistake);emit_binop 应该在 `cg_record_temp_holds_address` 后调 `cg_alloc_slot + cg_record_temp_slot`**。两个 call 都是 1-2 行 fix,total ~5-10 LOC。

```jhyy

// cg_record_temp_slot (v2.11.5 design API, deprecated by v2.11.8 SKIP, missed
// in v2.11.22 attempt). off = region (cg_alloc_slot advance). pointer-slot
// = off - 8 = 物理上 region "下面" (stack offset 更负 8 字节), 跟 region 物理
// 分离 + 跟 formula pool 物理分离 (formula `-(32+t*8)` 走 tier-2 fallback,
// tier-1 命中返 off-8)。
//
// Why off - 8 (not off): v2.11.5 design 写 off = region (self-referential bug,
// lea+mov 写 address 到 region 本身 overwrite);off - 8 避开 self-referential
// (pointer-slot 在 region 下面 8 字节, 跟 region 物理分离)。
//
// Why off - 8 (not off + 8): stack grows down,more-negative offset = 物理
// "下面" (lower address)。off - 8 在 region 下面, 跟 region element 物理
// 分离 + 不跟后续 alloc collision (后续 alloc 走 cg_alloc_slot advance
// next_offset,跟 off - 8 不会 overlap 因为 alloc_size > 8 一般)。
```

**Phase 2 关键 配套修改**: `cg_alloc_slot` (codegen_amd64_state.jhyy) alloc pool 起始 offset 从 0 改为 -8192,让 alloc pool 跟 formula pool 物理分离:

```jhyy
fn cg_alloc_slot(state: *u8, size: i64) -> i64 {
    let aligned = (size + (7 as i64)) & ((0 as i64) - (8 as i64));
    let s = state as *CGState;
    // v2.11.23 Phase 2:alloc pool 起始 offset — formula pool 占用 [rbp-2072, rbp-32],
    // alloc pool 必须从 rbp-8192 起向下增长 才不 collision
    if (*s).next_offset == (0 as i64) {
        (*s).next_offset = (0 as i64) - (8192 as i64);
    }
    let off = (*s).next_offset - aligned;
    (*s).next_offset = off;
    (*s).total_alloc = (*s).total_alloc + aligned;
    return off;
}
```
