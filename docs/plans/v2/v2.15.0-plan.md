# v2.15.0 — QBE 自写 (跳过 QBE IL, 直接 emit x86-64) 📋 planned

## Context

**v2.x 中期 5 sub-sprint 链 (v2.11.0 → v2.11.23 → v2.12.0 → v2.13.0 → v2.14.0)** ship 中,**当前架构** = 自写后端 `compiler/src0/codegen_amd64_*.jhyy` emit QBE IL → QBE external binary (`qbe/qbe.exe`,top-level `qbe/` 目录 per `Makefile` line 8 `QBE = qbe/qbe.exe`,audit 2026-09-17 verify — `vendor/qbe/qbe.exe` 不存在) → `.s`。QBE external binary 是历史遗留依赖 (per `v2.x-qbe-rewrite.md § 0`)。

**v2.15.0 启动前置**:
- v2.14.0 ship ✅ — N≥10 fixed point closure + mutation testing protocol + Linux N≥3
- v2.13.0 ship ✅ — 真 XMM regalloc + 真 amd64_sysv codegen 全覆盖 + amd64_sysv_freestanding 真 E2E
- v2.12.0 ship ✅ — 全量 self-backend audit (无抽样) phantom-free
- v2.11.23 ship ✅ — self-backend 0 FAIL parity with QBE path
- v2.0 阶段 ship ✅
- v1.0.0 真自举 byte-equal 闭环

**v2.15.0 必要性** (per `v2.x-qbe-rewrite.md § 2 + § 3.2 + § 5 挑战`):
1. **跳过 QBE IL**: 当前 `codegen_amd64_emit_*.jhyy` emit 中间产物 `.il`, QBE external binary 再 translate `.il` → `.s`。**QBE 自写** = 自写后端直接 emit `.s` (x86-64), 不经过 `.il` 中间表示。
2. **工具链 self-contained**: 移除 QBE external binary 依赖,jhyy 编 jhyy 工具链 0 外部依赖 (除 MinGW `as` + `gcc` linker)。**v2.16.0** ship = 完全删除 QBE。
3. **QBE IL 的设计局限**: QBE IL 是 QBE 项目的内部表示 (per `v2.x-qbe-rewrite.md § 5 挑战 3`),不是 jhyy-side first-class 概念。直接 emit `.s` 让自写后端的 emit path 简化 (不用生成 IL 再 translate)。
4. **M5 第二前置**: v2.15.0 + v2.16.0 = QBE 完全移除 = M5 独立 sprint 启动入口 (per `v1.x-phase-4-m5-boot-from-scratch.md`)。

**v2.15.0 在 v2 整阶段完成定义位置**:
- v2.0 阶段 ✅ ship (v2.0.0 → v2.4.0)
- v2.x 中期 ✅ ship (v2.5.0 → v2.14.0): self-backend parity + audit + 真 XMM + 真 sysv 全覆盖 + N 代 mutation
- v2.x 末 📋 planned (v2.15.0 + v2.16.0): QBE 自写 + QBE 移除 + perf bench + .exe byte-equal
- 后接: M5 独立 sprint 启动 (jhyy 编 jhyy 0 C 依赖闭环 per `v1.x-phase-4-m5-boot-from-scratch.md`)

## Scope (~1500 LOC + toolchain 验证, 5 commits ship)

### A. `compiler/src0/qbe/amd64_codegen.jhyy` (NEW, ~600 LOC)

**QBE 自写 x86-64 codegen 核心**:

**数据结构**:
- `QbeFunction`: name, params (with type), blocks (list of instructions + terminator)
- `QbeInstruction`: opcode, args (typed), targets
- `QbeType`: I8/I16/I32/I64/F32/F64/Ptr

**主入口 `amd64_codegen_jhyy_run(func: *QbeFunction, asm_path: *u8) -> i32`**:
- 调 `cg_emit_function_prologue` (push %rbp, mov %rsp, %rbp, sub $frame_size, %rsp)
- 遍历 blocks:
  - Emit label `.<func>.<block>:`
  - 遍历 instructions:
    - QBE_ADD/SUB/MUL/DIV → emit `addq/subq/imul/... %src, %dst` (per target ABI)
    - QBE_CALL → emit `call <func>` + ABI helper for arg passing
    - QBE_RET → emit `mov <result>, %rax; leave; ret`
    - QBE_PHI (resolved) → emit `mov %src, %dst` (per `v2.11.18` phi 修复)
    - QBE_STORE → emit `movq %src, -<off>(%rbp)` 或 `movq %src, -<off>(%rdi)`
    - QBE_LOAD → emit `movq -<off>(%rbp), %dst` 或 `movq -<off>(%rdi), %dst`
    - QBE_BLIT / QBE__VAARG / QBE__VASTART → 暂不支持, error fallback to QBE external (v2.15.0 阶段)
  - Emit terminator (jmp / je / jne / ret)
- Emit epilogue `leave; ret`
- 写 `.s` file

**复用 v2.13.0 真 XMM regalloc**:
- `compiler/src0/codegen_amd64_regalloc.jhyy` (从 v2.13.0 ship 后引入) 给 QBE 自写 codegen 用 XMM 分配

**ABI helper 复用 v2.13.0 真 amd64_sysv codegen**:
- `compiler/src0/abi_amd64_sysv.jhyy` 给 QBE 自写 codegen 用 arg passing + return value 处理 (per audit 2026-09-17 verify — 真 ABI 文件 = abi_amd64_*.jhyy)

### B. `compiler/src0/qbe/qbe_il.jhyy` (NEW, ~250 LOC)

**QBE IL text → jhyy-side struct**:
- `qbe_parse_il(il_path: *u8) -> *QbeFunction`: parse `.il` file → list of QbeFunction
- Tokenizer: 字符串 / 标识符 / 类型名 (l / w / s / d / b) / 指令名 (add / sub / mul / call / ret / jmp / jnz ...)
- Parser: function header → block list → instruction list
- Error handling: 解析失败 → stderr + exit

### C. `compiler/src0/main.jhyy` `run_qbe` 改 (~50 LOC modify)

**现状**:
```jhyy
fn run_qbe(il_path: *u8, asm_path: *u8, t: *Type) -> i32 {
    let cmd = fmt_sprintf("qbe.exe -o %s %s", asm_path, il_path);
    return system(cmd);
}
```

**改后**:
```jhyy
fn run_qbe(il_path: *u8, asm_path: *u8, t: *Type) -> i32 {
    // v2.15.0: jhyy-side QBE self-host (skip external qbe.exe)
    let func = qbe_parse_il(il_path);
    if func == null as *QbeFunction {
        jh_fputs_stderr("qbe_parse_il failed\n" as *u8);
        return -1;
    }
    return amd64_codegen_jhyy_run(func, asm_path);
}
```

## Risk + rollback

**Risk 1**: QBE 自写 codegen 不全 (QBE_BLIT / QBE__VAARG / QBE__VASTART 等不支持) → regress 部分 test FAIL
- **Mitigation**: V.4 regress 提前暴露; fallback to external qbe.exe for unsupported QBE IL (per Phase 4b 仍保留 qbe.exe binary)
- **Rollback**: revert Commit 4 (main.jhyy 改回调 external qbe.exe), Phase 1-3 (QBE 自写 lib) 保留作为 library

**Risk 2**: QBE 自写 .s 跟 external QBE .s 差异 > 20% (codegen 优化 gap)
- **Mitigation**: V.4 regress 持平 gate (行为正确性) + 接受 codegen 优化 gap (v2.16.0 perf bench 单独 verify ≤ 1.1x)
- **Rollback**: 同 Risk 1

**Risk 3**: QBE IL parser 解析失败 (jhyy-side emit 的 .il 跟 QBE 实际接受的 .il 不完全一致)
- **Mitigation**: V.1 unit test + V.2/V.3 端到端 verify
- **Rollback**: revert Commit 1 (parser lib 不 ship, 回到 external QBE .il text 直接传 qbe.exe)

**Risk 4**: 真 XMM regalloc (v2.13.0) 跟 QBE 自写 codegen 集成不兼容 (API mismatch)
- **Mitigation**: Phase 2 显式 import v2.13.0 真 XMM regalloc module + V.2/V.3 PASS verify
- **Rollback**: revert Commit 2 + Commit 3 (QBE 自写 codegen 不 ship, 仍走 v2.11.23 QBE IL emit)

**Risk 5**: v2.15.0 scope ~1500 LOC 比较大 (per `feedback_file_size_relaxed` 可放宽, 但仍需警惕)
- **Mitigation**: 5 sub-commit 分阶段 ship,任一 phase fail-fast 不影响其他 phase
- **Rollback**: 分阶段 revert
