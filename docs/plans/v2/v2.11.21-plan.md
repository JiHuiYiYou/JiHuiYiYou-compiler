## ⚠️ Critical finding: v2.11.20 RC-1 fix regression

v2.11.20 RC-1 fix (commit `56be6cf`) passed 5/6 slice tests (slice_index/iterate/literal/subrange/mixed_struct_slice_match) by happy accident but introduced SEGV in 6th test (`for_in_slice_nested`). Per `feedback_codegen_amd64_multifn`, single-function PASS evidence insufficient — multi-nested patterns require trace through every temp-id lifetime.

**Real bug:** emit_load line 704-710 marks dst as address-holder after load, but load's result is a VALUE (data at *ptr), not an address. When that value is later re-loaded (e.g. `loadl t42` reading the data_ptr VALUE from slot), emit_load indirect dispatch dereferences the VALUE as if it were a slot address → SEGV.

**Fix:** REMOVE load propagation block + tighten binop propagation (always propagate for `add/sub` on L_LOCAL regardless of src1 flag).

**v2.11.20 changelog + W-074.10 description needs amendment** (claim "emit_load flag propagate 真修" was over-aggressive for nested case).
