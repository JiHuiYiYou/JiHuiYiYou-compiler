> "进度又太慢, 又怕推块了老 revert, 进度就一直很缓慢, 二十多个小版本了, 自研后端还没搞定"

User 提出 28 个 Confirm FAIL 跨 7 簇(C.3 phi 11 / C.5 slice 5 / C.4 float 4 / B-runtime 3 / A2 ptr-deref 2 / unique 2 / cap_table test4 1)。User 选 **RCA-first** method,1 iter 诊断后落到本 plan。

**RCA 关键发现** (完整 RCA 见 [`docs/internal/rca-v2.11.17.md`](../../internal/rca-v2.11.17.md)):

1. 自研 backend 是**最小可行 backend**(per L4 § 4.3,`codegen_amd64_emit_call.jhyy:60-63`):不做 regalloc / 不做 peephole / **不做 phi resolve**(`emit_phi` 字面意义上 noop,只 emit 注释 + return 0)
2. **C.3 phi 11/28 真 bug**:`cg_emit_phi` (`codegen.jhyy:860-862`) 真的 emit QBE phi 节点进 IL,但自研 `emit_phi` 不翻译成 move → `.s` 缺 merge point 的 move 指令 → 11 个 phi 测试全挂 + **任何依赖 phi 解析 base/offset 的下游指令也挂** (潜在覆盖 C.5 slice 5 + A2 ptr-deref 2 + unique dungeon_game 1 = **19/28 = 68%**)
3. `emit_call.jhyy:32-34` 注释说 "phi resolved upstream" 是**误导** — `cg_emit_phi` 不 resolve,只 emit phi
4. C.4 float 4/28 是**架构边界**(零 SSE emit 代码,设计意图走 QBE_FALLBACK),不是 bug — 走 v2.11.19 自动 fallback
5. B-runtime 3/28 未诊断,留 v2.11.20
6. cap_table test 4 不属 v2 axis,推 v3.x

**修法候选** (完整 micro-spec 见 [`docs/internal/phi-fix-micro-spec-v2.11.18.md`](../../internal/phi-fix-micro-spec-v2.11.18.md)):
- 候选 A: 下游补回 `emit_phi` move emit — 影响 parse loop, MED risk, ~60-100 LOC
- 候选 B: 上游加 phi lowering pass — MED risk, ~80-120 LOC
- **候选 C(推荐):** 改 `cg_emit_phi` 直接 emit move-pair, **不发 phi** — LOC 最小(50-80),改动最局部,跟 v2.5.0 "minimal backend" 架构对齐

**本 sprint 选候选 C**。

### 1b. 改 `cg_emit_phi` (单点,~30-50 LOC)

位置: `compiler/src0/codegen.jhyy:855-863`

伪码:
```jhyy
// 原: 直接 emit phi 节点
// 改: 在每个前驱块末尾 emit move
fn cg_emit_phi(ir: *IRBuf, result: IRVal, block1: IRVal, val1: IRVal,
                                 block2: IRVal, val2: IRVal) -> i32 {
    // 分配 join block 的本地 result temp(已 caller 分配)
    // 在 block1 末尾: mov val1 → result
    // 在 block2 末尾: mov val2 → result
    // 不 emit phi 节点
    
    // 实现: 用 ir_emit_copy 在当前 IR 上下文 emit
    // 注意: 当前 IR 上下文可能在 block1 或 block2 中,需 caller 配合
    return 0;  // 实际 emit 由 caller 在合适 block 末尾做
}
```

**或者更激进**: 改 caller 调用方式,把 `cg_emit_phi` 拆成两个函数:
- `cg_emit_phi_then_part` (在 block1 末尾调, emit `mov val1 → result`)
- `cg_emit_phi_else_part` (在 block2 末尾调, emit `mov val2 → result`)
- 删除 `cg_emit_phi` 本身

### 1c. 配合 `cg_emit_if` / `cg_emit_match` (~20-40 LOC)

在 if/match value-producing 路径:
- 找到 emit then_val / else_val 的位置
- 不再 call `cg_emit_phi` + emit join block label
- 改成在 then 末尾直接 emit `mov then_val → result`
- 在 else 末尾直接 emit `mov else_val → result`
- join block 入口只用 result temp(不需重新定义)

**需要的支持**(可能已经存在):
- block-stack(per existing if/match emit)
- 每个 block 末尾的 "post-stmt hook"(检查 pending moves 并 emit)
- 新 temp 分配(join block 自己的 local temp — `ir_new_tmp`)
