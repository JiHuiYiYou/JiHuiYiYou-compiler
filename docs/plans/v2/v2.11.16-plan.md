## Bug surface deep-dive (for v2.11.17+ reference)

### A. C.5 slice addr+8 partial fix (Iter 4 residue)
- **File**: `compiler/src0/codegen.jhyy:881-891`
- **Code**: `let mut addr_plus_8 = addr;` (no offset) + comment "Pragmatic: emit `storel %t<len_id>, addr` AGAIN — wrong but无害"
- **Why partial**: `cg_emit_store(KIND_SLICE, slice_value, slot)` writes both ptr and len to SAME addr slot. The `len_id = val.id + 1` is the len temp, but the 2nd `storel` writes len to `addr` (NOT `addr+8`), so len overwrites ptr.
- **Why some tests PASS anyway**: `NODE_SLICE_LIT` at `codegen.jhyy:3214-3248` pre-builds ptr_addr + len_addr as separate IR temps BEFORE `cg_emit_store` is called. For initial `let s = &[10,20,30]`, the slice literal path bypasses the dispatcher. The dispatcher bug fires only on subsequent assignments (e.g. `let sub = s[1..4]`) or when `cg_assign` directly calls the dispatcher.
- **Fix pattern**: Either (a) emit `add %t<slot>,8` to construct len_addr, then use that as 2nd storel target — needs `IRVal` offset arithmetic primitive; or (b) factor `cg_copy_slice` helper that handles 16B store via 2 separate QBE IL stores (similar to existing `cg_copy_struct`).
- **LOC est**: ~15-25 LOC; could be ONE QBE IL builder helper + change dispatcher to use it.

### B. C.4 float imm bit-pattern (Iter 3 residue)
- **Files**: `compiler/src0/codegen_amd64_emit_call.jhyy:204-280` (`cg_parse_f64_imm_bits`) + `:283-323` (`emit_mov_imm_to_offset` + `emit_mov_f64_imm_to_offset`) + `:1215-1230` (copy IMM f64/f32 dispatch)
- **Bug 1**: `cg_parse_f64_imm_bits:230-233` explicitly returns 0 for fractional `d_N.M` literals (e.g. `d_2.5`). Need to extend parser to handle fractional values via IEEE 754 bit construction.
- **Bug 2**: No `emit_mov_f32_imm_to_offset` helper. f32 IMM `s_2.5` → integer 2 stored as 4-byte int; loaded via `movss` interprets as f32 garbage.
- **Bug 3** (deferred from Iter 3): `emit_binop:1366-1370` comment "src2 imm literal... imm fall through 现有 integer path". f64 ops with literal args emit `addq`/`imulq` instead of `addsd`/`mulsd`.
- **Fix pattern**: (1) Extend `cg_parse_f64_imm_bits` with IEEE 754 single+double bit construction (table lookup for common fractions 0.5, 1.5, 2.5, etc., or full strtod + bit-cast). (2) Add `emit_mov_f32_imm_to_offset` mirroring f64 helper. (3) Add src2-imm XMM path in `emit_binop`.
- **LOC est**: ~50-80 LOC for f64 + ~30-40 LOC for f32 + ~30-50 LOC for src2-imm XMM = ~110-170 total.

### C. A2-pointer-deref flag propagation
- **File**: `compiler/src0/codegen_amd64_emit_mem.jhyy:511` (emit_load indirect-dispatch check)
- **Bug**: `cg_is_address_holder(state, src)` check fails to fire because the address-holder flag is lost across `movq %rax, -<dst>(%rbp)` store in `emit_binop` (and through `emit_copy` at `codegen_amd64_emit_call.jhyy:1241-1243`).
- **Symptom**: `const_array_run.s:25` `movzbl -64(%rbp), %eax` reads low byte of stack slot containing ASCII_LOWER+25 address; should be `movzbl (%rax), %eax` reading ASCII_LOWER[25] = 122.
- **Fix pattern**: Add flag-propagation to `emit_copy` (when copying a pointer-typed temp, mark dst as address-holder) OR add flag-propagation to `emit_binop` final store.
- **LOC est**: ~10-15 LOC.
- **Risk**: MED — touches emit_copy/emit_binop hot path; could cascade-affect other pointer-heavy tests (struct passing, &local capture, slice ops).

### D. C.2 cap_table test 4 (16B struct cross-fn arg)
- **File**: `compiler/src0/codegen_amd64_emit_call.jhyy:550-697` (`emit_amd64_arg_regs`, lines 637-666 for Win path)
- **Bug**: For 16B struct pass-by-value, Win x64 ABI requires **2 integer regs** (RCX + RDX), not 1 reg + caller mem-copy. Current code treats `l %t32` (struct alloc ptr) as single 8-byte scalar in RCX, missing RDX half.
- **Fix pattern**: Detect 16B struct allocation in `emit_amd64_arg_regs`; emit 2 `movq` (loadl of struct+0 → RCX, loadl of struct+8 → RDX). For SysV, struct still passes via 2 regs (RDI+RSI for first args) but with same 2-load pattern.
- **LOC est**: ~40 LOC.
- **Risk**: HIGH — touches emit_call hot path used by every cross-fn struct call (cap_table_advanced, nested_struct_deep, struct_val_pass).

### E. dungeon_game gcc link error (Win ABI 5+ arg + symbol decoration)
- **Files**: `compiler/src0/codegen_amd64_emit_call.jhyy:1281` (Win ABI 5+ arg stack fallback) + `target_dispatch.jhyy` (target=Win vs SysV) + `abi_amd64_win.jhyy` (extern symbol decoration)
- **Bug 1**: For nargs ≥ 5, current code emits only rcx/edx/r8d/r9 (4 regs) + fake remaining args by copying rcx to spill slots. Real Win x64 ABI: push args 5+ to `40(%rsp)+` BEFORE `call`.
- **Bug 2**: Extern `puts`/`printf`/`scanf` declared without underscore prefix. On Windows mingw gcc, C library symbols are `_puts`/`_printf`/`_scanf`. Self-backend emits Windows ABI calling convention but with SysV-style symbol names.
- **Fix pattern**: (1) Implement Win ABI 5+ arg stack fallback (push args 5+ to `40(%rsp)+` BEFORE `call`). (2) Verify `_puts` decoration on Windows extern, OR ensure target dispatch emits right ABI for host.
- **LOC est**: ~20-40 LOC.
- **Risk**: HIGH — touches ABI calling convention + symbol decoration; could break all FFI tests, all extern-using tests.

### F. B-runtime (big_array + top_level_let_mut_types)
- **Files**: `compiler/src0/codegen.jhyy:3181-3211` (NODE_ARRAY_LIT stack alloc) + `:4277-4325` (module global data section emit) + `:1544-1600` + `:1921-1955` (NODE_IDENT/NODE_ASSIGN for IRVAL_STR globals)
- **Bug 1** (big_array): Frame size calculation misses either 400B array alloc OR printf arg spill slots OR double-counts 8B sum/i locals → STACK_BUFFER_OVERRUN at printf.
- **Bug 2** (top_level_let_mut_types): 3 globals means `cg_mod_global_register` called 3 times; either array grows but `n_mod_globals` doesn't track correctly OR data section labels collide.
- **Fix pattern**: Audit `emit_alloc` A0 stub call sites + prologue `subq $N, %rsp` to ensure sum matches all allocs. For globals, audit `cg_mod_global_register` lookup + ensure each global gets distinct label.
- **LOC est**: ~30-50 LOC total.
- **Risk**: MED — frame miscalc can silently corrupt unrelated tests; needs regression on other printf + array tests + multi-global tests.
