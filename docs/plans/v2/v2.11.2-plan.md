## Field-contract design (answers T1-a 根因)

### 不加 ILToken 字段

40-byte stride 在 5 处硬编码 (`_lexer.jhyy:1229, 1248, 1275`, `codegen_amd64.jhyy:139`, `_regalloc.jhyy:719`),加字段是 5 处协同 edit + offset accessor 重审 — 实际无收益。

### 用 `emit_mem` 已 documented 的 contract

`_emit_mem.jhyy:25-40` 文档 `tok.text/text_len = 指令原文 (含 mnemonic + 操作数)`,例如 `"jnz %t3, @then1, @else2"`, `"%t6 =w call $fib(w %t5)"`, `"alloc8 16"`。形式化:

**Instruction tokens** — `ALLOC / STORE / LOAD / LOADSUB / COPY / BINOP / CALL / RET / JMP / JNZ / PHI`:

| field | meaning |
|---|---|
| `kind` | `ILTOK_*` |
| `text` / `text_len` | NUL-terminated 整条指令原文 slice |
| `int_val` | **dst temp id**,or `-1` if no destination |
| `qbe_type` | result QBE type from `=<qt>` annotation;`0` = none;`-1` = `QBE_VOLATILE_MARKER` |
| `line` | source line |

**Declaration tokens** — `LABEL / FUNC_HEADER / DATA_STRING`: keep 现有语义 (`text` = name;`DATA_STRING` = `name\0content`)。这三个目前能 work,不打扰。

### 两处 contract 改动

1. **`int_val` 统一为 dst temp id** — 当前 `'%'` branch (`_lexer.jhyy:863-865`) 把 dst id 写到 **`text_len`**,跟 "`text_len` = 指令长度" 冲突。改 `int_val` + 更新 3 个 consumer (`emit_call:330`, `emit_copy:429`, `emit_binop:479`)。`_emit_mem.jhyy` + `_regalloc.jhyy:733` 已 assume `int_val = dst` → 让 lexer 跟 2 个 module 对齐。

2. **`ALLOC` size 从 `text` 读,不是 `int_val`** — `emit_alloc:258-268` 已 parse `"alloc8 16"` from `text`;删 `_lexer.jhyy:349-350` 的 `int_val = size` write。

### Lexer implementation

2 个共享 helper (add to `_lexer.jhyy`):

```
fn lex_finish_instr(s: *LexState, arena: *u8, t: *u8, kind: i32,
                    instr_start: *u8, dst_id: i64, qt: i32) -> i32
fn lex_consume_to_eol(s: *LexState) -> i32
```

`lex_finish_instr` 在每个 instruction helper 末尾调:计算 `len = cur - instr_start`,右 trim whitespace,`lex_init_token`,`arena_strdup` slice 写入 `text`,write `text_len / int_val / qbe_type`。

`'%'` branch (`_lexer.jhyy:832-871`) 在 consume `'%'` **前** record `instr_start`,slice covers `%tD =qt op operands`。bare-instruction paths (`ret`/`jmp`/`jnz`/`store`) 在 mnemonic 处 record `instr_start`。

每个 instruction helper **必须** consume to end-of-line (目前只有 `call` / `data` / `func_header` 做了,v2.11.1 加的)。共享 `lex_consume_to_eol` 覆盖 `ret / jmp / jnz / copy / binop / store / load / loadsub / alloc`。**这个 single helper 是 T1-a 根因的关键 fix** — 消除 phantom-`@then1` / lost-`@else2` 错位 (per Plan agent §1b)。

### Shared parse helpers → `codegen_amd64_state.jhyy`

`_emit_ctrl` + `_emit_call` 需跟 `_emit_mem` 同样的 scanner。Lift 到 state.jhyy (~90 LOC):
- `cg_parse_temp(text, len, idx) -> (temp_id, next_idx)`
- `cg_parse_int_from(text, len, from) -> (value, next_idx)`
- `cg_find_sub(text, len, pat) -> i64`
- `cg_parse_label(text, len, idx) -> *u8` (scans idx-th `@name`)
- `cg_streq_n(a, b, n) -> i32`

`_emit_mem` 保留 `mem_*` 副本不打扰 — dedupe 后续 sprint 清理。

## Frame state reset (answers T3-a)

### Call site: top of `emit_func_header`

Reasons:
- `cg_state_reset_for_function` 自己 doc (`_state.jhyy:128`) 写 "per function prologue",`emit_func_header:361-363` 有 TODO 说 `cur_fn_name` "由 caller 负责" — 但 caller 从未做。放这里关掉 TODO。
- `emit_func_header` 是唯一同时需要 reset **+** frame size 的位置 (emit `subq $N, %rsp` at `:357-359`)。
- `parse_and_emit` dispatch chain type-fragile (per W-068 fix #4)。

Reset: `next_offset = 0`, `total_alloc = 0`, `cur_fn_name = (*t).text`, `nparams = 0`。**不**碰 `target_tag` (per-compile)。

### Frame sizing: v2.11.2 global-max variant (~10 LOC)

Plan agent §5 提议 per-function pre-scan table (~70 LOC) 准确,但 v2.11.2 选更保守 fallback:

```
fn cg_compute_global_max_temp(tokens: *u8, n: i64) -> i64
```

Single pass over token array, take `max(int_val, all temp ids parsed from text)`。emit_func_header 用 `frame_size = 32 + (max_temp + 1) * 8`,rounded up 16。

**Correctness**: 浪费 stack 但**所有函数都用同一个 frame size**,function 边界不冲突。`fib_renamed` 144 bytes × 30 frames recursion 跑得动 (实测),`big_test` 留 v2.11.3。

**v2.11.3 升级**: per-function table (`CGState.cur_fn_index + frame_table[i]`),~70 LOC,精确每函数 frame size。

### De-risk: skip `regalloc_run` on self path

`codegen_amd64.jhyy:276` 调用 `regalloc_run`。Skip 它 → 所有 offset fn 走 identical `-(32 + t*8)` 公式 → 消除 N5 (emit_mem vs emit_ctrl offset 不一致) 整个 class。

**1 LOC change** + unify `compute_offset_for_temp_id_with_target` + `local_temp_offset` 到 `cg_offset_for_temp_with_target` (~20 LOC follow-on)。

**Hard invariant**: 不动 `codegen.jhyy` + `ir.jhyy` (per Plan agent R3 — v2.11.1 也守这条,D43 sha HOLD)。

## Risk + rollback

**R1** — `emit_mem` 终于 emit,peephole Rule 3 立刻变 assembler 错 (T1-e fix 之后)
- **Mitigation**: T2-c (Rule 3 register-dst only gate) **必须**跟 T1-e 在同一 commit (T1 整体),不能后置
- **Rollback**: `_peephole.jhyy:534` 早 return `input` disables entire pass in 1 LOC (behaviour-preserving for correctness)

**R2** — Lexer rewrite regresses `hello`,失去唯一当前 PASS test
- **Mitigation**: 先 fix `next_token_ret` + `next_token_copy` (T1-a isolated step),重 run `hello` 再动其他;`hello.il` 9 lines exercises exactly `dbgfile / func_header / label / dbgloc / copy-IMM / ret` — fast honest canary
- **Rollback**: T1-a 是 additive (`lex_finish_instr` 是新 tail call in each helper),revert 是 per-helper 不是 all-or-nothing

**R3** — D43 closure sha `6a2f2277…` drift,block ship on unrelated gate
- **Mitigation/evidence**: v2.11.1 ship ~390 LOC 同 6 files, sha **HOLD** because `byte_equal.sh` 比的是 `codegen.jhyy` / `ir.jhyy` 产 `.il` — 本 sprint 不动这 2 files。"不动 `codegen.jhyy` + `ir.jhyy`" 是 sprint hard invariant
- **Rollback**: 如 drift,原因几乎肯定是误编辑其他 7 文件外 — `git diff --stat` against `1e90999` 立即定位

**R4** — `CGState` + `cur_fn_name` + `frame_max_temp` 字段加,但 `codegen_amd64.jhyy:260` 仍 `malloc(64)` — current struct 7 fields ≈ 52 bytes,加 2 i64 = overflow → silent heap overwrite
- **Mitigation**: 同步 bump `malloc(64)` → `malloc(128)` in same edit
- **Rollback**: 字段加是 additive,revert 字段 + malloc 同步回 64

**R5** — `lex_il` slots 从 1024 → 16384 增加 memory usage,大测试可能 OOM
- **Mitigation**: arena 同步 2 MB → 8 MB;16384 × 40 bytes = 640 KB,8 MB arena 充足
- **Rollback**: slots raise 是 v2.11.3 才需要 (big_test 跨过 v2.11.3 EXIT exact ship gate);v2.11.2 可保守 4096 + 不动 arena
