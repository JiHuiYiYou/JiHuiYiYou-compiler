### **🔴 Phase 0 critical re-classification: A2 cluster root cause is WRONG**

Agent 2's audit claimed A2 cluster (3 tests: const_array / const_struct_array / dungeon_game) is caused by **missing `ILTOK_DATA_PRIM` token kind in lexer** (`.data` section silently dropped → link error).

**Phase 0 evidence REFUTES this claim**:
- `const_array_run.s` HAS `.data ASCII_LOWER: .byte 97, 98, ..., 122` correctly emitted
- `const_struct_array_run.s` HAS `.data PALETTE: .long 1, 2, ..., 9` correctly emitted
- `dungeon_game_run.s` (45KB) produced OK; gcc link fails with `ld returned 5 exit status` (not "undefined reference to $name")

**Real root cause for A2 cluster** = pointer dereference bug in self-backend:
- `const_array_run.s: movzbl -64(%rbp), %eax` reads 1 byte from stack slot containing ADDRESS (low byte = 0x25 from address of ASCII_LOWER), not `movzbl (%rax), %eax` reading ASCII_LOWER[25]
- `const_struct_array_run.s: movl -72(%rbp), %eax` reads 4 bytes of ADDRESS (low 32 bits), not `movl (%rax), %eax` reading PALETTE[2].b (= 9)

This is a **NEW cluster — call it A2-pointer-deref** — NOT the same as the "no ILTOK_DATA_PRIM" Agent 2 claimed. The "address-holder" pattern (per `%t11 (address-holder)` comments in .s) suggests the self-backend treats pointer-typed locals as if they were the pointee data.

## Iteration details

### Iter 1: A1-XMM return + arg reg split by qt (~15-25 LOC)

**File**: `compiler/src0/codegen_amd64_emit_call.jhyy`

**Bug surface** (verified via .s):
- `emit_call:341-343`: `let _r = emit_mov_reg_to_temp(state, ret_qt, "rax" as *u8, ret_off);` — hardcoded `"rax"` for all return types
- `emit_amd64_arg_regs:241-285`: integer regs (rcx/rdx/r8/r9 for Win; rdi/rsi/rdx/rcx/r8/r9 for SysV) for all args including f64

**Fix pattern**:
1. In `emit_call`, split return-reg move by qt:
   - W (i32/u32) → `movl %eax, -<off>(%rbp)` via `emit_mov_reg_to_temp(state, QBE_W, "eax", off)`
   - L (i64/u64) → `movq %rax, -<off>(%rbp)` via `emit_mov_reg_to_temp(state, QBE_L, "rax", off)`
   - S (f32) → `movss %xmm0, -<off>(%rbp)` (NEW)
   - D (f64) → `movsd %xmm0, -<off>(%rbp)` (NEW)
2. In `emit_amd64_arg_regs`, split arg-reg move by qt:
   - W/L → integer regs (existing)
   - D → xmm regs 0-7 (NEW) with `movsd` instruction
   - S → xmm regs 0-7 (NEW) with `movss` instruction
3. Add helper `emit_mov_temp_to_xmm_reg` / `emit_mov_xmm_reg_to_temp` using `movsd`/`movss`

**Tests**: 2 A1-XMM tests — `generics_fn_call_site_inference` / `generics_fn_turbofish_basic`.

**Honest FLIP est**: ~+2 PASS direct; ~+0-1 cross.
