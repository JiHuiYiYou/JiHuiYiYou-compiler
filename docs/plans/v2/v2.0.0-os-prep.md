## § 1 OS 启动里程碑定义(jhyy_OS 端锁)

来源: [../../../../jhyy_OS/docs/v0.0.0-design.md](../../../../jhyy_OS/docs/v0.0.0-design.md) § 6 + [../../../../jhyy_OS/docs/v0.0.2-foundation-revision.md](../../../../jhyy_OS/docs/v0.0.2-foundation-revision.md) § 4

| M | 名称 | OS 端目标 | 编译器侧硬前置 |
|---|------|----------|--------------|
| **M1** | kernel 启动(printk)| jhyy 编 `kernel.efi` → QEMU + OVMF → printk 到 framebuffer | v1.0 真自举闭环 + v2.0 `amd64_win_freestanding` target + v3.0 3a-3f 6 特性 |
| **M2** | cooperative scheduler | 单核调度器 | M1 基础上 |
| **M3** | syscall ABI | 系统调用接口 | M2 + 3a(asm syscall 指令)|
| **M4** | capability 落地 | Cap<T> 在 jhyy 编译期能验证 | M3 + v3.1 sprint 3g + 3g.5(`&mut + lifetime` + Cap<T> 8 规则 + phantom 0 字节)|
| **M5a** | design doc 锁 | OS 端设计阶段 | 无 |
| **M5b** | IPC 实现 | syscalls + capability 转移 | M4 基础上 |
| **M6** | driver 框架 | 字符设备起步 | M5b + 3a + 3c(asm MMIO + volatile)|
| **M7** | 自研文件协议 | Array<u8> 固定数组 FS,**不用泛型** | M6 基础上 |
| **M8a** | 早期 UI | framebuffer persistent + EFI GOP | M1 + 3c(volatile framebuffer MMIO)|
| **M8b** | PCI + AHCI + PS/2 keyboard | OS 端 driver | M8a 基础上 |
| **M8c** | virtio-net | OS 端 driver | M8b 基础上 |
| **M9** | SMP | rendezvous + per-CPU 数据 | M2 + 3f(memory barrier)|
| **M10** | riscv64 port | OS 端实现 | 等编译器 v4.x+ aarch64/riscv64 target |
| **M11** | **自举 OS 跑 jhyy 编译器** | jhyy_OS 跑 jhyy 编译器 + jhyy 编译器编 jhyy_OS | **M1-M10 + v3.2+ sprint 3i(generics)+ 3j(closures)+ 3l(std lib)** |

**MVP 路径(M1-M10)硬依赖链**:
```
v1.0 闭环 → v2.0 amd64_win_freestanding → v3.0 3a-3f → M1 → M2 → M3 → v3.1 3g + 3g.5 → M4 → M5b → M6 → M7 → M8a(M1+3c) → ...
```

**M11 硬依赖链**:
```
v1.0 闭环 → ... → M1-M10 → v3.2+ 3i + 3j + 3l → M11(自举 OS 真闭环)
```

## § 2 编译器侧里程碑视图(v2.0 / v2.x / v3.x 末对应)

| 编译器侧节点 | v0.8 末状态 | 完成定义 | 跟 OS 端里程碑接口 |
|--------------|-----------|---------|------------------|
| **v0.9.0** | ✅ shipped (2026-08-11, wip commit 2.83) | Stage 1 byte-equal 闭环(diff jhyy_0.il jhyy_1.il byte-equal) | 0 — OS 不可启动 |
| **v1.0.0** | ✅ TAGGED 2026-08-10 (commit `eabee0d`) | Stage 2 真闭环(jhyy_1 编 jhyy_1 跑 regress 持平 baseline)| 0 — 编译器自举达成,但 jhyy 不能编 OS(缺 3a-3f)|
| **v2.0** | 未启动 | `amd64_win_freestanding` target + 移除 QBE 工具链依赖 + 编 `hello-freestanding.jhyy` 跑 OVMF | **OS 启动链路第一项解锁**(为 M1 提供编译能力) |
| **v2.x** | 未启动 | 自写 IL → .s + `amd64_sysv` + `amd64_sysv_freestanding` + N 代 fixed point | jhyy 编 jhyy_OS 完全 self-contained |
| **v3.0** | 未启动 | OS P0 6 特性(3a inline asm / 3b naked / 3c volatile / 3d no_std / 3e link_section / 3f memory barrier) | **M1 启动可达** |
| **v3.1** | 未启动 | `&mut + lifetime` + Cap<T> 8 规则 + phantom 0 字节(3g + 3g.5 + 3g.7)| **M4 启动可达** |
| **v3.2+** | 未启动 | 后续特性(3i generics / 3j closures / 3l std lib) | **M11 启动可达** |
| **jhyy_OS M11** | 未启动 | jhyy_OS 跑 jhyy 编译器 + 编 jhyy_OS | **真自举 OS 闭环** |

**关键观察**:
- **v2.0 跟 v3.0 并行**:v2.0 启动 freestanding target(走 QBE + GCC),v3.0 启动 6 特性。两者**独立**,但都要 M1 启动前完成
- **v2.x 跟 v3.1+ 并行**:v2.x 自写 IL → .s,v3.1+ 实现语言特性。两者独立
- **M11 硬前置是 v3.2+ 3i+3j+3l**(jhyy 编译器自身源用 `Vec<T>` / 闭包 / std lib);M1-M10 不依赖

## § 3 关键决策点(v0.8 末 + jhyy_OS 协调后重写)

| # | 决策点 | 决策 | 落点 |
|---|--------|------|------|
| 1 | OS 走 ELF multiboot2 还是 UEFI + PE/COFF | ✅ UEFI + PE/COFF(走 OVMF) | jhyy_OS v0.0.2-foundation-revision.md § 5 锁 |
| 2 | v2.0 freestanding target 实现路径 | ✅ 走 QBE + GCC(实施快) | v2.x 末自写 IL → .s |
| 3 | v2.0 freestanding 跟 `#[no_std]` 关系 | ✅ v2.0 freestanding 不依赖 `#[no_std]` crate attr(只需"不 link libc");`#[no_std]` 跟 v3.0 sprint 3d 联动 | v2.0 + v3.0 sprint 3d 联动 |
| 4 | M1 启动硬前置是否包含 generics/closures | ✅ 不需要(M1-M10 用 fixed array + 显式 fn + struct env) | jhyy_OS v0.0.2-foundation-revision.md § 4 锁 |
| 5 | MVP coding style 跟 raw pointer | ✅ M1-M10 用 `*mut T` raw pointer + 手动 discipline;sprint 3g 后改 `&mut` | jhyy_OS v0.0.2-foundation-revision.md § 6 锁 |
| 6 | Cap<T> 8 字节布局 | ✅ `{cnode_idx: u32, depth: u8, rights: u16}` + phantom 0 字节(总 8 字节) | coordination.md § 3 锁 |
| 7 | 缺 feature = 设计输入(非 blocker)| ✅ jhyy 是 OS-driven,缺 feature 就加,只要不冲突 | coordination.md § 3 锁 |

## § 4 跨项目接口

### 4.1 v2.0 给 OS 端提供

| 提供项 | 形式 | OS 端用在哪 |
|--------|------|------------|
| `amd64_win_freestanding` target | `jhyy --target=amd64_win_freestanding` | OS 编 `kernel.efi` 走 OVMF |
| 编 `hello-freestanding.jhyy` 跑 OVMF demo | `kernel.efi` 启动 + printk | OS 端 M1 真启动参考实现 |
| 多目标 codegen dispatcher | `--target=<triple>` | OS 端选择 target |
| ABI 锁定(Windows x64 + SysV + freestanding) | spec § 13 增补 | OS 端调用约定对齐 |

### 4.2 v3.0 6 特性给 OS 端提供

| 特性 | 用途 | OS M 关联 |
|------|------|----------|
| 3a inline asm | 端口 I/O + CPU 特权指令 | M1 / M3 / M6 |
| 3b `#[naked]` fn | boot / interrupt entry | M1 |
| 3c volatile load/store | MMIO 设备寄存器 | M1 / M6 / M8a |
| 3d `#[no_std]` + core | freestanding | M1+ |
| 3e `#[link_section]` | boot 段控制 | M1 |
| 3f memory barrier | 多核同步 | M9 |

### 4.3 v3.1 给 OS 端提供

| 特性 | 用途 | OS M 关联 |
|------|------|----------|
| 3g `&mut + lifetime` | borrow checker(OS 模块间共享指针) | M4 capability |
| 3g + Cap<T> 8 规则 | 编译期验证 capability | M4 capability |
| 3g.5 phantom 0 字节 | Cap<T> 运行时 8 字节布局保证 | M4 + M5b IPC |
| 3g.7 跟 jhyy_OS cap 表 byte-equal 验证 | 编译器-OS 端 cap 表示 byte-equal | M4 + M5b |

### 4.4 v3.2+ 给 OS 端提供(M11 硬前置)

| 特性 | 用途 | OS M 关联 |
|------|------|----------|
| 3i generics(单态化)| jhyy 编译器源用 `Vec<T>` | M11 |
| 3j closures | jhyy 编译器源用闭包式 visitor | M11 |
| 3l std lib(9 模块)| jhyy 编译器编自己时需要 std + runtime | M11 |
