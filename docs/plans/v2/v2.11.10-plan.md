**根因: T3-a global-max frame size variant (v2.11.2 ship 决定)**

- v2.11.2 plan 原文: "T3-a Per-function frame state never reset + QBE temp 是 global 序列需 pre-scan (**v2.11.2 用 global-max variant, ~10 LOC vs 70 LOC full per-fn table**)"
- 实施位置:`compiler/src0/codegen_amd64.jhyy:279` 调 `cg_compute_global_max_temp(tokens, 40, n)` 扫整个 module 找最大 %tN,然后 `cg_state_set_frame_max_temp` 写进 `state.frame_max_temp`
- 实施位置:`compiler/src0/codegen_amd64_emit_ctrl.jhyy:438` 在 `emit_func_header` 里读 `(*cg).frame_max_temp` 算 `frame_size = (frame_max + 1) * TEMP_SLOT_BYTES()` 然后 emit `subq $N, %rsp` — **每个 function 都用同一 frame size**
- v2.11.3 plan 明确把 T3-a 全 per-fn table 标 "perf only, deferred v2.x 中期 V2-D" — **误判**, 实际是递归函数 SIGSEGV 的根因

**T3-a 全 per-fn table 修复策略**:

不调 `cg_compute_global_max_temp` 全扫一次,而是**两阶段 pre-scan**:
1. **Phase 1**: 扫 tokens 找所有 `ILTOK_FUNC_HEADER` 的 idx,记录到 `fn_starts: *u8` (i64[256]) 数组 (简单 pre-scan,~10 LOC)
2. **Phase 2**: 对每个 `[fn_starts[i], fn_starts[i+1])` 区间调 `cg_token_max_temp_id` 找 max → 写入 `per_fn_max[fn_idx] = max_temp_id`
3. **emit_func_header** 从 `per_fn_max[(*cg).cur_fn_idx]` 读对应 fn 的 max temp,emit `subq $N, %rsp`

每个递归 fn (`fact`, `fib`, `gcd`) 只用 5-10 个 temps,frame size = (10+1)*8 = 88 字节而非 15488,递归深度 30 也就 30×88 = 2640 字节,完全 fit。

**Scope UP — T4-c multi-arg FN_ARG 真修**:

v2.11.10 实施期间, gdb 取证 big_test 在 T3-a 真修后 SIGFPE in `gcd+158 idivl -576(%rbp)` (division by zero when b reaches 0)。根因追溯: gcd body 头两行 emit `movl %ecx, -504(%rbp)` (arg 0 = %a) 和 `movl %ecx, -512(%rbp)` (arg 1 = %b — 错!) — **两 args 都 hardcode %rcx**, %b 实际 = 0 → gcd loop 立即 b=0 → idivl SIGFPE。

W-074.7.7 (v2.11.3 SCOPE DOWN): "emit_copy FNARG 路径仍 hardcode 第 1 arg = %rcx。多 arg 真修 (T4-c full) 需要 lexer 把 fn header args 路由到 CGState.cur_fn_header_text — 当前 lexer 只 dup name 不 dup args, 故 cg_find_arg_idx 永远 return -1。"

v2.11.10 实施 T3-a 时, **同时真修 T4-c (~30 LOC 增量)**:
- lexer `next_token_func_header` 改 dup 完整 header text (`function w $name(args)`) 而非只 name
- emit_func_header 加 `cg_state_set_fn_header(state, (*t).text, (*t).text_len)` populate cur_fn_header_text
- emit_func_header 从 full header text extract name (`$name(ws)args`) 用于 `.globl` + label
- emit_copy FNARG 路径替换 hardcode `reg_rcx_for_qt(dst_qt)` → `cg_find_arg_idx` + `reg_rax_for_qt_idx(dst_qt, idx, target_tag)`

per [[feedback_codegen_amd64_multifn]] scope DOWN 阈值: T4-c 真修 ~30 LOC 跟原 T3-a ~50 LOC 累计 ~80 LOC source, 远低于 +5 FLIP trigger 阈值, **scope UP 接受**。

**File 3**: `compiler/src0/codegen_amd64_state.jhyy` 新增 `cg_compute_per_fn_max_temps` 函数 (Phase 1 + Phase 2, ~40 LOC)

```jhyy
fn cg_compute_per_fn_max_temps(state: *u8, tok_p: *u8, tok_size: i64, n: i64) -> i32 {
    let s = state as *CGState;
    if (*s).fn_starts == (0 as *u8) || (*s).per_fn_max == (0 as *u8) { return 1 as i32; }
    // Phase 1: 扫 fn_starts
    let mut fn_count: i64 = 0 as i64;
    let mut i: i64 = 0 as i64;
    while i < n {
        let t = (tok_p as i64 + i * tok_size) as *ILToken;
        if (*t).kind == ILTOK_FUNC_HEADER() {
            if fn_count < 256 as i64 {
                let p = ptr_add_u8((*s).fn_starts, fn_count * (8 as i64)) as *i64;
                *p = i;
            }
            fn_count = fn_count + (1 as i64);
        }
        i = i + (1 as i64);
    }
    if fn_count < 256 as i64 {
        let p = ptr_add_u8((*s).fn_starts, fn_count * (8 as i64)) as *i64;
        *p = n;
    }
    if fn_count > 255 as i64 { fn_count = 255 as i64; }
    (*s).fn_count = fn_count;
    // Phase 2: per_fn_max[i] = max temp id in [fn_starts[i], fn_starts[i+1])
    let mut fi: i64 = 0 as i64;
    while fi < fn_count {
        let start_p = ptr_add_u8((*s).fn_starts, fi * (8 as i64)) as *i64;
        let end_p = ptr_add_u8((*s).fn_starts, (fi + (1 as i64)) * (8 as i64)) as *i64;
        let start: i64 = *start_p;
        let end: i64 = *end_p;
        let mut max_t: i64 = 0 as i64;
        let mut j: i64 = start;
        while j < end {
            let t_max = cg_token_max_temp_id(tok_p, tok_size, j);
            if t_max > max_t { max_t = t_max; }
            j = j + (1 as i64);
        }
        let p2 = ptr_add_u8((*s).per_fn_max, fi * (8 as i64)) as *i64;
        *p2 = max_t;
        fi = fi + (1 as i64);
    }
    return 0 as i32;
}
```

## Risks + scope UP/DOWN considerations

**Risk 1 (MEDIUM)**: per_fn_max table 256-entry 固定 array 假设 fn 数 < 256 — big_test ~60 fns 安全。**Mitigation**: 加 `if fn_count >= 256` safety check + clamp 255 (per Phase A code)。

**Risk 2 (MEDIUM)**: T4-c 真修连带 lexer `next_token_func_header` 改 dup full header — emit_func_header 的 `.globl` arg + label 之前用 `(*t).text` 当 name, 现在是 full header, 需 extract name。**Mitigation**: Phase C name extract 代码 (从 `$` 到 `(` 或 ws)。

**Risk 3 (LOW)**: hdr_start 含 leading ws 时 `.globl` 多一个空格 → GAS `.globl  function...` link fail (实测发生)。**Mitigation**: Phase D hdr_start ws skip loop。

**Risk 4 (LOW)**: T4-c reg_rax_for_qt_idx Win/SysV gated by target_tag — SysV 用 rdi/rsi/rdx/rcx, Win 用 rcx/rdx/r8/r9; 函数已有, 不需新增 helper。

**Risk 5 (LOW)**: 改动 cross 5 文件 (codegen + state + emit_ctrl + emit_call + lexer) — 需要 rebuild 全 chain。**Mitigation**: standard `make selfhost` cycle。

**Risk 6 (HIGH, accepted)**: T3-a + T4-c fix 后, big_test 仍 SIGFPE due to T4-g (W-074.6 family pre-existing bug)。**Mitigation**: scope DOWN — 5/6 closure ship, T4-g 真修 v2.11.10a+ (估 ~30-50 LOC)。
