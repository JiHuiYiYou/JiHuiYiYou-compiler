# v2.13.8 — W-058 fmod emit 路径真修 (fold `a % b` 到 user-space formula)

## Context

v2.13.7 真修 W-057 (UTF-8 3/4-byte codepoint) 后,剩 2 条真未修: W-058 (vendor QBE 不支持 `remd`/`rems` 浮点取模) + W-081 (phi merge gap 4 sub-bugs 复合)。本 sprint 修 W-058,scope 限定小改动 (~30-60 LOC source)。

**W-058 范围** (per `docs/internal/workarounds.md:4047-4086`):
- spec 附录 B P3 fmod row "浮点取模 `%=` / `a % b` reject" (i32/i64 整数模 ship, 浮点模不 ship)
- 症状: `test.jhyy:3:9: error: invalid instruction 'remd' (vendor QBE 2026-08-15 build 不支持)`
- 根因: vendor QBE (qbe/qbe.exe 2026-08-15 build) 不实现 `remd` (f64 remainder) 和 `rems` (f32 remainder) 指令。其他 backend (e.g. gcc) 编译期 fold 到 `fmod()` library call, vendor QBE 不能 fold 拒绝指令
- 影响: user-space fmod 测试尚未 ship; OS (jhyy_OS) MMIO buffer scan 用 i64 % i64, 不依赖浮点模; jhyy 暂无 `<math.h>`, 用户写 fmod 一般 lib call (`extern fn fmod(...)`) 不走 `%` 路径

## 真修 path (scope 限定 — 临时方案, 5-instruction formula trunc toward 0)

**Codegen emit 改 path** (`src0/codegen.jhyy` cg_binop early-return):
- `OpRem` + `qt = D` (f64) 或 `qt = S` (f32) 时, 不直接 emit `remd`/`rems`, 改成 emit 5-instruction user-space formula **trunc** (toward 0; per user 2026-09-21 决定):
  ```asm
  # a % b (f64) → a - trunc(a/b) * b
  %t1 =qt div %t<a>, %t<b>          # a/b
  %tn =w dtosi %t1                  # dtosi (f64→i32) 或 stosi (f32→i32)
  %tnf =qt swtof %tn                # swtof (i32→float), 保持 f32/f64 类型
  %tm =qt mul %tnf, %t<b>           # trunc(a/b) * b
  %t<dst> =qt sub %t<a>, %tm        # a - trunc(a/b) * b
  ```
- **QBE IL 多态 arith op** (`div`/`mul`/`sub`) 靠 `=d`/`=s` 类型后缀, **不**嵌 type suffix 进 opcode name (跟 `stosi`/`dtosi`/`swtof` 这类 type-conversion ops 区分开)
- `%=` (compound assign) 走 binop path 同, parser desugar `a %= b` → `a = a % b` (per parser PREC_ASSIGN dispatch), 无独立 dispatch
- vendor QBE 不变 — `div`/`dtosi`/`stosi`/`swtof`/`mul`/`sub` 都 ship 很久, vendor QBE 都支持 (per `qbe/ops.h` `O(div, T(w,l,s,d,...))` 等)

**W-058 entry 实现路径 3 选择** (per workarounds.md:4076):
> "fmod library helper — 临时方案: codegen 把 `a % b` (f64) 折成 `(a - (a / b).trunc() * b)` user-space formula, vendor QBE 提供 `dtosi` (f64→i32) + `swtof` (i32→float)"

本 sprint 选 path 3 = 临时方案 (LOW risk, vendor QBE 不变, 自研 backend 不变, codegen 一处改)。

**Fold op 选 trunc (per user 2026-09-21 决定)**:
- `trunc` (toward 0) 跟 QBE upstream `remd`/`rems` spec 一致 + 跟 C `fmod()` 一致
- 不需 spec LIMIT 段 (semantics 直接 match 标准库)
- 将来 vendor QBE 加 `remd`/`rems` 支持后, fold IL 跟 native IL 产生结果 byte-equal (零迁移成本)
- 对比 `floor` (toward -∞): 跟 Python `%` 一致但 跟 C/QBE 不同 → spec LIMIT + 将来迁移成本高

**Test 加**:
- `compiler/tests/examples/fmod_basic.jhyy` (~10 LOC): `let r: f64 = 7.0 % 2.0; r as i32` → exit = 1
- `compiler/tests/examples/fmod_negative.jhyy` (~10 LOC): `let r: f64 = -7.5 % 2.0; (r as i32) + 100` → exit = 99; trunc 区分 floor (floor 会 exit=100). 注意: `+100` 是为了避免 Windows NTSTATUS 误判 — Win process `exit(-1)` Python 看到 `0xFFFFFFFF` 被 ntstatus_name() 视为 runtime crash, regress W-028 mod-256 来不及
- `compiler/tests/examples/fmod_f32.jhyy` (~10 LOC): `let r: f32 = 7.0 % 2.0; r as i32` → exit = 1 (f32 path 同 f64 formula)

**Spec §附录 B P3 fmod row 修订**:
- 加段: "v2.13.8+ codegen emit `a % b` (float) 用 user-space formula `a - trunc(a/b) * b` (vendor QBE 不支持 `remd`/`rems`, 临时方案). Semantics = truncated division (跟 QBE upstream `remd` spec + C `fmod()` 严格一致, 标 NOT LIMIT)."
