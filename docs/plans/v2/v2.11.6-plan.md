**v2.11.6 调研 (2026-09-12)**:

原 plan: 单纯 block-name uniquify (`_b<count>` suffix 拼 `.L<name>`), 预期修 big_test link fail。实现后发现:
1. emit_label / emit_jmp / emit_jnz 加 `_b<count>` suffix 后跑 self-backend big_test
2. big_test 仍 link fail — 但**error 不一样**: 之前 "ld returned 1" (no entry point), 现在 link error 仍在
3. 读 big_test.s 调试: `.s` 文件 size 异常小 (e.g. 17K 行 vs QBE fallback 40K+ 行)
4. 比对 .s 行数 vs QBE fallback: **big_test emit 4090 行**, 但 GAS assemble 后只剩 3500+ 行 (中间截断)
5. 找截断点: 在 `t_bit_and` 函数 body 中部, 函数后面所有函数 (含 main_jhyy FH #118) 全部不见
6. 排查路径: emit_func_header (FH) 都调到了 (118 个 FH 全部 dispatch), emit_func_body 出口看 peephole_fold 返回 fold 后的 buf
7. **根因**: `peephole_fold` `max_lines = 4096` cap, 4090 行 .s 输入折半到 4000+ 行 fold 后, 第 4091 行起 `line_idx >= max_lines → break` → 早退 fold loop → **folded buf 在 t_bit_and body 中部 truncate** → 后续 main_jhyy 等所有函数 body 不见 → link fail

**根因确认**: `peephole_fold` `max_lines` cap 设计时估 4096 lines 够 cover regress 用例 (per comment "够 cover regress 用例"), 但 big_test emit 4090 行超出预期。`max_lines` 不是"regress 用例行数"而是"biggest single function body 行数", 设计假设错了。

**File**: `compiler/src0/codegen_amd64_peephole.jhyy:554`

```jhyy

// 根因:big_test.jhyy emit .s 有 4090 行,cap 4096 时刚好 pass 但 fold 后
```
