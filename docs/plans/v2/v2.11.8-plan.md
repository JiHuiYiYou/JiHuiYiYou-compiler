**v2.11.7 调研结论 (per `docs/plans/v2/v2.11.7-plan.md` + `docs/internal/workarounds.md` W-074.7.8 NEW entry)**:

真根因 = **所有 derived address** (e.g. `add %t6, 0` 的 result temp 装的是 runtime 计算的 address, 不是 stack slot)。Codegen 当前 1-to-1 栈栈搬运假设 (L4 § 3.5 E2 简化边界) 在 `storew val, derived_addr` 跟 `loadw derived_addr` 形态上根本不成立 — derived address 需要 `movl %eax, (%raddr)` 间接写, 不能走 `movl %eax, -<slot>(%rbp)` slot 写。

empirical 取证 (struct_val_pass.jhyy self-backend `.s`):
```asm
movq -8(%rbp), %rax           # load 8-byte pointer from %t6's slot
addq $4, %rax                 # add 4 (偏移 = struct.y)
movq %rax, -96(%rbp)          # store pointer to %t8's slot  (derived-address)
movl -88(%rbp), %eax          # load 4-byte value (10)
movl %eax, -96(%rbp)          # ❌ OVERWRITES pointer with 10
```

**v2.11.7 scope UP 实施 53/115 → 40/115 regress 原因**: 4 emit path 真修都假设 src/dst 必是 stack slot — 修 alloc-result pointer (lea 取 ADDRESS 然后写到 dst slot) 反而比原 bug 更错 (因为 dst 在 `storew val, derived_addr` 形态下不是 slot, 是 derived address)。

**v2.11.8 真修方向**: bitmap flag **任何 temp holding derived address** (alloc-result + binop add/sub pointer-arith + copy of address-holder); emit_load/emit_store/emit_loadsub dispatch slot vs indirect (`movl (%r8), %reg`); emit_copy propagate flag; emit_call arg load 不变 (因为 arg 是 address VALUE, 现有 `movq -off, %reg` 已正确)。

### Phase C: emit_alloc flag + lea+mov + self-referential slot fix (~155 LOC)

**File**: `compiler/src0/codegen_amd64_emit_mem.jhyy` (lines 285-340)

**关键真修**:
1. **flag write**: `let _had = cg_record_temp_holds_address(state, dst);`
2. **lea+mov emit**: `leaq -<region>(%rbp), %rax; movq %rax, -<formula>(%rbp)` 把 alloc'd 地址写到 dst 自己的 pointer-slot
3. **self-referential slot bug fix**: skip `cg_record_temp_slot` (v2.11.5 design 让 pointer-slot == region, lea+mov 自我覆盖) — pointer-slot 走 formula `-(32+t*8)` Win / `-(t*8)` SysV, NOT region offset
4. **formula vs region 分离**: 后续 `storew val, %t_derived` 走 indirect 写 val 到 region 不影响 pointer-slot, `add %t6, off` 重读 pointer-slot 永远拿到正确的 alloc'd 地址

```jhyy
// v2.11.8 (W-074.7.8): alloc-result temp 是 address-holder (持有 alloc'd
// 栈对象 ADDRESS 而非 VALUE)。emit_alloc 后调 cg_record_temp_holds_address
// flag 这个 temp。emit_load/store/loadsub 看 flag 决定 indirect vs slot。
let _had = cg_record_temp_holds_address(state, dst);

// v2.11.8 self-referential slot bug 真修:
// v2.11.5 design cg_record_temp_slot(state, dst, off=region) 让 dst 的
// pointer-slot == region offset, lea+mov 写 address 到 dst slot = 写到
// region 本身 — 后续 storew val, %t_derived 走 indirect 写 val 到 region
// 覆盖掉地址。真修: SKIP cg_record_temp_slot, pointer-slot 走 formula
// -(32+t*8) Win / -(t*8) SysV = DIFFERENT from region offset.
// lea+mov 写 address 到 dst pointer-slot (formula), 后续 indirect store
// 写 val 到 region 不影响 pointer-slot, add %t6, off 重读 pointer-slot
// 永远拿到正确的 alloc'd 地址。
let pointer_slot = cg_offset_for_temp_with_target(dst, target_tag);
emit_mov_reg_to_temp(state, dst, "q", "rax", region_off);  // movq %rax, -<formula>(%rbp)
```

## Risks + scope UP considerations

**Risk 1 (HIGH)**: bitmap propagation gap — missing a propagation site (e.g. emit_copy TEMP, ret-temp chain) → silent wrong emit, no crash. **Mitigation**: Phase F emit_copy flag propagate (TEMP + FNARG paths) + post-build audit grep `addq $N, %rax; movl %eax, -<off>(%rbp)` (should NOT exist for address-holder dst).

**Risk 2 (MEDIUM)**: peephole fold across indirect — peephole might fold `movq -off, %r8; mov<size> (%r8), %reg` → `mov<size> -off, %reg` (slot read), silently reverting the fix. **Mitigation**: regress.py 跑后 audit; if regress, add `%r8` to peephole skip-list.

**Risk 3 (LOW)**: regalloc in active use — if regalloc has been wired since v2.11.5, address-holder temps in registers would bypass slot-read. **Mitigation**: grep `regalloc_run` in `codegen_amd64_run.jhyy`. If present, document and defer regalloc-aware fix to v2.11.9.

**Risk 4 (LOW)**: C-bridge setter unused dead code — `jh_cgstate_set_holds_address` is no-op. **Mitigation**: keep it for API consistency with `jh_cgstate_set_temp_slots` (forward-ref-safe pattern per v2.11.5); add `__attribute__((used))` to silence -Wunused.

**Risk 5 (MEDIUM)**: off-by-one in propagate flag at function boundary — if a temp's flag isn't cleared when crossing into a new fn where the same temp id is reused with a different meaning. **Mitigation**: per-fn zero in `cg_state_reset_for_function` (Phase A.5) is the canonical solution; verify with audit-grep on emitted `.s`.

**Risk 6 (MEDIUM)**: scope UP 大改 CGState + 5 emit path + emit_binop propagation — large change surface, may introduce new regress. **Mitigation**: per [[feedback_codegen_amd64_multifn]], scope DOWN trigger is FLIP count > 5; if triggered, scope DOWN to Phase A+C+D (state infra + emit_alloc + emit_binop flag) only, defer emit_load/store/loadsub indirect to v2.11.8a+.

**Risk 7 (HIGH)**: self-referential slot bug — alloc-result dst 的 pointer-slot 跟 region 在 v2.11.5 design 下物理重叠. **真修**: SKIP `cg_record_temp_slot` (v2.11.5 的 alloc-tracking 留 deprecated, pointer-slot 走 formula), formula 跟 region 物理分离, lea+mov 不自我覆盖.

**Risk 8 (HIGH)**: FNARG flag propagate gap — l-typed fnarg (struct param pointer) 走 FNARG path 不 flag propagate → struct_val_pass EXIT garbage. **真修**: FNARG path 加 `if dst_qt == QBE_L_LOCAL() { cg_record_temp_holds_address(dst) }` (Phase F).
