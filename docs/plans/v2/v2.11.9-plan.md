**v2.11.9 plan mode Explore agent 调研发现 (2026-09-13)**:

调研发现 2 个独立 root cause — W-074.7.9 entry 原 "into" 假设是 **错的**; 实际是 **x86 `idiv` `#DE` fault** (Windows reports as STATUS_INTEGER_DIVIDE_BY_ZERO 0xC000008C, 但某些 config 会 wrap 成 0xC0000095), 因 `idivl`/`idivq` 没有 `cltd`/`cqto` sign-extend prefix + lexer 不识别 QBE `rem` keyword (QBE `%` 操作 → `rem` IL op, lex 静默 skip → 操作不 emit):

**Root cause #1 — `idiv` emit 无 sign-extend prefix**:
- File: `compiler/src0/codegen_amd64_emit_call.jhyy:1068-1080` (`is_div` branch)
- 现有 emit: `\tidiv<size> -src2(%rbp)` 或 `\tidiv<size> $imm` — **NO `cltd`/`cqto` prefix**
- x86 `idivl` semantics: dividend = `(%edx << 32) | %eax` (64-bit), quotient 在 %eax, remainder 在 %edx
- `%edx` 残留 (前 op 写入只设 %eax 不设 %edx, 例如 `movl $5, -<off>(%rbp)` 用 %eax 写 4-byte; 或前面 `idiv` 的 `%rdx` 残留) → dividend ≠ 真 src1 值
- Even a small divisor produces quotient > 2^31-1 → **#DE fault** (Divide Error) → Windows STATUS_INTEGER_DIVIDE_BY_ZERO 0xC000008C (or wrapped 0xC0000095 per process config)
- Compare with `is_mod` branch at lines 1081-1105 — emits `\tcltd\n` / `\tcqto\n` BEFORE `idiv` ✅ (correct)
- Evidence: `compiler/build/bin/_regress_big_test.s` grep `idivl|cqo|cltd|cdq` = 5/0/0/0 hits pre-fix (zero sign-extend prefixes for 5 div instructions) → 5/5/5/0 post-fix
- **Fix**: add `\tcltd\n` / `\tcqto\n` prefix to `is_div` branch (mirror `is_mod`); remainder in %rdx is silently discarded by x86 `idiv` → safe (the QBE `div` user semantics is "return quotient" = %rax, not %rdx)

**Root cause #2 — Lexer 不识别 QBE `rem` keyword**:
- File: `compiler/src0/codegen_amd64_lexer.jhyy:631` (`next_token_binop` dispatcher table)
- Existing accepted keywords: `add|sub|mul|mod|div` (lines 646, 657, 680, 682, 694)
- QBE `%` operator emits `rem` (signed remainder) in QBE IL, e.g. `%t109 =w rem %t107, %t108` (per QBE spec)
- Our lexer doesn't have a `rem` branch → `next_token` returns -1 → `lex_il` line 1420-1424 silently skips 1 byte at a time → `rem` keyword + 2 operand temps (5+ chars) ALL skipped → those `t109`/`t110` SSA values never appear in `.s` (grep confirms 0 hits pre-fix → 9 hits post-fix)
- big_test 用 `%` 9 次 (e.g. `sum_even_to`, `sum_odd_to`, `harmonic_sum`, `collatz_steps`) → ALL miscompute → 最终 exit code garbage
- Evidence: `compiler/build/bin/_regress_big_test.il` 9 `rem` QBE ops; grep `.s` for `movq %rdx, %rax` count = 0 pre-fix → 9 post-fix
- **Fix**: add `rem` branch in `next_token_binop` (`r` = consume `em`, op_name=`rem`, dispatch `is_rem` flag); in main `next_token`, add `'r'` → ret/rem disambiguate dispatch (跟 `'d'` → div pattern 一致, main dispatcher consume 第 1 byte only, next_token_binop 内部 consume "em")

**Bonus — `'r'` → `'ret'` pre-existing 返回 -1 问题**:
- File: `compiler/src0/codegen_amd64_lexer.jhyy:1124-1128` (pre-fix)
- `'r'` → `'ret'` branch returns -1 for any non-"ret" 'r'-starting token → newly-added 'rem' branch unreachable
- **Fix (Phase B')**: combined into single `'r'` → ret/rem disambiguate dispatch (跟 `'d'` → div + `'j'` → jmp/jnz pattern 一致, 两个 `if` 而非 `if/else if/else` per jhyy type inference)

**Bonus — `mod` QBE keyword works but unused**:
- QBE emits `rem` for `%`, never `mod` (per QBE IL spec § 6.3). So `mod` branch is currently dead code; keep for future-proofing.

### Phase A: `idiv` sign-extend prefix (~5 LOC)

**File**: `compiler/src0/codegen_amd64_emit_call.jhyy` (lines 1068-1080)

**Strategy**: insert `cltd` / `cqto` emit before `idiv` instruction, mirroring `is_mod` branch (lines 1084-1094):

```jhyy
} else if is_div != (0 as i32) {
    // v2.11.9 (W-074.7.9): idiv 必须有 sign-extend prefix (cltd/cqto) — x86
    // idivl semantics dividend = (%edx << 32) | %eax; %edx 残留会触发 #DE
    // fault. QBE div 语义只读 %rax quotient (%rdx remainder 丢弃 — safe).
    if qt == QBE_L_LOCAL() {
        let _se1 = sb_append_cstr(arena, s, "\tcqto\n" as *u8);
        let _b1 = sb_append_cstr(arena, s, "\tidivq" as *u8);
    } else {
        let _se1 = sb_append_cstr(arena, s, "\tcltd\n" as *u8);
        let _b1 = sb_append_cstr(arena, s, "\tidivl" as *u8);
    }
    let _b2 = sb_append_cstr(arena, s, " " as *u8);
    if src2_is_imm != (0 as i32) {
        let _b3i = sb_append_cstr(arena, s, "$" as *u8);
        let _b3v = sb_appendf_lld(arena, s, "%lld" as *u8, src2_imm_val);
        let _b3n = sb_append_cstr(arena, s, "\n" as *u8);
    } else {
        let _b3 = sb_appendf_lld(arena, s, "%lld" as *u8, src2_off);
        let _b4 = sb_append_cstr(arena, s, "(%rbp)\n" as *u8);
    }
}
```

### Phase B: Lexer `rem` keyword gap (~8 LOC)

**File**: `compiler/src0/codegen_amd64_lexer.jhyy` (line 631 `next_token_binop`)

**Strategy**: add `rem` branch in dispatcher table. The `r` byte currently falls through to default error case. Add analogous to existing `div` branch (lines 685-694):

```jhyy
} else if op_byte == (114 as i32) { // 'r'
    // v2.11.9 (W-074.7.9): "rem" — consume "em" (QBE '%' operator = signed remainder).
    // Same x86 path as mod (cltd/cqto + idiv + movq %rdx, %rax); differ from mod
    // only in IL keyword, so op_name = "rem" routes through emit_binop is_rem branch.
    let n1 = lex_peek_byte_at(s, 0 as i64);
    let n2 = lex_peek_byte_at(s, 1 as i64);
    if n1 != (101 as i32) || n2 != (109 as i32) { return -1 as i32; }
    let mut i: i64 = 0 as i64;
    while i < (2 as i64) {
        let _x = lex_next_byte(s);
        i = i + (1 as i64);
    }
    op_name = "rem" as *u8;
}
```

### Phase B': Combined `'r'` → ret/rem disambiguate dispatch (~25 LOC + cleanup -7)

**File**: `compiler/src0/codegen_amd64_lexer.jhyy` (line 1124 main `next_token` dispatcher)

**Strategy**: combine `'r'` → `'ret'` branch (pre-existing) + `'r'` → `'rem` dispatch (new) into single combined dispatcher. 跟 `'j'` → jmp/jnz pattern 一致, 用两个 separate `if` 而非 `if/else if/else` per jhyy type inference requirement:

```jhyy
// ── 'r' → 'ret' / 'rem' ──
// v2.11.9 (W-074.7.9): 'rem' 必须在 'r' dispatch 内部 disambiguate —
// 否则 'r' → 'ret' fallback 对 'remw' 等返回 -1 → lex_il 静默 skip →
// rem-result SSA values 永远 missing from .s。QBE rem = signed remainder
// (same x86 path as mod: cltd/cqto + idiv + movq %rdx)。
// 注:跟 'd' → 'div' dispatcher 同样的 pattern — main dispatcher 只 consume
// 第 1 个 byte ('r'),next_token_binop 内部 consume "em"。
if c0 == (114 as i32) {
    let n1r: i32 = lex_peek_byte_at(s, 1 as i64);
    let n2r: i32 = lex_peek_byte_at(s, 2 as i64);
    if n1r == (101 as i32) && n2r == (116 as i32) {
        // "ret"
        if lex_match_kw(s, "ret" as *u8, 3 as i64) == 0 { return -1 as i32; }
        return next_token_ret(s, arena, t);
    }
    if n1r == (101 as i32) && n2r == (109 as i32) {
        // "rem" — consume 'r' only, next_token_binop consumes "em"
        let _xr = lex_next_byte(s);
        return next_token_binop(s, arena, t, 114 as i32);
    }
    return -1 as i32;
}
```

Plus cleanup: delete pre-existing 1269-1272 unreachable late 'r' branch (replaced by new combined dispatch above).

## Risks + scope UP/DOWN considerations

**Risk 1 (LOW)**: `idiv` prefix 增加会让 `idivl` 比 `divl` 快一点 (e.g. multi-div 测试) — 但 `.s` 行数+少量, 无 perf regression. **Mitigation**: regress.py baseline byte-equal preserved.

**Risk 2 (LOW)**: Lexer `rem` branch 可能跟其他 'r'-leading QBE IL token 冲突 (e.g. `ret`, `round`, etc.) — but QBE IL keywords are checked explicitly per dispatch, and `ret`/`round` 不在 `next_token_binop` 路径. **Mitigation**: `'r'` → ret/rem disambiguate dispatch (跟 `'d'` → div + `'j'` → jmp/jnz pattern 一致); audit grep `compiler/build/bin/_regress_big_test.il` for `rem\b` occurrences (should be 9 matches per QBE spec).

**Risk 3 (LOW)**: `is_rem` 跟 `is_mod` 共用同一 emit path → QBE emit `mod` 直接走 `mod` branch (per QBE spec §6.3 actually uses `rem`, not `mod`; but if a future IL emits `mod`, both branches handle it identically). **Mitigation**: cross-check QBE spec.

**Risk 4 (LOW)**: Scope 小 (~30 LOC source QBE side only) — 不触发 scope DOWN per [[feedback_codegen_amd64_multifn]]; 反而风险是改动太小遗漏 — **Mitigation**: 全 5 emit_binop 分支 audit (add/sub/mul/div/mod/rem/cslt/...); post-build 5/5 EXIT exact closure 是强验证.

**Risk 5 (LOW)**: W-074.7.9 entry 之前假设 "into" 错; 新 root cause 需 overwrite (per [[feedback_document_workarounds_in_docs]] + [[feedback_fix_evaluation_rule]]). **Mitigation**: 写明"原假设错"reasoning + Explore agent 取证引用.
