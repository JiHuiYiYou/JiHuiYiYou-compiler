## 根因 (2 个独立 bugs,NOT 1 个)

**Bug A — shl/shr (5 ops) missing**:
1. `compiler/src0/codegen_amd64_lexer.jhyy:631-720` `next_token_binop` dispatcher 只接 'a' (add) / 'd' (div) / 'm' (mul/mod/rem) / 's' (sub/store) / 'u' (udiv/urem) / 'c' (cslt/.../ceqw/cnew) 等 prefix;**完全没有 'h' (shl/shr) / 完整 'a' (and) / 'o' (or) / 'x' (xor) handler**
2. `compiler/src0/codegen_amd64_lexer.jhyy:1307-1329` main dispatcher `'s'` branch 在 sub check 前**没有 shl/shr check**;main dispatcher **没有 'o' (or) / 'x' (xor) 分支**;`'a'` 分支 **没有 and check**
3. `compiler/src0/codegen_amd64_emit_call.jhyy:1013-1040` op-name detection chain 没有 and/or/xor/shl/shr check → emit_binop `else` fallback emit `addl/addq`
4. cascading:t180+ 的 copy emit 在 IL 序列里 emit → 但因为 dst temp 没被 def → emit_copy 拿 dst_id 错误 → 跟 Bug B 联动 → bit_pack hang

**Bug B — emit_copy dst_id=0**:
1. t178 (last correct) → t180 (collapsed to -32) 之间的 emit_copy 拿 `dst_id=0`
2. `lex_parse_temp_id_from_ident` 返回 0 on parse fail
3. `cg_offset_for_temp_with_target(dst_id=0, target_tag)` → formula `-(32 + 0*8) = -32` (Win)
4. 推测 root cause:LHS parse path `codegen_amd64_lexer.jhyy:1032-1073` recursive `next_token` for copy tokens,在 t178 后 cursor state corruption

**QBE baseline (对照,不受影响)**:
- `big_test_run.s:892-911` (QBE fallback output) 正确 emit,使用 register-only operands
- self-backend 不能复用 QBE 的 register-only 策略,必须自己实现 correct slot allocation

**Risk 4 (LOW, accepted)**: 改动 cross 2 文件 (lexer + emit_call) + 6 doc files。

**Risk 5 (NONE)**: v2.11.8 derived-address tracking 真修未 regress — shift result 永不 address-holder。

**Risk 6 (MEDIUM, accepted)**: Phase C root cause 修复不完整可能暴露 第 4 个 sub-bug。**Resolution**: Phase C fix 是 simple 2 行,无 sub-bug 暴露。
