# v1.7.0 任务清单 + 概要设计: gap + workaround 补全 (5 候选, 分多步走)

> **承接**: v1.6.0 shipped (commit `c02ea9f`, 2026-08-27 — W-053 char family + W-054 sizeof IL).
> **当前 baseline**: regress 78/82 PASS + 4 SKIP, Stage 2 byte-equal closure 稳定 (`il_sha256: 54f8e2a1...` family).
> **目标**: 把 v1.6.0 changelog "Known uncovered" 留的 5 个候选 + ACTIVE workaround 补完, 让 v2.x (QBE 重写) + v3.x (`&mut` lifetime + `no_std` + inline asm) 启动时不再被这些底层 gap 阻塞.

> **本文件性质**: **umbrella 总览** (stage 拆解 + 依赖 + ship 顺序). 各 stage 独立 plan 文件见下表 — 每个 stage 启动时单独调出对应 plan 文件执行, 不要把 5 stage 一次性 ship.

## Ship 模式 (跟 v1.5 / v1.6 同型)

- **每 stage 独立 commit** (1 commit per stage, 跟 W-052 / W-053 / W-054 ship pattern)
- **每 stage commit message**:`<type>(v1.7.0 stage N): <summary> (parity src + src0)` (Stage 1 不需要 src0 parity, 因 regress.py 改)
- **每 stage umbrella 部分**:`docs/logs/v1/changelog-v1.7.0.md` 后续追加 (per `feedback_changelog_umbrella.md`, 1 个 umbrella, 不分 standalone)
- **每 stage 验证 gates**:
  - 5/5 PASS on target test per `feedback_fix_evaluation_rule`
  - `jhyy_selfhost_check all_byte_equal=true` (Stage 2-4 mandatory; Stage 1 因零语义改影响小但也跑; Stage 5 因只动 lexer 也跑)
  - regress `--all` baseline 不跌
- **每 stage 工作流** (per v1.5 / v1.6 ship 经验):
  1. 读对应 stage plan 文件
  2. 跑 task list (TaskCreate / TaskUpdate)
  3. 实施 + commit
  4. 验证 + 标 task completed
  5. **pause**, 询问 user 是否继续下一 stage (per "分多步走不着急" 决策)
