### 4.1 `null` 关键字

```
// 现在:   let p = 0 as *u8;
// 之后:   let p = null;
```

src0/ 里 `0 as *u8` / `0 as *Node` / `0 as *Sym` 几百处。sema 从上下文推断 null 的目标类型 (跟 `0 as *T` 一样路径).

| 端 | 改动 |
|----|------|
| lexer | 1 个新 token `null` |
| parser | null → NODE_INT_LIT(0) + type_ptr=NULL (sem 阶段 infer) |
| sema | null 遇到 `*T` 上下文 → 自动 fill type_ptr |
| codegen | 不变 (NODE_INT_LIT 路径已有) |

**估时**: 0.5 sprint.

### 4.2 `else if` 语法糖

```
// 现在:
if a { ... } else { if b { ... } else { ... } }

// 之后:
if a { ... } else if b { ... } else { ... }
```

纯 parser sugar — `else if` desugar 成 `else { if ... }`。不碰 sema/codegen.

| 端 | 改动 |
|----|------|
| parser | TOKEN_ELSE 后遇到 TOKEN_IF → 不要求 `{`, 直接开新 if parse |

**估时**: 0.5 sprint.

### 4.3 `sizeof` 内建函数

```
// 现在:   let size = 72 as i64;  // CGCONTEXT_SIZE — 手算, 易错
// 之后:   let size = sizeof(CGContext);
```

**这就是 VariantDesc heap overflow 的根因** — VARIANT_DESC_SIZE 手写 16 时已是错的 (真值是 24). 编译器知道所有类型的 size/layout, 只是没暴露给用户.

| 端 | 改动 |
|----|------|
| parser | `sizeof(TypeName)` → NODE_SIZEOF |
| sema | sema 阶段求值 → 替换成 NODE_INT_LIT |
| codegen | 不变 |

**scope**: 只支持 type name (struct/enum/primitive), 不支持表达式 (`sizeof(*ptr)` 不需要). 用已存在的 `type_size(*Type) -> i64` 函数.

**估时**: 1 sprint.

### 4.4 `#[inline]` attribute

```jhyy
// 现在:   小 helper 函数有 call overhead
// 之后:
#[inline]
fn qbe_type_of(t: *Type) -> i32 { ... }
```

jhyy 无 forward ref, 小 helper 函数不能 inline → 只能手写代码重复 (parser match-expr 内联 92 行, cg_body_returns 必须定义在 cg_expr 之前). `#[inline]` 让 codegen 在 callsite 内联函数体, **变相解决一部分 forward ref 问题**.

| 端 | 改动 |
|----|------|
| parser | 识别 `#[inline]` attribute |
| AST | fn 节点加 `is_inline` flag |
| codegen | 对 `#[inline]` 函数不 emit call → 在 callsite 内联 emit 函数体 |
| 限制 | 不内联递归函数; inline 函数必须在使用前定义 (仍是 jhyy 限制) |

**估时**: 1-2 sprint.

### 4.5 `for x in slice`

```
// 现在:
let arr = [1, 2, 3];
let len_val = 3 as i64;
for i in 0..len_val {
    let x = arr[i];
    ...
}

// 之后:
for x in arr {
    ...
}
```

jhyy 已有 slice `[*]T` 的 ptr+len 内部结构. `for x in slice` desugar 到 index loop — sema 拿 slice 的 len, codegen emit 标准 for-loop. 不跟 v3.x `for x in iter` 冲突 (v3.x 走 iterator trait, 这个是 slice-specific sugar).

| 端 | 改动 |
|----|------|
| parser | `for IDENT in expr` 语法 |
| sema | 检查 expr type = `[*]T` → desugar 到 index loop |
| codegen | 同 NODE_FOR, 加自动 index + elem load |

**估时**: 1 sprint.

### 4.6 `defer` 语句

```
fn compile_file(path: *u8) -> i32 {
    let f = fopen(path, "rb");
    defer fclose(f);
    // ... 无论怎么 return, fclose 都会在函数退出时调用
}
```

src0/main.jhyy 里 `goto cleanup` 模式到处都是. Go 的 `defer` 是零成本的 cleanup 方案.

| 端 | 改动 |
|----|------|
| parser | `defer expr;` → NODE_DEFER(expr) |
| sema | 收集函数内所有 defer, 注册到 Func.defer_stack |
| codegen | 每条 return 前 emit defer stack (LIFO, 倒序执行) |

**scope**: 只支持 `defer fncall();`, 不支持 `defer { block }` (更复杂, 留给 v3.x).

**估时**: 1-2 sprint.
