## Context (2026-08-12 audit)

### 现状盘点

| 维度 | 当前 | 目标 |
|------|------|------|
| **生产路径** | `jhyy.exe` (C 端, 314KB) | `jhyy.exe` 物理 = jhyy-side 编译产物 (~412KB) |

| **CLAUDE.md 措辞** | "C 端生产路径, v1.x → v2.x 渐进迁移" | "v1.x = jhyy-side production, C 端 stage-0 bootstrap" |

### 阻塞问题:硬编码路径

`compiler/src/main.c` 和 `compiler/src0/main.jhyy` 把 `QBE` / `gcc` / `runtime.c` / `jhyy_helpers.c` 路径写死成用户目录:

```
compiler/src/main.c:433    "C:/Users/liuzhen/Desktop/coding/JiHuiYiYou/qbe/qbe.exe ..."
compiler/src/main.c:445    "C:/msys64/ucrt64/bin/gcc.exe ... runtime.c ... jhyy_helpers.c ..."
compiler/src0/main.jhyy:64 fn QBE_PATH() -> ... C:/Users/liuzhen/Desktop/coding/JiHuiYiYou/qbe/qbe.exe
compiler/src0/main.jhyy:65 fn GCC_PATH() -> ... C:/msys64/ucrt64/bin/gcc.exe
compiler/src0/main.jhyy:66 fn RUNTIME_C() -> ... C:/Users/.../compiler/runtime/runtime.c
compiler/src0/main.jhyy:67 fn HELPERS_C() -> ... C:/Users/.../compiler/src0/jhyy_helpers.c
```

这条**两边都有**, 而且**字面值相同** —— main.jhyy 是 v0.8 commit 2a 翻译 main.c 时的"per v1.0.0 L1 § 134 决策"硬编码.

后果: 任何 clone 到非 `C:/Users/liuzhen/Desktop/coding/JiHuiYiYou` 路径的用户, jhyy.exe 直接 gcc link failed (跟 PowerShell gcc link failed 不是一回事 —— 这是绝对路径找不到 runtime.c).

### 联动关系

- **main.c ↔ main.jhyy 路径**: 必须同步改 + byte-equal 守门
- **C 端 → stage 0**: gcc build chain 只在 CI/bootstrap 时跑, 用户本地不用
- **regress.py ↔ regress_v1.py**: 双跑, 任一退化 → 回滚该 sprint
- **DWARF ↔ gdb pretty printer**: codegen.jhyy 加 debug emit + 单独 .gdbinit 文件

### 不在 v1.4.0 scope

- v2.x QBE 自写 + 多目标 (parallel axis, v1.4 ship 后才启动)
- v3.x 语言扩展 (parallel axis)
- v1.5 installer (v1.4 ship 后才启动)
- 跨平台 (Linux / macOS) — 仍是 Windows-only

## Risks / 守门

| 风险 | Mitigation |
|------|------------|
| argv[0] 在 `system()` 调用时丢失 (cmd.exe 不传 argv[0]) | main.c 启动时把项目根存全局, system() 用全局; 或 cmd.exe 调用用 `%1` 传 |
| jhyy-side 编 src0/main.jhyy 性能慢 2-5x (gdb pretty printer test 跑通但开发者本地 build 慢) | DWARF 默认关 (`--debug` opt-in flag), 生产 build 不带 debug |
| mcp-jhyy 11 tools 路径不变但内容变 → 可能某些 tool 假设 C-side 行为 | 跑 `pytest mcp-jhyy/tests/` (14 smoke test) 守门; 任一 FAIL → 修该 tool |
| regress_stage0.py 加进 CI 增加 build time (~3-5 min) | 可 cache stage 0 binary (只在 src/ 改时重 build) |
| `.gdbinit` 仓库根可能跟用户个人 `.gdbinit` 冲突 | 仓库 `.gdbinit` 只做 auto-source, 不覆盖用户配置 (不用 `set print ...` 等) |
| CLAUDE.md 措辞改了之后其他 plan 文件措辞滞后 (e.g. v1.3.0 写的"v2.x 渐进迁移") | 本 plan ship 后下一个 plan author 各自查措辞, 不在本 plan scope |
| jhyy.exe 物理替换后 v1.0.0 byte-equal 历史 baseline 仍记录 jhyy_v1.exe.exe sha | 保留 v1.0.0 baseline (jhyy_v1.exe.exe) 作历史, 新 baseline 改 jhyy.exe.exe (在 v1.4.5 阶段定) |

#### 1.2 Helper: `cg_mod_global_register` + `cg_mod_global_find`

```c
/* Append a module-level global. Returns the registered CGModGlobal*. */
static CGModGlobal *cg_mod_global_register(CGContext *cg, Sym *sym,
                                           const char *qbe_name, char qbe_type) {
    if (cg->n_mod_globals >= cg->cap_mod_globals) {
        size_t new_cap = cg->cap_mod_globals ? cg->cap_mod_globals * 2 : 16;
        CGModGlobal *ng = arena_alloc(cg->arena, new_cap * sizeof(CGModGlobal));
        if (cg->mod_globals && cg->n_mod_globals > 0)
            memcpy(ng, cg->mod_globals, cg->n_mod_globals * sizeof(CGModGlobal));
        cg->mod_globals = ng;
        cg->cap_mod_globals = new_cap;
    }
    CGModGlobal *g = &cg->mod_globals[cg->n_mod_globals++];
    g->sym = sym;
    size_t len = strlen(qbe_name) + 1;
    char *cn = arena_alloc(cg->arena, len);
    memcpy(cn, qbe_name, len);
    g->qbe_name = cn;
    g->qbe_type = qbe_type;
    return g;
}

static CGModGlobal *cg_mod_global_find(CGContext *cg, Sym *sym) {
    for (size_t i = 0; i < cg->n_mod_globals; i++) {
        if (cg->mod_globals[i].sym == sym) return &cg->mod_globals[i];
    }
    return NULL;
}
```

### 子任务 2: W-019 真修 — 嵌套 struct field chain

#### 2.1 根因 (确诊)

`compiler/src/codegen.c:1613-1687` `case NODE_FIELD` "For struct value field access" 分支 (line 1662 起):

```c
IRVal base = {0};
cg_expr(cg, d->expr, &base);     /* 递归拿 base value */
/* 假设 base 是 address — buggy for nested chain */
```

当 `d->expr` 本身是 `NODE_FIELD` (e.g. `outer.inner`), `cg_expr(d->expr, &base)` 递归调用, 内部也走 NODE_FIELD 路径, 拿到的是**已经 load 出的 inner value** (一个 IRVal, 类型 = 'l' 但语义是 inner struct 的 value, 不是地址)。

随后 caller 把这个 value 当 address 用, `add offset` 拿到的地址偏移是相对 value 的高字节, 而 value 已经在寄存器里 → `loadsw` 拿到错字节 → "invalid type for first operand %t2 in loadsw"。

#### 2.2 修法: 3 步 chain + `cg_alloc_temp_slot` helper

新逻辑:
```
base = cg_expr(d->expr);             /* step 1: 拿 .expr 的 value */
if base 来自 value-of chain:
    slot = cg_alloc_temp_slot(base, size_of_type(d->expr.type));
    addr = slot;                     /* slot 是真 address */
else:
    addr = base;                     /* base 已经是 address */
addr += offset_of(field);            /* step 2: 加 field offset */
result = load(addr);                 /* step 3: load field value */
```

```c
/* Allocate a temporary stack slot, store `value` into it, return the slot
   address as an IRVal (kind=IRVAL_TEMP, type='l'). Used for nested struct
   field chain where intermediate values are not addresses. */
static IRVal cg_alloc_temp_slot(CGContext *cg, IRVal value, int size) {
    if (size < 4) size = 4;
    IRVal slot = ir_new_tmp(cg->ir, 'l');
    ir_emit_alloc(cg->ir, slot, size);
    cg_emit_store(cg, NULL, value, slot);
    return slot;
}
```

#### 2.3 改 `cg_expr NODE_FIELD` (line 1662-1687 重构)

```c
/* v1.4.6: W-019 真修 — 嵌套 struct field chain 区分 address-of vs value-of.
   If d->expr is itself a NODE_FIELD / NODE_INDEX (复合地址路径), the
   recursively-evaluated value is a value, not an address — allocate a
   temp slot to materialize the address. */
int base_is_value = (d->expr->kind == NODE_FIELD ||
                     d->expr->kind == NODE_INDEX);
IRVal base = {0};
cg_expr(cg, d->expr, &base);
Type *st = expr_type;
if (!st || st->kind != KIND_STRUCT) {
    *out = (IRVal){0}; return;
}
size_t offset = 0;
Type *field_type = NULL;
for (size_t i = 0; i < st->struct_type.nfields; i++) {
    if (strcmp(st->struct_type.fields[i].name->name, d->field) == 0) {
        offset = st->struct_type.fields[i].offset;
        field_type = st->struct_type.fields[i].type;
        break;
    }
}
IRVal addr;
if (base_is_value) {
    /* v1.4.6: W-019 真修 — allocate temp slot for nested field value */
    addr = cg_alloc_temp_slot(cg, base, (int)type_size(st));
    if (offset > 0) {
        IRVal adj = ir_new_tmp(cg->ir, 'l');
        ir_emit_binary(cg->ir, adj, "add", addr, ir_new_int((int64_t)offset));
        addr = adj;
    }
} else if (offset > 0) {
    addr = ir_new_tmp(cg->ir, 'l');
    ir_emit_binary(cg->ir, addr, "add", base, ir_new_int((int64_t)offset));
} else {
    addr = base;
}
IRVal result = ir_new_tmp(cg->ir, field_type ? qbe_type_of(field_type) : 'w');
cg_emit_load(cg, result, field_type, addr);
*out = result; return;
```

### 失败回滚

如果 Stage 1 byte-equal 失守 (mirror 字节差):
- 检查 CGCONTEXT_SIZE 是否同步刷新
- 检查 helper fn IR emit 字节是否同步 (用 `jhyy_il_diff` 首差异定位)
- 必要时 revert codegen.jhyy 改动, 先 ship codegen.c 单边 (Stage 1 byte-equal 临时失守, 但 Stage 2 closure 仍跑; v1.4.6 拆 2 commits)

如果 regress 退化:
- 跑 `jhyy_get_il` 看退化用例 .il
- 对比改前 .il (git stash + checkout pre-v1.4.6 commit)
- 定位 codegen 改动引入的 IR 差, revert 该 helper

如果 Stage 2 closure 失守 (v2/v3/v4 .il 不一致):
- 极不可能 (mirror 性质 + 改动只 emit 同一段 IR)
- 如果发生, revert + 拆 sprint
