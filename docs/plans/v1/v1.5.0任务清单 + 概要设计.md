# v1.5.0 任务清单 + 概要设计: Windows 引导式安装器 (WiX + Burn + MSI)

> **承接**: v1.4.0 shipped (src0 production flip — jhyy.exe 物理 = jhyy-side, 路径硬编码消除).
> **当前 baseline**: regress 53/53 (3 library skipped) + Stage 1 byte-equal (per `feedback_il_byte_equal`) + Stage 2 N=4 byte-equal (v1=v2=v3=v4 .il sha 一致, per MCP `jhyy_selfhost_check`) + clone 到任意路径可跑.
> **校准 2026-08-15**: regress 50/50 → 53/53 (v1.4.6 加 top_level_let_mut_test + gdb_pretty_test), Stage 2 N=3 → N=4 (MCP 跑 v1→v2→v3→v4, 不止 v1→v2→v3). Stage 1 byte-equal 7/7 是 v1.4.0 era 措辞, 数字实际由 `mcp-jhyy/jhyy_il_diff` 现数, 不再硬编.
> **目标**: 用户能下载一个 `jhyy-installer-x.y.z.exe`, "next-next-finish" 装好 jhyy (含 qbe.exe + binutils), 系统 PATH 自动配好, `.vscode` 不用配, 默认下 VSCode 也能直接 `jhyy run hello.jhyy`.
> **复用**: Burn bundle 结构为 jhyy_OS 后续安装器预留 (一处 bundle, 多个 MSI chain).
> **本次补排原因**: 之前 v1.x 计划没考虑"如何发给用户", 当前只靠 git clone + bootstrap.cmd. v1.4 切 src0 生产路径后, installer 包内容明确 (jhyy-side 产物), 此时做 installer 顺水推舟. 同时把"jhyy_OS 安装器"复用结构定下来, 避免 OS 那边再重新设计.

## Context (2026-08-12 audit)

> **路径概念澄清** (v1.4 ↔ v1.5): v1.4.1 "装到任意路径" 指 **开发时 clone 路径无关** (`D:\test\jhyy\` 也能跑 hello.jhyy);v1.5 installer 装到 **标准安装路径** `C:\Program Files\JHYY\` (MSI 默认)。两个概念不冲突 — 开发路径消除硬编码是 v1.4.1 的事,标准安装路径是 v1.5 installer 默认配置。

### Bundle 内容 + 体积估算

| 文件 | 来源 | 体积估 |
|------|------|--------|
| `jhyy.exe` (jhyy-side, 含 DWARF) | `compiler/build/bin/jhyy.exe` (per v1.4.0 flip) | ~412KB |
| `qbe.exe` (vendored) | `qbe/qbe.exe` | ~几百 KB |
| binutils 子集 (as.exe / ld.exe / cc1.exe / collect2.exe) | MSYS2 `ucrt64/bin/` | ~30MB |
| `LICENSE` | 仓库 | ~几 KB |
| `vscode-ext/jhyy-*.vsix` | `vscode-ext/` 打包 | ~几 KB |
| 文档 / examples (可选) | `docs/` + `compiler/tests/examples/` | ~几 MB |
| **MSI 自带** | WiX 工具链 + metadata | ~几 MB |
| **总计** | | **~35MB** |

> **体积优化选项** (决策点 § 决策-3):
> - 选项 A: 完整 bundle (~35MB) — 零依赖, 用户装完就能用
> - 选项 B: 仅编译器 (~几 MB) — 用户自己装 MSYS2
> - 选项 C: 编译器 + QBE + stdlib (无 binutils) (~5MB) — 用户配 MSYS2 PATH
>
> **推荐 A** — "next-next-finish" 承诺, 用户不用任何额外步骤.

## Risks / 守门

| 风险 | Mitigation |
|------|------------|
| WiX 4 .NET-based 在 Windows Server 兼容性 | WiX 4 文档说支持 Win10 1809+, 本项目 Win10 19045 验证 |
| `dotnet tool install --global wix` 没持久化 PATH | 跑 source ~/.bashrc / 或者 .cmd 脚本自己加 |
| 系统 PATH 写入 HKLM 需要 admin | UAC prompt 显示 (Burn UI 默认), 文档说明 |
| binutils 30MB 让 installer 太大 | (决策点承认) 用户面向开发者, 35MB 可接受 |
| VSCode ext 检测 `code` 命令失败 | component 用 `Condition` 跳过, 不 block 整体安装 |
| 卸载时 PATH 没清除 | Burn 默认 `Persist="no"` 清 PATH, 写 uninstall 验证 |
| `code --install-extension` 后用户之前有 jhyy ext 冲突 | 先 uninstall 旧版, 再 install 新版 |
| Burn bundle 装到 D: 盘用户的 Program Files 路径 | 给默认 `C:\Program Files\JHYY`, 让用户改 |
| WiX 4 .wxs 语法记错 | WiX 4 docs + WiX 4 extension 编译器自带 verification |
| GH Actions 跑 WiX 4 时间 (5-10 min) | cache `~/.wix` + cache `MSYS2 ucrt64/bin` (binutils 提取) |
| 用户装完 jhyy.exe 在 PATH 但 MSYS2 bin 也被装到 JHYY\bin 会不会跟其他项目冲突 | binutils 装到 `JHYY\bin\as.exe` etc, 命名空间隔离 |
| jhyy.exe 内容升级 (v1.5.0 → v1.5.1) installer 怎么跟着 | GH Actions release workflow 自动 build + 上传 (per v1.5.5) |
| installer 验证 — 装到干净 Windows VM 测 | 写 `installer/Vagrantfile` + `installer/test-smoke.ps1` (v1.5.5 末) |
| jhyy_OS 后续 sprint 改 installer/os/ 路径结构 | 决策点承认 — v1.5 写 stub, OS 端 sprint 设计后定结构 |

## 决策点 (跟 user 对齐)

| 决策 | 选项 | 推荐 |
|------|------|------|
| **WiX 4 vs WiX 3** | (a) WiX 4 (.NET-based, dotnet tool) / (b) WiX 3 (C#/.NET-Framework) | **(a)** — 你 .NET 已装, 维护活跃, 新项目推荐 |
| **Bundle 体积 (35MB)** | (a) 完整 bundle (jhyy + qbe + binutils) / (b) 仅编译器 / (c) 编译器 + QBE | **(a)** — "next-next-finish" 承诺, 零依赖 |
| **VSCode ext 是否打包** | (a) 装 (if `code` 在 PATH) / (b) 不装, 文档告诉用户装 | **(a)** — 引导式体验完整 |
| **`.jhyy` 文件关联** | (a) 关联 VSCode / (b) 关联 jhyy.exe / (c) 不关联 | **(a)** — 跟 VSCode ext 配套, 关系清晰 |
| **PATH 注册位置** | (a) HKLM 系统 PATH (要 admin) / (b) HKCU 用户 PATH (无 admin) | **(a)** — 提供系统级安装, 多人用同一机器方便 |
| **代码签名** | (a) v1.5 ship 时不加 / (b) v1.5.5 加 Authenticode / (c) v2.x 加 | **(a)** — v1.5 ship 时手头没有 HSM / EV cert, 文档说明 "unknown publisher" warning |
| **GH Actions 何时跑** | (a) tag 触发 / (b) 手动 workflow_dispatch / (c) 都不 (manual upload) | **(a)** — semi-automated, 但 留 manual workflow_dispatch 作 escape hatch |
| **installer 验证 VM** | (a) GitHub Actions Windows runner 装 + 测 / (b) Vagrant + VirtualBox / (c) 手动开发者机 | **(a)** — CI 内闭环, 不用本地 VM |
| **jhyy-side 编译时 actual binary** | (a) 用 v1.4.0 ship 时的 jhyy.exe / (b) 每次 build installer 重新编 jhyy.exe (from src0) | **(b)** — installer 总是带 latest jhyy-side 产物, 避免 stale binary |
| **jhyy_OS placeholder 写法** | (a) `installer/os/.gitkeep` + README / (b) 写完整 stub MSI / (c) 不占位, OS 那边自带 installer | **(a)** — 后续 OS sprint 决定, 留目录 + 文档即可 |
| **chocolatey / scoop / winget manifest** | (a) v1.5 ship 时不加 / (b) v1.5.5 加 manifest (no actual publish) / (c) v2.x publish | **(b)** — 写 manifest, 实际 publish 推到 v2.x (你自有仓库不会立即被社区采纳) |
| **离线安装 vs 在线安装** | (a) 离线 (无外部下载) / (b) 在线 (下 .NET Runtime if needed) | **(a)** — jhyy.exe + qbe.exe + binutils 全部打包, 无外部依赖 |
| **Start Menu 快捷方式** | (a) 加文档 / 快速开始 / 设置链接 / (b) 只多加一个 GitHub 链接 / (c) 不加 | **(a)** — 详细 launcher, 帮助用户上手 |
| **升级 vs 卸载重装** | (a) Major.Minor 升级保留配置 / (b) 每次升级 = 卸载 + 装 | **(a)** — Burn standard upgrade behavior, 配置文件保留 |
