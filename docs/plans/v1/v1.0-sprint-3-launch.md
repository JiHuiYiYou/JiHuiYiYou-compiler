## Task #1: parser.jhyy NODE_CONST_DECL 翻译 (~150 行)

**目标**: parser.jhyy 翻译 NODE_CONST_DECL node, 让 jhyy_v1 编 const_array.jhyy / const_struct_array.jhyy 等顶层 const 声明能跑通 → stage1 byte-equal 从 6/7 → 7/7。

**事实依据**:
- per v0.9 wip commit 2.7 changelog: "B-data 根因重诊断 — parser CERR (顶层 const 拒绝), 不是 codegen gap → 推迟 v1.0.0 sprint 3 (Task #52)"
- 6/7 byte-equal fail 是 const_array.jhyy (跟 const_struct_array.jhyy); parser 不识别 NODE_CONST_DECL → sema 拒绝 → codegen 不跑

**做法**:
1. 读 `compiler/src/parser.c` 找 NODE_CONST_DECL 的 parse path (~80 行 C)
2. 翻译到 `compiler/src0/parser.jhyy` (跟现有 parse_decl / parse_stmt / parse_expr 同 pattern)
3. 验证 `jhyy_v1 compile const_array.jhyy` 不报 parse error
4. 跑 stage1 byte-equal → 7/7 PASS

**风险**:
- parser.jhyy 已经 3000+ 行 (per v1.0 sprint 3 commit 2.12b Stage 0 closure scan), NODE_CONST_DECL 翻译可能引发未知 codegen gap
- 跟 stage1 byte-equal 7/7 闭环强绑定 — 不达成, sprint 3 不算 ship

**完成定义**:
- parser.jhyy 翻译 NODE_CONST_DECL, 不影响现有翻译 (parse_decl / parse_stmt / parse_expr)
- `jhyy_v1 compile const_array.jhyy` 通过 → stage1 byte-equal 7/7 PASS
- regress 持平 baseline 50/53 (v0) + jhyy_v1 regress 持平 12/47 (略升可接受)
- 1 commit ship-able

## Task #2 (∥ #1): resolve_imports 翻译 (~250 行)

**目标**: 把 `compiler/src/main.c:241-330` (resolve_imports 90 行) + `L101-L239` (resolve_one_import helper 139 行) 翻译到 `compiler/src0/main.jhyy`, 替代 inline_imports workaround → jhyy_v1 真多文件编译。

**事实依据**:
- per v0.9 wip commit 2.5 changelog § "下一步": "B (sprint 3 B'): main.jhyy 收尾 (resolve_imports 翻译 ~300 行)"
- inline_imports workaround (commit 2.7) 是字符串拼接, 没法走真多文件 import 路径
- v0 jhyy.exe 当前 main.c 有完整 resolve_imports (90 行 + 139 行 helper), jhyy 端要补齐才能真多文件

**做法**:
1. 翻译 `resolve_imports` (90 行) 到 main.jhyy — 操作 Node AST + arena + 文件 IO
2. 翻译 `resolve_one_import` (139 行 helper, 递归) 到 main.jhyy — 循环检测 + 传递性 import
3. 替代 inline_imports workaround (删 src0/main.jhyy L120-L300 段拼接代码)
4. 验证 `jhyy_v1 compile namespace_dup.jhyy` (用 import 的测试) 通过

**风险**:
- resolve_imports 不用 SymTable (per 2026-08-05 audit Q&A), 但读 `(*id).sym->name` (L294) 走单 Sym.name 字段访问
- main.c 文件 IO (read_file / calloc) 走 jhyy_helpers FFI
- 替代 inline_imports 是大改, 需谨慎 revert 备份

**完成定义**:
- main.jhyy 加 resolve_imports + resolve_one_import (~250 行)
- inline_imports workaround 段删除
- `jhyy_v1 compile namespace_dup.jhyy` 通过
- regress 持平 baseline 50/53 + jhyy_v1 regress 持平 12/47
- 1 commit ship-able (per Task #52 平行 ship)

## Task #3: B' / Task #61 — jhyy_v1 编 src0/main.jhyy 真闭环 (~100 行)

**目标**: 让 jhyy_v1 编 src0/main.jhyy 跑通, 产出 jhyy_v2.exe (不再是 segfault, 10/10 → 0/10)。

**事实依据**:
- per v0.9 wip commit 2.14 changelog § "下一步": "Task #61: jhyy_v1 编 src0/main.jhyy 跑通 (sema + codegen 全路径)"
- 当前 jhyy_v1 编 src0/main.jhyy 在 PARSE 阶段 segfault (per commit 2.14 W-004 BLOCKED verification)
- post-Task #60 (commit 2.15) parse 阶段 ✅, 但 sema / codegen 阶段 segfault pre-existing

**做法**:
1. 跑 `jhyy_v1 compile src0/main.jhyy -o jhyy_v2`, 观察 segfault 点 (parse/sema/codegen 哪阶段)
2. bisect 找根因 (类似 v0.8 wip commit 6 bisect heap corruption pattern)
3. 修根因 (per memory `feedback_self_edit_authority`: 1 commit 真修 ship-able)
4. 验证 `jhyy_v2 compile hello.jhyy` 通过 (跟 jhyy_v1 编 hello.jhyy 一致)
5. 验证 `jhyy_v2 regress` (用 JHYY_CC env var, per v0.9 wip commit 4 plan) 持平 baseline

**风险**:
- bisect 根因不可控 (per commit 6 经验)
- 修根因可能 cascade 多个 W 系列 workaround 二次触发 (per `feedback_codegen_workaround_linkage`)
- main.jhyy 25KB 大文件 (per v0.9 wip commit 4 plan), codegen 阶段输出大

**完成定义**:
- jhyy_v2 编出 (jhyy_v1 编 src0/main.jhyy 不再 segfault)
- jhyy_v2 编 hello.jhyy 通过 (跟 jhyy_v1 编 hello.jhyy 行为一致)
- regress JHYY_CC=jhyy_v2 持平 baseline 50/53 (跟 jhyy.exe 编的 regress 结果一致)
- 1 commit ship-able (或多 commit, per bisect 复杂度)

## Task #4: W-004 verification → commit 2.19 (~80 行)

**目标**: jhyy_v1 编 codegen/parser/sema.jhyy 不 stack overflow → W-004 失效条件 (i) 实证 → W-004 标 RESOLVED OR 触发批量改名。

**事实依据**:
- per memory `feedback_w004_verification_blocked.md`: "W-004 verification path ... blocked by Task #60, NOT W-004 itself"
- post-Task #60 (commit 2.15) + post-Task #61 (Task #3) → W-004 实证路径解锁
- per memory `feedback_codegen_workaround_linkage`: W-004 跟 W-001/W-002 联动

**做法**:
1. 跑 `jhyy_v1 compile src0/codegen.jhyy -o tmp_codegen`, 看是否 stack overflow (W-004 触发)
2. 同 `src0/parser.jhyy` + `src0/sema.jhyy` (Task #60 修后 parse 阶段过)
3. **不触发** → W-004 标 RESOLVED, commit 2.19 doc-only
4. **触发** → 走 v0.9 wip commit 2.15 changelog § "下一步" 表的 "commit 2.15 (W-004 RESOLVED 段 OR 批量改名)" 路径:
   - 方案 A (优先): src0/codegen.jhyy / parser.jhyy / sema.jhyy 内 1-char 局部变量批量改名 → 9+ char (避免 FNV-1a hash 碰撞触发 stack-spill bug)
   - 方案 B (备选): codegen stack-slot allocator 真修 (高风险, 推迟 v2.x)

**风险**:
- 方案 A 批量改名可能 100+ 处 (per `project_bootstrap_closure_state.md` 经验), 改完需全 regress 重测
- 方案 B 真修可能引入新 codegen bug (per `feedback_v0_codegen_bug_workarounds.md`)

**完成定义**:
- W-004 失效条件 (i) 实证完成
- 不触发 → W-004 标 RESOLVED, doc-only commit
- 触发 → 方案 A 批量改名 ship, codegen.jhyy / parser.jhyy / sema.jhyy 内 1-char → 9+ char
- regress 持平 baseline 50/53 + stage1 持平 6/7 (或 7/7 post Task #52)
- 1 commit ship-able

## Task #5: D — N=3 byte-equal (~30 行)

**目标**: Stage 2 真闭环 = jhyy_1 → jhyy_2 → jhyy_3 三代自举, 产 .il byte-equal。

**事实依据**:
- per v0.9 wip commit 2.14 changelog § "下一步": "D: N=3 byte-equal (在 6/7 层面)"
- per v1.0.0 详细实现方案 § 5.3: "jhyy_1 编 src0/main.jhyy 得 jhyy_2; diff jhyy_2.il jhyy_3.il byte-equal (N=3 fixed point 验证)"
- 当前 jhyy_2 还无法编 (Task #3 卡), post-Task #3 才能开

**做法**:
1. 跑 `jhyy_v1 compile src0/main.jhyy -o jhyy_v2` (post-Task #3 完成)
2. 跑 `jhyy_v2 compile src0/main.jhyy -o jhyy_v3`
3. 跑 `jhyy_v3 compile src0/main.jhyy -o jhyy_v4`
4. diff jhyy_v3 编的 .il vs jhyy_v4 编的 .il → byte-equal (N=3 fixed point)
5. 验证 jhyy_v4 regress (JHYY_CC=jhyy_v4) 持平 baseline

**风险**:
- jhyy_v2 / jhyy_v3 / jhyy_v4 是 stack of self-hosted compilers, 任何 codegen 路径非确定性 (per C' audit, 0 risk) 都会放大
- main.jhyy 25KB 大文件, 多次编译慢 (per v0.9 wip commit 4 plan: 5-10 分钟)

**完成定义**:
- jhyy_v2 / jhyy_v3 / jhyy_v4 全部生成成功 (无 segfault)
- jhyy_v3 vs jhyy_v4 对相同 .jhyy 测试集产 byte-equal .il (Stage 2 closure)
- jhyy_v4 regress 持平 baseline 50/53
- N → ∞ 留给 v2.x (per v1.0.0 详细实现方案 § 5.4)
- 1 commit ship-able (验证脚本 + 文档)

## 不在 v1.0 sprint 3 范围

| 项 | 推到 | 理由 |
|----|------|------|
| jhyy 编译自己优化 | v2.x 末 | sprint 3 目标 = 闭环达成, 不优化 |
| N → ∞ (≥4 代) fixed point | v2.x | v1.0 sprint 3 只 N=3, 完整 N 验证 v2.x |
| W-007 (cg_convert_arg struct field + global var path) 真修 | v2.x 或单独 sprint | partial ACTIVE, 翻译路径用 workaround 绕 |
| W-006 (1-char local var stack spill) 真修 | v2.x (codegen stack-slot allocator) | dormant 状态 (per commit 2.14 scan), 无活跃触发面 |
| v0 codegen bug 1/2/3/4 (LEA / phi / loadub / &local) 真修 | v1.0 sprint 5 收尾或 v2.x | workaround 在 jhyy 源码里, 不阻闭环 |
| 嵌套 const array / const pointer / const slice / const enum array | v3.x+ | 自举不需要 |
| const fn / 编译期求值 | v3.x+ | 自举不需要 |
| `&mut + lifetime` / `Cap<T>` / 泛型 / 闭包 / std lib | v3.x | 跟 OS M11 硬前置联动 |
