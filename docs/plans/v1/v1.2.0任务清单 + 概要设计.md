### Sprint 详细

#### v1.2.1 — W-005 `let mut x_v1` style revert

**目标**: 把所有 `let mut size_v1` / `let mut i_v1` / `let mut idx_v1` 等风格的 `let mut` 改回自然 jhyy `let mut size` / `let mut i` / `let mut idx`。

**Why this matters**: W-005 #2 真修 (Sprint 4.25 commit 2.81) 后,cg_expr 不再 emit sentinel IRVal,`let mut x = cg_expr()` 模式已正确。`x_v1` 后缀是历史 stale-name 防御,现已无触发面。

**Scope** (audit 2026-08-12):
- `compiler/src0/main.jhyy`: ~7 处 (`let mut idx_v1`, `let mut i_v2`, `let mut i_v3`, `let mut k`, `let mut last_sep_off`, ...)
- `compiler/src0/codegen.jhyy`: ~5 处 (`let mut src_off`, `let mut dst_off`, `let mut all_term`, `let mut is_array`, `let mut is_struct`, `let mut is_sret`, `let mut ret_slot`, ...)
- `compiler/src0/arena.jhyy`: 1 处 (`let mut size_v1`)
- `compiler/src0/_driver_*.jhyy`: ~3 处 (测试驱动)

**实施步骤**:
1. 备份当前 jhyy_v1.exe.exe sha + .il sha
2. `grep -rn 'let mut [a-z_]\+_v[0-9]\+\b' compiler/src0/*.jhyy` 列全 16 处
3. 逐文件 revert (`let mut size_v1` → `let mut size`),保持 `_vN` 后缀在**非** `let mut` 位置(那些是 v1.2.3 的活)
4. 重新跑 jhyy_v1 build + regress_v1 + Stage 1 byte-equal
5. Stage 2 N=3 byte-equal: jhyy_v1 → v2 → v3 → v4 全 .il sha 比对

**风险**:
- 同名变量在不同 scope (e.g. 嵌套 loop) 需要保留 `_vN` — audit 时辨别
- codegen.jhyy 内部大量 `_v1` 是 W-005 #2 历史防御,W-005 真修后大多可去,**但** cg_body_returns/cg_match_pattern/cg_copy_struct 等关键函数要保守,5/5 PASS 触发面

**验证**:
- regress.py 50/53 PASS 持
- regress_v1.py 50/53 PASS 持
- Stage 1 byte-equal 7/7 持 (sha 不变 = 翻译层行为不变)
- Stage 2 N=3 byte-equal 持 (`2445e97d...`)
- 5 个 W-005 触发 .jhyy 测试各 5 轮 PASS (= 25/25)

**不动**:
- W-005 v0 C-side 真修 (Sprint 4.25 已 ship,committed)
- src0/codegen.jhyy 内部 helper 的 `_vN` (那些是 W-005 真修后的语义保留,v1.2.3 处理)

#### v1.2.2 — W-003 `let _ = fncall()` revert

**目标**: 把所有 `let _ = sema_init(...)` / `let _ = ir_emit_arg(...)` / `let _ = ir_emit_binary(...)` 等 call-result-ignored 模式改回**有名字的 binding**,W-003 真修 (v1.1.4 commit 1.4 已 ship docs) 后 jhyy-side 不再需要 `_` 丢弃模式。

**Why this matters**: `_` 模式在 jhyy 当前 parser 是合法 binding,但生成的 IR 等价于 `let _b = X` 的 store-and-immediately-drop。W-003 真修后,sema/codegen 不再 emit stale path,但**翻译层**应保留语义清晰。

**Scope** (audit 2026-08-12):
- `compiler/src0/_driver_sema.jhyy`: 1 处 (`let _x = sema_init(...)`)
- `compiler/src0/codegen.jhyy`: ~12 处 (`let _b`, `let _ld`, `let _lp`, `let _al`, `let _val`, ...)
- `compiler/src0/main.jhyy`: ~7 处
- `compiler/src0/_driver_*.jhyy`: ~4 处

**实施步骤**:
1. 全 `let _ = ` 列出来 (audit 是 24 处,跨 6 文件)
2. 给每个 `_` 起描述性名 (`_init`, `_load`, `_store`, `_emit`, `_disc`, ...)
3. 重新编译 src0/,确认 Stage 1 byte-equal 7/7 持
4. 跑 regress 双 50/50

**风险**:
- 命名冲突 (e.g. `_init` 跟现有变量重名) — audit 时辨别,必要时加 scope prefix
- 翻译层语义改变 — 必须 byte-equal 验证,不能 byte-different 但语义同

**验证**:
- Stage 1 byte-equal 7/7 持 (翻译层不应改变语义)
- regress 双 50/50 PASS 持

**不动**:
- parser / AST `_` binding 处理 (那是 v3.x 范畴)
- W-003 v0 C-side 真修 (Sprint v1.1.4 已 ship)
- codegen `_b` / `_ld` 等 `_x` 命名 — 起描述性名,但**不**改 codegen.jhyy 的局部命名约定

#### v1.2.3 — `_v1` 后缀 119 处 cross-file cleanup

**目标**: 清理所有 `_v1` 后缀 (标识符名以 `_v1` 结尾),这是 W-005 真修前历史 stale-name 防御的最大残留。

**Why this matters**: 119 处 _v1 是 src0/ 翻译产物"非自然"的最大单一来源。清理后 src0/ 接近自然 jhyy 代码风格,可读性 / 可审计性显著提升。

**Scope** (audit 2026-08-12):
- 跨所有 src0/*.jhyy 文件 (主要在 main.jhyy / codegen.jhyy / parser.jhyy / sema.jhyy / util.jhyy / ir.jhyy)
- `_v1` 命名模式 = `<descriptive_name>_v1`,e.g. `phi_v1`, `size_v1`, `ftype_slot_v1`, `sym_p_v1`, `idx_v1`

**实施步骤**:
1. `grep -rEhn '\b[a-z_]+_v1\b' compiler/src0/*.jhyy` 列出 119 处 (去重复后约 60 个 unique identifier)
2. 起新名字 (去掉 `_v1`,e.g. `phi_v1` → `phi` 或 `phi_tmp`)
3. **保守**原则: 同一 identifier 在不同 scope (e.g. `phi_v1` 在 cg_expr 和 cg_match_pattern) 是不同变量,可同名;但在**同一 scope** 是同一变量,起新名时考虑可见性
4. 重新 build jhyy_v1 + Stage 1 byte-equal 验证
5. 跑 Stage 2 N=3 byte-equal 验证

**风险**:
- cross-file rename 复杂度高 (一个 identifier 跨 5+ 文件)
- 命名冲突 (e.g. `phi` 是数学常用名,可能跟现有变量重名) — audit 时辨别
- byte-equal 短暂抖动 (新名字 emit 不同 symbol table hash,QBE label 改变) — 必须持续验证 sha `2445e97d...`

**验证**:
- Stage 1 byte-equal 7/7 持 (sha 不变)
- Stage 2 N=3 byte-equal 持 (`2445e97d...`)
- regress 双 50/50 PASS 持
- 工作树 src0/*.jhyy 100% 无 `_v1` 后缀 (grep 验证)

**不动**:
- `_v2` / `_v3` / `_v4` / `_v5` 后缀 (v1.2.4 处理)
- src0/codegen.jhyy 中**有意保留**的 `_v1` (W-005 真修后的语义保留,e.g. cg_match_pattern 内部的 `match_phi_v1`)
