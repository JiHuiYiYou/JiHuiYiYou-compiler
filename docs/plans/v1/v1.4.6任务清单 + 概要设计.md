# v1.4.6 任务清单 + 概要设计: 真修 W-017 + W-019 (codegen 收口)

> **承接**: v1.4.4 ship (jhyy.exe 物理 = jhyy-side 产物) — 物理 production flip 完成后, codegen 端 2 个 ACTIVE workaround 可以无外部 blocker 落地修。
> **当前**: 2 个 ACTIVE workaround (per [`docs/internal/workarounds.md`](../../internal/workarounds.md) § W-017 + W-019) 都跟 jhyy-side codegen 缺某段 IR emit 有关, C-side mirror 已正确 emit。fix 范围 = C-side codegen.c + jhyy-side codegen.jhyy 同步改, mirror 字节相同 (Stage 1 byte-equal 守门)。
> **本 plan 目标**: 让 jhyy-side codegen 跟 C-side 镜像对齐, 移除 2 个 workaround, 让 v1.x ship = "src0 production 真" (无任何 ACTIVE workaround 偷跑外部 C runtime 状态)。

## Context

### 现状盘点

| workaround | 引入 | 触发面 | 影响 |
|------------|------|--------|------|
| **W-017** | v1.4.1 | 任何顶层 `let mut g_x: T = expr;` | jhyy 端 codegen 完全丢弃 (cg_module pass A 只处理 NODE_CONST_DECL);后续 fn body 读 `g_x` 走 `cg_find_local` miss → emit `%t =l copy 0` 兜底, 运行时无 store, 全局状态失效。当前唯一受影响 = `jhyy_helpers.c` 委托的 path state |
| **W-019** | v1.4.3 | `(*outer_ptr).inner.field` 嵌套 struct 字段访问 | codegen `cg_field_addr` 在 chain `.inner.field` 时把外层 `.inner` 当 value-of 解 (递归 `cg_expr` 拿回一个 IRVal), 后续 `add offset` 当 address-of → QBE reject `loadsw` 类型错。`gdb_pretty_test.jhyy` 已避, lexer/parser/codegen.jhyy 不触发 |

### C-side 已正确实现的部分

per `compiler/src/codegen.c` audit (2026-08-14):

| 模式 | C-side codegen.c | jhyy-side codegen.jhyy |
|------|------------------|------------------------|
| Module-level `NODE_CONST_DECL` | ✅ `cg_module` pass A: `data $name = { ... }` | ✅ mirror |
| Module-level `NODE_FUNC_DECL` | ✅ `cg_module` pass B: `cg_func` 调 | ✅ mirror |
| Module-level `NODE_LET` (let / let mut) | ❌ 没 case (silent 丢弃 — C-side 也有此 bug!) | ❌ 没 case (silent 丢弃) |
| Top-level nested struct field chain | ❌ 没正确分支 (`cg_expr` NODE_FIELD 对 chain 不区分 address-of vs value-of) | ❌ mirror 同样 |
| Static global storage 路径 | ✅ `main.c` 有 `static char g_project_root[1024]` → emit 到 .data section | ❌ 缺 |

**关键观察**: 两个 workaround **都是 jhyy-side / C-side 都缺**, 不是 jhyy-side 单独缺。mirror 守门要求 = 字节相同 (Stage 1 byte-equal 7/7 维持), 但因为两端都缺, fix 时可以"双向同时加", 守门仍 7/7 (mirror 性质保留)。

### 子任务 1: W-017 真修 — 顶层 `let mut` emit `.data` section

| 步骤 | 工作 |
|------|------|
| **1.1 audit** | 读 `compiler/src/codegen.c` `cg_module` pass A (line ~2236) — 确认只 emit `NODE_CONST_DECL`, 不 emit `NODE_LET` |
| **1.2 设计** | 加 `NODE_LET` 分支:`let x: T = expr;` (immutable) → emit `data $name = { <const init> }` (跟 const decl 同形, 但 sym 走 module-level globals 表);`let mut x: T = expr;` → emit `.data $name` (mutable, 后续 fn body 写 `x` emit 真 store 到 `$name`)。需要 module-level globals dict (类似 CGContext.locals 但跨 fn lifetime) — 新增 `cg_mod_globals` Arena<Sym* → IRVal> (offset / $name 字符串), CGContext 加 `cg_globals *` 指针。`cg_find_local` 在 miss 时 fallthrough 到 `cg_globals` 查 |

| **1.4 codegen.jhyy mirror** | 同步改 3 处 (mirror 字节相同 — Stage 1 byte-equal 守门) |
| **1.5 新增测试** | `compiler/tests/examples/top_level_let_test.jhyy`:<br>`let mut counter: i32 = 0;`<br>`fn inc() -> i32 { counter = counter + 1; return counter; }`<br>`fn main_jhyy() -> i32 { let a = inc(); let b = inc(); return a + b; }` → `// EXPECT: 3` (a=1, b=2, 1+2=3) |
| **1.6 验证** | (a) `top_level_let_test.jhyy` compile + run → EXIT=3; (b) regress 50/50 PASS; (c) Stage 1 byte-equal 7/7; (d) Stage 2 N=3 byte-equal 维持 |

### 子任务 2: W-019 真修 — 嵌套 struct field chain 区分 address-of vs value-of

| 步骤 | 工作 |
|------|------|
| **2.1 audit** | 读 `compiler/src/codegen.c:1613-1687` `case NODE_FIELD` — 确认 `.inner` 当 value-of 处理 (递归 `cg_expr` 拿 `base` IRVal), 然后 `add offset` 当 address-of 用 → 类型错。根因: `(*o).inner` 中 `o` 是 `*Outer`, 所以 `cg_expr(*o)` 应该 emit deref `*Outer` 拿到 `Outer` value (16 字节 stack slot `base: l`), 然后 `.inner` 应该是 `*(base + offset)` 拿 `Inner` value (16 字节 stack slot `inner_slot: l`), 然后 `.a` 才是 `(inner_slot + a_offset) → loadsw a_addr`。当前代码把 `.inner` 当成单步 .field, 跳过了"内层字段也是 stack slot、需要再 deref 一层"这一步 |
| **2.2 设计** | `cg_expr NODE_FIELD` 拆三步: (a) 递归 `cg_expr(d->expr, &base)`; (b) 如果 `d->expr` 本身是 `NODE_FIELD` / `NODE_INDEX` / 任意"复合地址"路径, `base` 是 value (IRVAL_TEMP `l`), 不是 address — 需要 alloc 一个临时 slot, 把 `base` 存进去, 拿 slot 当 address; (c) `add offset` + `load` 拿 value。简化方案: 总是 alloc 临时 slot (即使 `.field` 直接 = struct slot) — 多一次 alloc + store, 但简洁且对称。当前 `cg_emit_store` 已经处理任意 value 类型 → 直接复用 |
| **2.3 codegen.c 实现** | 改 `case NODE_FIELD` (line 1613): 加 helper `cg_alloc_temp_slot(CGContext*, IRVal value, int size) -> IRVal addr` (alloc + store + return slot); 在"struct value field access"分支 (line 1662 起) 调 helper 拿到 `addr`, 后续 offset + load 同 |
| **2.4 codegen.jhyy mirror** | 同步改 |
| **2.5 新增测试** | `compiler/tests/examples/nested_struct_test.jhyy`:<br>`type Inner = struct { a: i32, b: i32 }`<br>`type Outer = struct { inner: Inner }`<br>`fn read_inner(o: *Outer) -> i32 { return (*o).inner.a + (*o).inner.b; }`<br>`fn main_jhyy() -> i32 { let i = Inner { a: 7, b: 8 }; let o = Outer { inner: i }; return read_inner(&o); }` → `// EXPECT: 15` (7+8) |
| **2.6 验证** | (a) `nested_struct_test.jhyy` compile + run → EXIT=15; (b) regress 50/50 PASS; (c) Stage 1 byte-equal 7/7 (mirror 字节相同 — 同一 helper 两端都用); (d) `gdb_pretty_test.jhyy` 加 nested-struct 用例 (单行 printf) 验证 pretty printer 也 cover nested |

## Risks / 守门

| 风险 | Mitigation |
|------|------------|
| Stage 1 byte-equal 失守 (mirror 字节差) | 两端同步改同一处, helper 名字 + IR emit 字节相同 — 写完后 `jhyy_il_diff` 立即查 |

| perf 退步 (>1.3x) | per `project_v1_0_perf_baseline.md` memory: 退步 >1.3x 需排查;W-019 fix 多一次 alloc + store 临时 slot, 大 struct chain 可能慢 ~10-20%; 跑 `compiler/src0/main.jhyy` build perf 对比 jhyy_v1.exe.exe vs 旧 binary |
| `cg_alloc_temp_slot` 多 alloc 致 stack slot 溢出 (MAX_LOCALS=1024) | per W-010 已 align jhyy-side 到 1024; nested struct field 链最深 ~5 层, 每层 1 slot = 5 slots, 远低于 1024 — 无风险 |
| 嵌套 enum 字段 (`(*o).payload.inner` enum payload 是 struct) 触发 W-019 之外的 bug | 本 plan 不修, 子任务 2.6 测试只覆盖 plain struct; 留 v1.4.7+ |

| 修 W-017 后 jhyy_v1 codegen emit 真 global store 改变 .il 字节, Stage 1 byte-equal 失守 | C-side 镜像 `cg_module` 也加 NODE_LET 分支, 两端 emit 同样 IR — Stage 1 byte-equal 仍 7/7 (mirror 性质保留) |
