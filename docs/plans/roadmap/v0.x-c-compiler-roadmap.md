## § 4 跟 v1.x / v2.x / v3.x 边界

| 轴 | 范围 | 跟 v0.x 关系 |
|----|------|--------------|
| **v0.x**(本 doc) | C 端编译器(已就绪) | 基础 |
| **v1.x** | jhyy 端编译器自举(进行中) | v0.x 是"参考实现" + 编译自验证的 host |
| **v2.0** | `amd64_win_freestanding` target + 移除 QBE 工具链 | 跟 v0.x 并行(不阻塞 v1.x);QBE 移除前 v0.x 编译管线不变 |
| **v2.x** | 自写 IL → .s + 多目标 + N 代 fixed point | 跟 v0.x 退役时机绑定(v1.0 闭环 + N 代稳定) |
| **v3.0** | OS P0 6 特性(3a-3f) | 跟 v0.x 无直接关系(纯语言扩展) |
| **v3.1** | `&mut + lifetime` + Cap<T>(3g + 3g.5 + 3g.7) | 跟 v0.x 无直接关系 |
| **v3.2+** | 后续特性(3h-3n) | 跟 v0.x 无直接关系 |

**v0.x 退役时机**:
- v1.0 真闭环达成(jhyy_1 编 jhyy_1 跑 regress 持平)= C 端编译器退役 = v0.x 时代结束
- v2.0 移除 QBE 工具链 + v2.x 自写 IL → .s 完成 = C 端 QBE 工具链依赖彻底移除 = v0.x 编译管线完全 self-contained
- 退役后:C 端 .c 文件归档到 `docs/logs/v0/`, 只保留 jhyy 端(`compiler/src0/*.jhyy`)

## § 5 跟 jhyy_OS 的对接(总览)

- **v0.x 阶段** OS 不可启动(自举未达,无 v3.x 6 特性)
- **v0.x → v1.0 过渡**:编译器自举 = 工具链 self-contained 关键节点
- **v1.0 closure**:jhyy 能编 jhyy(自举)→ 是 OS 启动链路**编译能力**的**基础**
- **v2.0 `amd64_win_freestanding` target**:给 OS 提供"编 UEFI PE/COFF kernel.efi + 不 link libc"的能力 = OS M1 启动链路第一项解锁
- **v3.0 6 特性 + v3.1 `&mut + Cap<T>`**:给 OS 提供 M1 启动 + M4 启动的语言能力
- **OS M11**:jhyy_OS 跑 jhyy 编译器 + 编 jhyy_OS kernel.efi = 真自举 OS 闭环

完整阶段链见 [`architecture-refactor.md` § 16](architecture-refactor.md)。
