## 3. v4.x 跨轴关系(post-merge serial)

### 3.1 v4.x 内部顺序(per 依赖图决定 — **不**预设串行 / 并行元规则)

- **v4.0.0 merge**(机械,不动代码)→ **v4.1.0 M5**(强前置 merge)
- **强依赖锁**(必须按序):
  - v4.3.0 lifetime full + Polonius → v4.4.0 closure 增强(v4.4.0 依赖 v4.3.0 Polonius)
  - v4.2.0 async → async trait / async closure(v4.x 中 backlog)
  - v4.11.0 并发 cap → "async + 多线程完整集成"(backlog)
- **弱依赖 / 独立**(可并行):
  - v4.2.0 async ‖ v4.5.0 const generic ‖ v4.6.0 trait objects ‖ v4.7.0 错误恢复 ‖ v4.8.0 优化 ‖ v4.9.0 包管理
  - v4.5.0 + v4.6.0 → v4.10.0 HKT + specialization(v4.10.0 强依赖 v4.5/v4.6)
- **worktree 规则**:per 实际依赖图决定(per [[feedback-no-blind-serial-rule]])
  - 强依赖链 → 同 worktree 串行 commit
  - 独立 sub-sprint → 可开 feature branch / worktree 并行,merge 时解冲突
  - 跟 v2 ‖ v3 parallel model 一致(v3.x 内部 V3-A / V3-B / V3-C 也是错峰并行)

### 4.2 worktree 规则(post-merge)— **按依赖图判断**

- v4.x 主轴 = `main` branch(integration),feature branch merge 时 fast-forward / rebase 进 main
- v4.x 每 sub-sprint ship 走:`main` direct commit + tag `v4.X.0`(或在 feature branch 完成后 squash merge)

### 4.3 D43 阶段性 self-equal(per `v1.x-phase-4-m5-boot-from-scratch.md`)

- v4.x 每 ship 走 V2-C v2.8.0 + v3.x 已建立的 reproducibility gate(同输入 .il byte-equal)

## 5. v4.x 完成标准

v4.x 全部 ship = jhyy 是**功能完整现代系统编程语言**:

| 类别 | 特性 | 来源 |

| **OS-required 语言** | asm / naked / volatile / no_std / link_section / barrier / `&mut` + lifetime / Cap<T> / generics / closures / std lib(mem / fmt / string / arena / io / os / vec / map / math)| v3.x + v3.3.0 |
| **M5 闭环** | 删 `src/*.c` + untrack QBE + 删 `runtime.c` | v4.1.0 |

| **UX** | 错误恢复 / 优化 pass / 包管理器 | v4.7 - v4.9 |
| **高级类型系统** | HKT + specialization / 并发 cap + memory model + 多架构 ABI | v4.10 - v4.11 |
| **Binary format** | `.jhyynb` native binary(DWARF + section builder + `--target=jhyy-os` + `jhyy-inspect`)| **v4.12.0** |

完成后 = **现代系统编程语言 + 自举 OS 真闭环**。

## 6. v4.0.0 merge 流程(简)

merge 本身是机械动作(per `[../v4/v4.0.0-plan.md](../v4/v4.0.0-plan.md)`):

1. `git checkout main`
2. `git merge --no-ff axis-v2`(冲突解决;docs/ 路径冲突多,源码 `src0/*` 冲突少)
3. `git merge --no-ff axis-v3`
4. D43 重新 baseline freeze → 写进 `docs/logs/v4/changelog-v4.0.0.md`
5. `axis-v2` + `axis-v3` worktree + branch 删除(per `feedback_batch_worktree_cleanup`)
6. `git tag -a v4.0.0` + `git push origin v4.0.0`
7. `main` `CLAUDE.md` 版本轴段更新:v2/v3 并行 → "v4 按依赖图决定并行/串行"

merge 不开新 worktree — 1 个 commit 完成。

## 7. v4.x 完成 ≠ M5 完成 / OS 真闭环

v4.1.0 M5 ship 后:
- 编译器端 0 C 依赖闭环(`jhyy 编 jhyy`)
- 但 **OS 端真闭环**还要求 jhyy_OS 用 jhyy 编 OS kernel + 在裸机跑通 — 这部分在 jhyy_OS 项目,不在 v4.x scope
- v4.1.0 ship 后 OS launch 阶段才能暴露 / 验证
