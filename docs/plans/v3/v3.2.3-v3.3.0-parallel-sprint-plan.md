# v3.2.3 → v3.3.0 并行 sprint 调度

> 锁定于 2026-09-09 (v3.2.2 ship 后规划)。 后续 v3.x 并行 sprint 排程参考本文件 + `docs/plans/roadmap/v2-v3-parallel-sprint-plan.md`。

## 1. Context

**为什么做这个规划**:v3.2.2 (3l.1 std lib M0) ship 后,v3.2.3..v3.3.0 这 5 个 sprint 仍在 waiting 状态(per W-073 D43 closure chain hold)。 鉴于 v2.x 中末 (QBE 自写 + amd64_sysv 实 impl + N 代 fixed point + codegen_amd64_run 真修) 是 v3.2.3+ 启动的**真正前置**,先把这 5 个 sprint 内部互相依赖分析清楚,等 v2.x 中末 ship 信号后可立即按并行计划启动。

**为什么不直接串行**:v3.2.3 / v3.2.4 / v3.3.0 互不阻塞(per各自 plan "上游依赖" 段),串行浪费 wall-clock 3×。

**与既有计划的区别**:`docs/plans/roadmap/v2-v3-parallel-sprint-plan.md` 描述 v2.x ⟂ v3.x 跨轴并行;本文件聚焦 **v3.x 内部** v3.2.3..v3.3.0 这 5 个 sprint 的并行调度。

## 2. Sprint scope + dependency matrix

| Sprint | scope | 上游依赖 | 内部硬阻塞 |
|--------|-------|----------|-----------|
| **v3.2.3** (3l.2) | `std::io` (Win32/POSIX file r/w + stdin/stdout/stderr) + `std::os` (open/read/write/exit/getenv syscall wrappers) | v3.2.2 ✅ (mem/arena) | 无 |
| **v3.2.4** (3l.3) | `std::vec<T>` (动态数组,mem/arena 复用) + `std::map<K,V>` (open addressing + linear probing,可选 string hash) | v3.2.2 ✅ (mem/string/arena) | 无 (Vec 不依赖 io/os;Map hash 可选 string 3l.1) |

## 4. 并行风险 + 缓解

### R1: 3 路并行同时改 src0/codegen.jhyy + src0/main.jhyy → merge 冲突

| 影响 | 缓解 |
|------|------|
| v3.2.3 (std::io/os) 改 `main.jhyy` inline_imports 路径集成;v3.2.4 (vec/map) 改 `main.jhyy` + `codegen.jhyy` 泛型 std lib 集成;v3.3.0 (3h) 大改 `codegen.jhyy` (新 QBE s/d ops + ABI 分支) | 3 路用不同 worktree (per `feedback_axis_vn_worktree_isolation`):<br>- axis-v3.2.3 worktree (从 v3.2.2 HEAD 拉)<br>- axis-v3.2.4 worktree (从 v3.2.2 HEAD 拉)<br>- axis-v3.3.0 worktree (从 v3.2.2 HEAD 拉)<br>merge 时按"std lib 先于 codegen" 顺序集成(避免 codegen 改动吃 std lib 集成) |

### R2: D43 closure chain hold 在 3 路并行下被新 codegen 改动破

| 影响 | 缓解 |
|------|------|
| v3.3.0 大改 codegen.jhyy (新 s/d ops) 极可能让 N15 byte-equal 漂移;v3.2.3/v3.2.4 不碰 codegen (除非 vec/map 触发新 codegen 路径) | 每个 sprint ship 前 `make selfhost` 验证 v1→v2→v3→v4→v5 byte-equal chain;漂移 → N15 baseline re-set + changelog 记。 **N15 漂移本身不破 ship,只是 baseline 重置** |

### R3: jhyy_selfhost_check MCP 锁 main worktree (per `feedback_mcp_jhyy_run_workspace`)

| 影响 | 缓解 |
|------|------|
| 3 个 worktree 并行时 MCP jhyy_selfhost_check / jhyy_run 只看 main worktree,看不到 axis-v3.x 子 worktree 改动 | **3 路全用 Bash + 绝对路径** (per memory `feedback_mcp_jhyy_run_workspace`):<br>- `python compiler/build/bin/regress.py --binary=<worktree>/jhyy.exe`<br>- `make selfhost` 走 absolute path<br>MCP 工具**仅**用于 main worktree 单测 (axis-v3 worktree 不调 MCP) |

### R4: v3.2.4 vec<T> 在 std::mem 用 i32-store (W-075) 下的 byte-level 行为不一致

| 影响 | 缓解 |
|------|------|
| std::mem mem_set 是 i32-store (W-075) 而非 byte-store;Vec copy/move 用 mem_copy 后,**非 4 倍数长度**数据可能错位 | v3.2.4 plan 阶段就把 `mem_copy` 改成 byte-store 真修 W-075 (per W-075 描述 "v3.x mid 优化" 重新评估,vec 真依赖 → 提前修);测试覆盖非 4 倍数长度 (e.g. 5 字节 copy) |

### R5: v3.3.0 浮点 ABI Win vs SysV 跟 codegen_amd64_emit_call.jhyy 的 4 NULL guard (W-068/W-072) 叠加

| 影响 | 缓解 |
|------|------|
| v3.3.0 给 codegen_amd64_emit_call.jhyy 加 SSE xmm0-7 调用 → 跟 v3.1.4 累积的 4 NULL guard + dedup 改撞 | v3.3.0 ship 前必 `grep -c "fn codegen_amd64_run" compiler/src0/codegen_amd64.jhyy = 1` 验证 invariant;新 SSE 分支独立 module 写,不混进 `codegen_amd64_emit_call.jhyy` 主函数体 |

### R6: std::os syscall wrappers 跟 runtime.c 已有 Win32 wrapper 冲突

| 影响 | 缓解 |
|------|------|
| runtime.c 已经有 Win32 wrapper (`GetCommandLineW` / `CommandLineToArgvW` / `WideCharToMultiByte` 等, per W-076);std::os 加 open/read/write 会跟 runtime.c `jh_*` helper 重名或重复 impl | std::os module 用 `std_os_*` 前缀 fn 名 (per W-076 pattern);runtime.c `jh_*` 保留作为 legacy bridge;std::os 是新 API,替代 jh_* (后续 v3.x 中末切换) |

## 5. 推荐调度(per 2026-09-09 user 决定 "只写计划就行")

### 阶段 A — 等 v2.x 中末 ship 信号

- v2.x 中末 ship 触发 (QBE 自写 + amd64_sysv 实 impl + codegen_amd64_run 真修 + N 代 fixed point)
- D43 closure chain N15 baseline 真测(不再 hold)

### 阶段 B — 3 路并行启动

按 R1-R6 缓解路径,3 路 worktree 各开一个 sprint:

| Worktree | Sprint | scope | 工作量估 |
|----------|--------|-------|----------|
| axis-v3.2.3 | v3.2.3 (3l.2) | std::io + std::os | 4 std 模块 + 8-12 测试 |
| axis-v3.2.4 | v3.2.4 (3l.3) | std::vec + std::map 泛型 | 2 std 模块 + 8-10 测试 + jhyy 自身迁移 (大 refactor) |
| axis-v3.3.0 | v3.3.0 (3h) | f32/f64 类型 + ABI | ~10 文件改 + 4 测试 + ABI spec supplement |

### 阶段 C — v3.2.5 barrier (3 路都 ship 后启动)

| Sprint | scope | 工作量估 |
|--------|-------|----------|
| v3.2.5 (3l.4) | std::math FFI libm | 1 std 模块 + 4 测试 |

### 阶段 D — OS M11 launch (v3.x 全 ship 后)

v3.x ship 链路:v3.0..v3.1.x → v3.2.0..v3.2.5 → v3.3.0 → 全部 ship → **OS M11 launch**。

## 7. Activation gate

本并行计划在以下条件**全部满足**时激活:
1. ✅ v2.x 中末 ship (QBE 自写 + amd64_sysv 实 impl + N 代 fixed point + codegen_amd64_run 真修)
2. ✅ D43 closure chain N15 baseline byte-equal hold (per W-073)
3. ✅ user 显式启动信号 ("start v3.2.3 + v3.2.4 + v3.3.0 in parallel" 之类)

激活前不做任何 sprint 启动工作(避免 wall-clock 浪费 + 避免在 v2.x 还在修时污染 D43 baseline)。
