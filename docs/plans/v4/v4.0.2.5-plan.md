# v4.0.2.5 — W-097 emit_func_header multi-field-access operand swap 真修 → Stage 2 closure 走通 → v4.0.0 final promote

## Context

v4.0.2.4 ship 后 ACTIVE bucket = 1 (per W-098 真修 audit + flip)。剩 **W-097 (DEFERRED)** 阻塞 v4.0.0 final promote:Stage 2 closure chain (`jhyy.exe → jhyy_v2.exe.exe → jhyy_v3.exe.exe → ...` byte-equal) 因为 jhyy-side codegen `emit_func_header` 处理 multi-field-access 表达式 (e.g. `ptr_add_u8(field_a, (field_b - N) * 8)`) emit wrong QBE IL → `per_fn_max` lookup 读 garbage → `frame_size > 4096B` → `___chkstk_ms` clobber `%rcx` → 所有 C 函数 call SEGV。

W-097 audit (`docs/audit/w-097-emit-audit-checklist.md`) 原始 list 3 sites in `emit_ctrl.jhyy:519/529/551`。Re-audit 2026-10-09 跨 src0/ 全 grep surface **25 sites in 10 files** with multi-step ptr_add_u8 arithmetic pattern。Tracked `jhyy_v1.exe.exe` baseline (v1.8.3.2 C-side compiled) works;fresh `_fix_v1.exe` (v2.5.0 self-backend) fails。

**RCA 假说 (未验):** 单一根因可能在 `cg_expr` NODE_BINARY → `ir_emit_binary` path,对 chained binop-as-fn-arg 的 operand ordering 处理。或在 emit-side `emit_binop` 的 `src2_is_imm` parser 对 multi-digit 表达式 (e.g. `mul t1, 8` 后续 chained 表达式) parse 错。

**Goal:** W-097 真修 → Stage 2 closure chain N≥3 byte-equal PASS → v4.0.0 final tag promote。
