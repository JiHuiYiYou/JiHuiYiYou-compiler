## Context

**这一版解决自审里「最严重的一处遗漏」。**

> 我的需求清单把它列为第 11/12 项,但**路线图里没有任何阶段承接**。
> 这是个结构性错误:我所有的 P 阶段都在解决「**内核安不安全**」,
> **没有一个阶段在解决「内核能不能用这门语言表达出来」**。

**自审的原话**:
> 做不到这一点,语言在内核里就活不下去 —— Rust for Linux 至今的拉锯都在这。

**三个原语**:

| 原语 | 解决什么 | 现状 |
|---|---|---|
| **`Rcu<T>`** | 读侧关联 grace period;延后释放不被提前回收 | 原语不存在 |
| **`PerCpu<T>`** | 每 CPU 一份;跨 context 的指针不会失效 | 原语不存在 |
| **侵入式容器** | 内核对象常驻链表 / 队列,**不能移动** | 无 list_head / trait / 移动模型 |

⚠️ **Rust 的教训**:Rust 并不能让「对象在多个链表、生命周期由 RCU grace period 管理」
自然成为单所有权模型。
⇒ **JHYY 应直接设计侵入式容器与 RCU token,而不是先复制 Rust `Box/Arc` 再补 `ListLinks`。**

---

## Goal

1. **一个内核链表 + RCU 读侧能用 JHYY 自然表达,无需 unsafe**
2. **`Rcu<T>` 有明确的 grace period 语义**
3. **`PerCpu<T>` 用 `gs:` 段寻址**
4. **侵入式容器不要求对象可移动**

## Scope

### 任务 1 —— 侵入式容器

```jhyy
struct ListNode { next: *ListNode, prev: *ListNode }

struct Task {
    name: [u8; 16],
    list: ListNode,        // 嵌入在 Task 里 ⇒ Task 不可移动
}

fn list_push(head: &mut ListHead, task: &mut Task) { ... }
```

⚠️ **「不可移动」是核心约束** —— 容器指针悬空是这个原语要防的。
⇒ **类型系统要不要表达「不可移动」?**
⇒ **建议:先不引入 move 语义**(那是 Rust 级别的改动),
但**在文档与 API 上明确「嵌入 ListNode 的类型不可移动」**,
并用**运行时断言 + 文档**双管。

⚠️ **这是本版的一个明确取舍** —— 完整方案是「引入 move 语义 + 编译器检查」,
**代价远超本版**;**先做 API 层的约束**。

### 任务 2 —— `Rcu<T>`

**读侧**:
```jhyy
let p = rcu.read();
let v = p.get();          // 读侧安全
// grace period 内 v 有效
```

⚠️ **必须回答**:
- grace period 的**边界**是什么(何时算「读侧结束」)
- `Rcu<T>` 的**读侧是否需要显式 drop / guard**(Rust 的 `RcUReadGuard` 模式)
  ⇒ **建议**:需要 —— 编译器无法推断读侧的结束点 ⇒ 用一个 **RAII guard 对象**表达
- 写侧(改指针)的**同步语义**

⚠️ **与 v4.13(OS-12)的效果系统的关系**:
「在 grace period 内读」是一个**上下文事实** ⇒ 理想上要进效果系统
⇒ **但 v4.13 的效果格没有这一维** ⇒ **本版先用显式 guard 对象**,不进效果系统。

### 任务 3 —— `PerCpu<T>`

- `gs:` 段寻址(x86-64 的 per-CPU 基址)
- 需要**链接器 / 启动代码**把 `gs:` 段设好 ⇒ **这是内核侧工作**
- ⚠️ **跨 CPU 迁移时指针失效** ⇒ 类型上要表达「只在当前 CPU 有效」

### 任务 4 —— 与 `ptr<phys>` / capability 的交互

⚠️ **PerCpu 指针与 `ptr<phys>` 是不同的东西** ——
`ptr<phys>` 是物理地址;PerCpu 指针是**每 CPU 的段内偏移**。
⇒ **不能互相转换**。

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| **「不可移动」只在文档里** ⇒ 对象被移动后指针悬空 | 运行时崩 | API 层约束 + 文档;⚠️ 完整方案(move 语义)留 v4.16+ |
| RCU 语义与内核的 grace period 实现对不上 | 提前回收 ⇒ UAF | 边界定义要跟内核侧对齐;**这一格依赖 OS 侧设计** |
| `PerCpu` 与 `ptr<phys>` 混用 | 物理地址越权 | 明确的禁止转换规则 + 门 |
| 与 v4.13 效果系统割裂 | 长期两套 | 本版先用显式 guard;后续版本再考虑进效果格 |
