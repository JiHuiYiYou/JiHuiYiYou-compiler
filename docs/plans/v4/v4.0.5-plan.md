## Strategy: 1-iter RCA + minimal repro + targeted fix (per audit § 5 separate address-holder pool direction)

**关键 insight (per audit § 5):** fix 路径不是改 alloc pool 跟 formula pool 的关系,而是给 address-holder slot 走**完全独立**的 pool,放在 alloc pool **下方**,formula pool **完全无关**。

```
当前 frame layout:
  [formula pool: rbp-X ... rbp-32]  ← local_max=2060 → rbp-16520
  [overlap zone: rbp-16520..rbp-8192]  ← alloc/formula 互相 clobber
  [alloc pool: rbp-8192 ... rbp-?]

v4.0.5 frame layout (3 pools 独立):
  [formula pool: rbp-X ... rbp-32]      ← local_max dependent
  [alloc pool: rbp-Y ... rbp-formula_end - 64]  ← attempt #4 fail
  [address-holder pool: rbp-Z ... rbp-alloc_end - 64]  ← 新独立 pool
  [stack args / shadow space]
```

**Address-holder pool 走完全独立 region** — 跟 formula pool + alloc pool 都物理 disjoint:
- address-holder slot = `(allocated pointer) → (ptr-to-allocated-block)` storage,emit_copy/emit_load/emit_store 走 indirect load/store 通过 holder
- holder slot 必须 永远不被 emit_binop / emit_const / 任何 formula-path 写
- 当前 bug = holder 落 alloc pool (跟 formula pool overlap) → alloc pool 第一目标修是把它推 formula 下方,但**不解决** (alloc 自身 formula pool overlap)

**v4.0.5 实施思路:** address-holder 走自己 pool,start = alloc pool end + 64 gap (= 公式 `-(per_fn_alloc_end + 64)`,per-fn dynamic)。alloc pool 自身保留 attempt #1-#4 disjoint 修复 (init_off = formula_end + 64,已 ship 部分,见 attempt #4 ledger `f55f8d4` 步骤 1) — 但**只保证 alloc pool 跟 formula pool disjoint**,address-holder 完全跳出三 pool 关系。

### Step 2 — 1-iter RCA 验证 separate address-holder pool 假设 (per `feedback_rca_first_root_cause`)

**假设:** 把 `cg_record_temp_slot(state, dst_id, holder_offset)` 写入的 holder slot 从 alloc pool 移到独立 pool,可彻底断开 alloc/formula pool overlap → emit_binop 写 formula slot 不可能 clobber address-holder。

**验证方法 (1-iter):**

1. **Read `codegen_amd64_state.jhyy:857-870` (`cg_alloc_slot`):** 当前 hardcoded `next_offset = -8192`,**所有 alloc 都落这个 pool**,包括 pointer-holder + value-holder。
2. **Read `codegen_amd64_state.jhyy:315-326` (`cg_record_temp_slot`):** setter writes `temp_slot_for_id[t] = offset`,**所有 holder 都走这里**。
3. **Read `codegen_amd64_emit_mem.jhyy:259` (`emit_alloc`):** 调 `cg_alloc_slot` 拿 holder slot,设 `temp_holds_address[result_id] = 1`。
4. **Read `codegen_amd64_emit_call.jhyy:1062` (`emit_copy`):** copy src→dst,**当 dst holds address**,copy 是 indirect through holder。
5. **Read `codegen_amd64_emit_mem.jhyy:389` (`emit_store`) + `:635` (`emit_load`):** indirect through holder。

**RCA question:** 如果 `cg_alloc_slot` 给 holder slot 走独立 pool (per audit § 5 fix direction),how 改 init_off formula 让:
- alloc pool 自身 init_off = `-(formula_end + 64)` (per attempt #4 ship 修过,部分 OK)
- address-holder pool 自身 init_off = `-(alloc_end + 64)` (NEW)

**预期 fix (per audit § 5 direction):**

```jhyy
// cg_alloc_slot NEW signature: accept "is_address_holder" param
fn cg_alloc_slot(state: *u8, aligned: i64, is_addr: i32) -> i64 {
    let s = state as *CGState;
    // 第一 call init:
    if (*s).next_offset == 0 {
        if is_addr != 0 {
            // address-holder pool = alloc pool end + 64 gap
            (*s).next_offset = (*s).addr_holder_init_off;
        } else {
            // value pool = formula end + 64 gap
            (*s).next_offset = (*s).alloc_init_off;
        }
    }
    // ...
}
```

加 `(*s).addr_holder_init_off` field 到 CGState,emit_func_header 算完 alloc_end 后 set `addr_holder_init_off = -(alloc_pool_end_off + 64)`。

**Verify 假设 (1-iter):**
- alloc pool 范围 = `[rbp-X, rbp-formula_end-64]` (attempt #4 已 ship 部分)
- address-holder pool 范围 = `[rbp-Y, rbp-alloc_end-64]` (NEW)
- formula pool 范围 = `[rbp-formula_end, rbp-32]`
- 三 pool 完全 disjoint
- emit_binop 写 formula slot 不影响 address-holder pool (物理 disjoint)
- emit_load %t9191 的 holder load 不走 alloc pool (走独立 addr_holder pool) → 不被 emit_binop clobber
