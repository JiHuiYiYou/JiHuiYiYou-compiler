## Context

**当前状态:零。**
lang-spec § 11.3 与附录 B 都明列 **HKT**(higher-kinded types)为不支持。

**这一版在 OS 线上的意义**:
HKT 支撑的是**以类型为参数的容器 / 抽象** ——
例如「一个对任意元素类型提供某种能力的抽象」(`Functor` / `Monad` 那一族,
或内核侧的「任意可分配对象的容器」)。

⚠️ **但要极度克制。** 强串行链的末端是 HKT,它的收益在 OS 语境下**最不直接**:
能力微内核需要的是**具体的能力类型**(`Cap<T>` / `ptr<space>` / 效果行),
不是高阶抽象。

⇒ **本版明确限定为「一阶 `F<*>` + 一层 impl 覆盖」** ——
**不做** kind 推断、**不做** kind 多态、**不做** higher-kinded trait bound 的完整推导。

---

## Goal

1. **一阶 `F<*>` 可声明**
2. **一层 impl 覆盖** —— 一个 `impl` 可以对「任意 `F`」实现
3. **3+ HKT 用例 PASS**
4. **不引入 kind 推断**(显式声明 kind)

---

## Scope

### 任务 1 —— 一阶 kind 语法

```jhyy
trait Functor<*> {
    fn map<A, B>(self, f: fn(A) -> B) -> Self;
}
```
⚠️ **kind 必须显式** —— 不做 kind 推断。

### 任务 2 —— 一层 impl 覆盖

```jhyy
impl<*> Functor<*> for Vec<T> { ... }
```
⇒ **一个 `impl` 覆盖一族类型**(而不是每个类型写一遍)。

### 任务 3 —— 单态化

`impl<*>` 的实现要按**具体类型**单态化 ⇒ 与 const generic / trait 的单态化机制共用。

### 任务 4 —— 与 trait / const generic 的共用

⇒ 三者(v4.12 trait / v4.12.3 const generic / v4.12.5 HKT)共用同一套
**泛型 + 单态化 + mangling** 基础设施 ⇒ **本版要复用,不要另起炉灶**。
