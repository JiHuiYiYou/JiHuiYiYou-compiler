## Scope

### 任务 1 —— trait 声明与实现

```jhyy
trait KernelObject {
    fn type_tag(&self) -> u32;
    fn revoke(&mut self) -> Result<(), KernelError>;
}

impl KernelObject for Frame {
    fn type_tag(&self) -> u32 { 1 }
    ...
}
```

⚠️ **trait 方法的 ABI / 效果 / 是否 `#[naked]` 必须匹配**(与 v4.10 的函数类型一致)。

### 任务 2 —— vtable 生成

每个 `impl` 生成一张 vtable ⇒ **要进 codegen**。
⚠️ **vtable 布局是 ABI 的一部分** ⇒ 要进 abi 文档 + abi-hash。

### 任务 3 —— `dyn Trait` 与 `Box<dyn Trait>`

- `dyn Trait` = **胖指针**(数据指针 + vtable 指针)⇒ **大小是 16 字节**
  ⇒ 影响 struct 布局 / 传参 / IPC wire ⇒ **要进 abi 与 D41 的布局契约**
- `Box<dyn Trait>` = 堆分配 + 虚调用

⚠️ **胖指针会撞上 OS 需求清单第 15 项**(wire 结构稳定 repr 与布局测试)
⇒ `dyn Trait` 出现在 IPC message struct 里时,必须按 D41 显式 `_pad`。

### 任务 4 —— 泛型约束 `<T: Ord>`

⚠️ **这是 trait 系统里最容易被低估的部分** —— 约束需要**约束求解**。
⇒ **建议先做「单约束 + 无关联类型」的最小形态**,
不要一上来做 Rust 那套完整的 trait 求解。

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| **约束求解器成本失控** | 版本做不完 | 先做「单约束 + 无关联类型」的最小形态 |
| **学习曲线陡增** ⇒ 违背「两周上手」 | 采纳率低 | 准入检查表第 4 条**写成验收门**;8 个内置 rights 类型的设计初衷就是避开这套代数 |
| **胖指针撞上 IPC wire 布局** | ABI 错 | D41 显式 `_pad`;布局差分测试(OS-16) |
| vtable 破坏产物可复现性 | 不可复现 | mangling 必须确定性(W-121 教训:符号名不许取自堆地址) |
| trait 方法 ABI 不匹配 ⇒ 静默错 | 难查 | ABI / 效果匹配检查进 sema |
