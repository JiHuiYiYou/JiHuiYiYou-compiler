## Context

**v4.10.5(OS-7)只做了两个效果 + 直接禁止规则。**
本版把它扩成**完整效果格 + 传播 + 禁止规则 + 锁序图**,
并补上**地址空间类型**这一块。

**四个效果 + 一个参数**(OS 侧要的最小集):

| 效果 | 语义 | 拦住的 bug |
|---|---|---|
| `may_sleep` | 是否允许 blocking | 持锁睡眠 |
| `irq_ctx` | 当前是否在中断上下文 | 中断中非法 sleep |
| `preempt_disabled` | 是否能 reschedule | 不可抢占区里的阻塞 |
| `may_alloc` | 是否允许分配 | PF 路径分配 |
| **`holds(L)`** | **持有哪些锁** | **锁序死锁** |

**三块内容**:

| # | 内容 | 为什么需要 |
|---|---|---|
| 1 | **完整效果格 + 传播** | v4.10.5 只有直接禁止 |
| 2 | **`holds(L)` 锁序图 + 环检测** | OS 需求清单第 19 项:「组合两个子系统即产生死锁」 |
| 3 | **`ptr<user>` / `ptr<kernel>` + 地址空间感知别名分析** | OS 需求清单第 4 项;**优化侧**至今零覆盖 |

⚠️ **第 3 项里的「别名分析」是自审点名的真遗漏**:
只做了安全侧(`ptr<phys>` 派生),**优化侧零覆盖**。

## Goal

1. **效果完整传播**(不只是直接禁止)
2. **锁序图无环** —— 反向锁边编译失败
3. **`ptr<user>` 直接解引用编译失败** —— `copy_from_user` 是唯一跨界通道
4. **per-CPU 备份栈的语义归位**(从 D11 的栈策略里划出来,归效果系统)
5. **误用给出确定错误码**

---

## Scope

### 任务 1 —— 完整效果格

**三段式**:声明的上限 + 调用点自动收窄 + 禁止点。
- 缺省时 Sema 从函数体**自底向上**计算效果格上确界
- 调用时被调者效果 ⊆ 当前允许效果
- 闭合效果集 + 子集传播;**不做** row 多态(除非内核 API 出现大量「多数效果相同、少数不同」的签名)

### 任务 2 —— `holds(L)` 锁序图

- 锁效果不是「锁名字的无限集合」,而是
  `(lock_class, direction, option<order_index>)` 的**有限事实**
- **普通锁只检查有序对**;读/写锁才进入强依赖规则
- **环检测**:编译期构建锁序图 ⇒ 有环 ⇒ 编译失败

```text
E0511: 锁序违反已验证的偏序
  = 已有持有集：{ lock_class=7(A), order_index=0 }
  = 新加锁边：A(7) -> B(9)
  = 全程序已存在强路径：B(9) -> ... -> A(7)
  = 建议：统一按 LOCK_ORDER 声明，或将 A/B 改为同层嵌套锁
```

⚠️ **锁类用显式 `lock_class!` 编号**(不做依赖类型 `Lock<order>`)
⇒ 避免锁比较和调用签名迅速膨胀。

### 任务 3 —— `ptr<user>` / `ptr<kernel>`

- `ptr<user>` 指向用户空间、`ptr<kernel>` 指向内核空间
- **解引用上下文检查**:在错误的上下文解引用 ⇒ 编译失败
- **`copy_from_user` / `copy_to_user` 是唯一的跨界通道**

### 任务 4 —— 地址空间感知别名分析(优化侧)

⚠️ **自审点名的真遗漏** —— 优化侧至今零覆盖。
目标:知道两个指针是否可能指向同一块内存 ⇒ 才能安全地重排 / 合并 / 消除访存。

⚠️ **与 `ptr<io>` 的交互**:`ptr<io>` 默认 volatile、不合并、不推测
⇒ 别名分析**不得**把两个 `ptr<io>` 判为同一对象从而合并访问。

### 任务 5 —— per-CPU 备份栈归位

D11 建议把 per-CPU 备份栈**从栈策略里划出去** ⇒ 归效果系统
(`preempt_disabled` 语义 + per-CPU 双缓冲)。

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| **效果格求解误拒合法代码** | 开发阻塞 | 误拒比漏拒好,但要有明确错误信息 + 覆盖机制 |
| **锁序图误报环** | 开发阻塞 | 环检测要能区分「同层嵌套锁」与真环 |
| **别名分析激进 ⇒ 误合并访存** | 静默错值 | **偏保守**:不确定就不优化 |
| 别名分析与 `ptr<io>` 冲突 ⇒ MMIO 读被合并 | 硬件级静默错误 | 明确规则 + 门 |
| 效果元数据进 IL ⇒ schema 变化 | 回归面 | 与 v4.9(OS-5)的 IL 节点设计对齐 |
