## Context

**跨基本块的值今天全部落槽** —— v4.4.0 的资格判据是「def 与**所有** use 在同一基本块
(中间不能有 label)」⇒ 一个 `if` / `match` 分支两侧的汇合点就断了。

**phi 解析今天是 slot-based 的顺序 copy**(`codegen_amd64_emit_call.jhyy:1167`),
**寄存器化后必须改成并行移动**:
顺序 copy 在源和目标重叠时会读到自己刚写的值 ⇒ 经典的 swap 需要临时寄存器。

⚠️ **这一版同时是「缺 dominance / phi」这个缺口的正式承接点** ——
IR **已经是 SSA**(前端一直产的),但**后端没有 dominance 信息**,
所以 phi 节点在 emit 层只能退化成「顺序 copy 到汇合点的槽位」。
本版要补的是**后端的 dominance / 块间活跃信息**,不是把 IR 改成 SSA。

---

## Goal

1. **跨基本块的值能进寄存器** —— 分支汇合不再强制落槽
2. **phi 用并行移动** —— 顺序 copy 在源/目标重叠时正确
3. **环能打破** —— 并行移动图里存在环时(理论上不该有,但要能检测)有确定处理
4. **`-O0` 产物逐字节不变**(默认关)

---

## Scope

### 任务 1 —— dominance / 块间活跃信息

后端需要能回答:
- 一个 temp 的 def 在哪个块,use 在哪些块
- 哪些块在汇合点存活(liveness)

⚠️ 前端**已有 SSA**,但**不保证**把 dominance 传给后端 ⇒ 需要确认
IL 里是否已保留足够的块结构信息,不足则要扩 IL schema。

### 任务 2 —— phi 并行移动

把 phi 边改成**同时赋值**语义:
```
// 今天:顺序 copy —— src/dst 重叠时读到自己写的值
// 要做:并行移动 —— 需要临时寄存器打断环
```
实现形状:构建并行移动图 → 找环 → 每个环用一次 temp 打断。

### 任务 3 —— 环检测与响亮失败

理论上 SSA + 合法 phi 不产生环 ⇒ **出现环就是 bug** ⇒ 必须**响亮失败**,
不能"绕过去"(per W-120 / W-130 的规矩)。

### 任务 4 —— 与「禁 XMM / red zone」约束的交互

跨基本块的 XMM 值 ⇒ 同样是「XMM 能不能当溢出目标」的真实场景 ⇒
本版要验证该约束在跨块场景下仍然成立。

## 验收门

| Gate | 验证方法 | Status |
|---|---|---|
| **`-O0` 产物逐字节不变** | 默认关 ⇒ 现有门全绿 | ⏳ |
| **if / match 汇合点的值正确** | 造用例:分支两侧赋不同值、汇合后使用 ⇒ 结果正确 | ⏳ |
| **phi 源/目标重叠时正确** | 造用例:两个 phi 互为源与目标(swap 形状)⇒ 结果正确 | ⏳ |
| **并行移动出现环 ⇒ 响亮失败** | 造红灯 ⇒ 编译失败 | ⏳ |
| **跨块 XMM 值不违反约束** | 造红灯 ⇒ 编译失败 | ⏳ |
| **访存指令数进一步下降** | `runtime_perf.py` 静态指标 `mem` | ⏳ |
| **全量 regress 不退步** | 当前基线见 [FACTS § 2](../../internal/FACTS.md#2-回归与门) | ⏳ |

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| 并行移动写错 ⇒ **静默错值** | 极难查 | 造 swap 形状用例;响亮失败优先 |
| 扩 IL schema ⇒ 前端改动面扩大 | 回归面扩大 | `-O0` 逐字节不变作硬约束 |
| 跨块活跃分析不准确 ⇒ 过度保守或过度激进 | 覆盖率不升 / 错值 | 过度保守只是没收益,过度激进是错值 ⇒ 偏保守 |
| 收益有限(跨块占比小) | 投入产出差 | 启动时先量语料 A 的跨块占比,不够则缩小范围 |
