## Context

**这一版不是语法美化,而是 P4 与内核 API 的语义基础。**

| 缺什么 | 为什么阻塞 |
|---|---|
| **块表达式** | BootState 本质是**带顺序的状态迁移**;若块不能产生值、函数末表达式不形成连续控制流,状态推进只能在函数边界完成,临时状态与错误恢复会退回全局可变变量 |
| **`fn(...)` 类型位置** | 当前没有函数指针类型语法,而 `#[naked]` interrupt、MS x64 函数指针和 IPC stub 都要求编译器知道参数/返回值的 lowering |
| **闭包捕获** | 阻止 hot helper 携带本地 token,迫使开发者把大量两行函数写成顶层名字 |
| **`()` 类型位置** | 消除「函数指针无类型、闭包不能捕获、函数体末表达式返回不触发 defer」的断裂 |
| **结构化内联汇编** | `asm!` 仍是字符串(abi § 8)—— 只修了「内联位置」这个正确性 bug(W-113),**没做结构化改造** |
| **可用的格式化输出** | ⚠️ **2026-11-02 补**:v4.5 阶段 0 补齐了 `fmt_*` 函数集与 `[0; N]`(buffer 声明从 **318 字符**降到 32 字符),但**调用方仍要手写缓冲区 + 手拼 `fmt_i32` + `io_print`** ⇒ 「打印一个整数」**还是 5 行**(阶段 0 不减句数 —— 2 句要「格式化+打印」组合 helper ⇒ `fmt`↔`io` 依赖边,而 std 模块间能否 import **至今未验**)。⇒ 本版补「**编译期分派**」这一层 |

⚠️ **闭包捕获目前是编译期明确报错**(MVP 范围外,见 W-115)⇒
**本版要么实现它,要么维持报错** —— 不能静默生成坏代码。

⚠️ **`#[inline]` 只在函数体为单条 `return expr;` 时展开**
⇒ 内核热路径**一个 helper 都内联不了** ⇒ 闭包捕获 + `#[inline]` 是同一件事的两面。

---

## Goal

1. **BootState 迁移可写在块内**
2. **函数指针可跨模块传递**(带 ABI / 效果 / `#[naked]` 匹配检查)
3. **100 个内核 helper 可写成 1–5 行闭包**并被 `#[inline]` 展开
4. **`asm!` 块未声明 clobber 即报错**
5. **`defer` 覆盖末表达式**(当前末表达式返回不触发 defer)
6. **`println!` 编译期格式化** —— 「打印一个整数」从 5 行降到 1 行(2026-11-02 新增)

## Scope

### 任务 1 —— 块表达式

```jhyy
fn enable_paging(s: BootState<PagingOff>) -> BootState<PagingOn> {
    configure_cr3();
    if ready() { mark_on() } else { try_fallback() };
    BootState { _token: PhantomData }
}
```
⚠️ 这会**动 parser 与 sema 的表达式解析** ⇒ 回归面大 ⇒ 分步 ship。

### 任务 2 —— `fn(...)` 类型位置

最小方案**不必先实现高阶类型**:只要允许函数类型出现在**参数、变量和返回值**位置,
并强制其 **ABI / 是否 `#[naked]`** 匹配。
⚠️ **「效果」那一维本版不做**(见下面的定案)—— 效果系统在 v4.10.5(OS-7),晚半格。

```jhyy
fn register_handler(cb: fn(ctx: &TrapCtx) -> u64) { ... }
```
⚠️ 报错要指路:
```text
E0801: 函数指针类型不兼容
   = 目标期望：extern "sysv" fn(ctx: &TrapCtx) -> u64
   = 实际签名：fn()
   = 建议：使用完整函数类型，不要将裸地址转为不透明函数指针
```

#### `fn` 类型的**效果行 = 格顶（全部效果）** —— 本版定案

**为什么必须在这一版定**（编译器侧 §3.2 的同一决定）:
完整效果系统在 **v4.10.5(OS-7)**,晚半格。若 `fn` 类型在本版没有效果行、
且默认取 **bottom（无效果）**,则

```jhyy
let f: fn() = sleep;
f();          // ← 调用点无效果信息 ⇒ OS-7 的禁令被绕开
```

是一次**洗白** ⇒ **整条效果系统从这一处漏掉**。

⇒ **本版定案:`fn` 类型的默认效果 = 效果格的顶（全部效果）**。
经函数指针的调用一律**假定被调者可能 sleep / alloc / 中断**
⇒ OS-7 的禁令与后续 P3.5 的锁序、`may_alloc` 规则**都仍拦得住**。
`asm!` 块的效果签名**同样默认格顶**。

代价：间接调用**过度保守**（合法的 `f()` 在 `irq_ctx` 里也会被拒）——
但这是**误拒**不是**漏拒**，且 P3.5 的完整效果格会把它收窄。

⚠️ 本版**还没有** `with { ... }` 显式标注（那是 v4.10.5 的语法）
⇒ 效果行**恒为格顶**；v4.10.5 起可显式收紧。

#### `fn` 调用点必须申报栈预算

本版引入**间接调用** ⇒ 调用图出现断边 ⇒ P2 的 `call_path_max` 从「全程序上界」
退化成**下近似** ⇒ 链接期断言会被绕过。

⇒ **`fn` 类型的调用点必须显式申报栈预算，否则链接期拒绝**
（复用 P0.5 / `v4.7-plan.md` 任务 3 的「递归 / 动态调用显式标记」机制）。

### 任务 3 —— 闭包捕获

⚠️ **W-115 的教训**:闭包捕获外层变量在 MVP 范围外,
旧实现**没有任何检查** ⇒ 生成坏代码(env 压根没传进合成 fn)⇒ 运行时炸。
⇒ **要么实现,要么编译期明确报错** —— 绝不能静默生成坏代码。

### 任务 4 —— `()` 类型位置 + `defer` 覆盖末表达式

消除「函数体末表达式返回不触发 defer」的断裂。

### 任务 5 —— 结构化内联汇编

目标:**类型化操作数、显式 clobber、效果签名**。
```jhyy
asm!("...", in(reg) x, out(reg) y, clobber("cc"), volatile);
```
⚠️ **clobber 未声明即报错** —— 这是「汇编破坏 ABI 假设却无法静态发现」的正解
(OS 需求清单第 22 项)。

⚠️ **效果签名本版恒为格顶**（任务 2 的同一定案）—— 显式 `with { ... }` 是
v4.10.5(OS-7)的语法 ⇒ 本版 asm 块的效果 = 全部效果（假定它可能 sleep / alloc / 中断）。

⚠️ 与 v4.9(OS-5)的 IL 节点承接:本版把 IL 节点的类型化信息真正用起来。

### 任务 6 —— 编译期格式化宏 `println!`

> **2026-11-02 新增。** 归属理由:它要**前端宏设施**,而 jhyy 现在**没有宏**
> (`asm!` 是「单字符串 literal」的特殊 builtin,§ 17.2)⇒ 要么做 builtin 形式的宏,
> 要么做通用宏系统。本版与 `asm!` 的结构化改造(任务 5)同属**前端表达式设施** ⇒ 同版。

**形状**

```jhyy
println!("x = {}", x);
println!("{:.2} {:#x} {:p}", y, z, w);
```

**编译期做三件事**(运行时零解析):

1. 解析格式串数出 `{}` 的个数 ⇒ 与实参个数比对 ⇒ 不符**编译期报错**
2. 每个实参取**静态类型** ⇒ `{}` 按类型选转换器;`{:x}` / `{:.2}` / `{:p}` 显式指定
   ⇒ 类型不符**编译期报错**
3. 展开成一串**固定元数**的调用(`fmt_i32(buf, x); io_print(buf);`)

**⚠️ 展开目标是纯 jhyy 的 `std/fmt.jhyy` + `std/io.jhyy`** —— **不是 C bridge**:
v4.5 已把 std 变成纯 jhyy(0-C 闭环)⇒ 若走 C bridge 就与那个方向相反。
⇒ **转换器函数集在 v4.5 阶段 0 已冻结** ⇒ 本任务只是它上面的一层薄分派。

**为什么放本版而不是更早**

| 理由 | 说明 |
|---|---|
| **要宏设施** | jhyy 无宏 ⇒ 本版只做 **builtin 形式**(一个 `println!`),**不做通用宏系统** |
| **分派不依赖 trait** | 分派发生在**编译期**,按实参的静态类型 ⇒ **不需要 `Display`** ⇒ 不用等 v4.12 |
| **与 `asm!` 同属一类改造面** | 任务 5 已在本版改前端表达式设施 ⇒ 一次前端改造期 |

**明确不做**

| 不做 | 为什么 |
|---|---|
| **通用宏系统**(hygiene / 多阶段展开) | 另一个量级的工程 ⇒ 本版只做 builtin |
| **trait 派发的 `Display`**(`impl Display for MyType` + `println!("{}", my)`) | 等 **v4.12**(OS-9);本版分派**只按内建类型** |
| **变参 ABI** | § 14 明写不支持;`printf` 绑不了是既定事实 ⇒ **本版永远不碰** |
| **运行时格式串解析** | 零运行时开销是本方案的全部意义 |

**两条硬门**(卡住的东西不许静默)

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **`volatile T` 实参 ⇒ 编译期报错** | 编译器侧 § 3.3:`emit_volatile` 只发注释、什么都不做 ⇒ 寄存器分配一上就会**缓存 MMIO 读** ⇒ volatile 值不得进格式化路径 |
| 2 | **`#[no_std]` 下 `println!` ⇒ 编译期报错** | 它依赖 `io` 的 libc 侧;内核的 early console 走 `os::std_os_write`,**不占用 `println!`** |

**三条歧义要写进规范正文**(不然天天有人踩)

| 写法 | 结果 | 依据 |
|---|---|---|
| `println!("{}", 'a')` | 打 **97** 不是 `a` | 字符字面量类型是 `i32`(§ 2.1)⇒ 打字符要 `{:c}` |
| `println!("{}", some_ptr)` | **只有 `*u8` 打字符串**;其它指针 / 借用(`*i32` / `&T` / `&mut T`)一律打**地址** | 字符串字面量就是 `*u8`;要地址用 `{:p}` |
| `println!("{}", b)` | **非零即 true** | bool 不归一化(§ 2.1)⇒ 与 `&&`/`||` 的 `jnz` 判非零对齐 |

⚠️ **求值顺序定死**:从左到右、边求值边输出(零额外栈开销,与 § 3.4 现状一致)
⇒ **保证 `f()` 先于 `g()` 求值,但不保证输出原子性** —— 这一点要写进规范。

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| **闭包捕获生成坏代码** ⇒ 运行时炸 | 极难查 | ⚠️ W-115 的教训:实现不了就**编译期报错**,绝不静默 |
| parser 改动面大 ⇒ 回归面大 | 回归风险 | 分步 ship;每步 `-O0` 逐字节不变 |
| 块表达式与现有 `match` / `defer` 交互出错 | 语义错 | 专门用例 + 现有回归门(基线见 [FACTS § 2](../../internal/FACTS.md#2-回归与门)) |
| `#[inline]` 展开条件放宽 ⇒ 产物变化 | byte-equal 门红 | 默认行为不变,展开条件变更单独 ship |
| **宏展开与任务 1 的 `parse_expr` 改动撞车** | 解析回归 | 任务 6 单独 ship ⇒ **两个可单独回滚的点** |
| **宏展开出的临时缓冲区逃逸** | 悬垂指针 | 缓冲区是**展开处的栈变量** ⇒ 生命周期不跨调用 ⇒ 不得把 `&buf` 存进任何结构 |
| **格式串与实参类型不匹配被放过去** | 打印错值 | 分派在**编译期**按静态类型 ⇒ 不匹配**编译期报错**(硬门) |
