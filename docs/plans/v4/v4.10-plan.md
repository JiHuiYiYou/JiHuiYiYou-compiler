## Context

**这一版不是语法美化,而是 P4 与内核 API 的语义基础。**

| 缺什么 | 为什么阻塞 |
|---|---|
| **块表达式** | BootState 本质是**带顺序的状态迁移**;若块不能产生值、函数末表达式不形成连续控制流,状态推进只能在函数边界完成,临时状态与错误恢复会退回全局可变变量 |
| **`fn(...)` 类型位置** | 当前没有函数指针类型语法,而 `#[naked]` interrupt、MS x64 函数指针和 IPC stub 都要求编译器知道参数/返回值的 lowering |
| **闭包捕获** | 阻止 hot helper 携带本地 token,迫使开发者把大量两行函数写成顶层名字 |
| **`()` 类型位置** | 消除「函数指针无类型、闭包不能捕获、函数体末表达式返回不触发 defer」的断裂 |
| **结构化内联汇编** | `asm!` 仍是字符串(abi § 8)—— 只修了「内联位置」这个正确性 bug(W-113),**没做结构化改造** |

⚠️ **闭包捕获目前是编译期明确报错**(MVP 范围外,见 W-115)⇒
**本版要么实现它,要么维持报错** —— 不能静默生成坏代码。

⚠️ **`#[inline]` 只在函数体为单条 `return expr;` 时展开**
⇒ 内核热路径**一个 helper 都内联不了** ⇒ 闭包捕获 + `#[inline]` 是同一件事的两面。

---

## Goal

1. **BootState 迁移可写在块内**
2. **函数指针可跨模块传递**(带 ABI / 效果 / `#[naked]` 匹配检查)
3. **100 个内核 helper 可写成 1–5 行闭包**并被 `#[inline]` 展开
4. **`asm!` 块未声明 clobber 即报错**
5. **`defer` 覆盖末表达式**(当前末表达式返回不触发 defer)

## Scope

### 任务 1 —— 块表达式

```jhyy
fn enable_paging(s: BootState<PagingOff>) -> BootState<PagingOn> {
    configure_cr3();
    if ready() { mark_on() } else { try_fallback() };
    BootState { _token: PhantomData }
}
```
⚠️ 这会**动 parser 与 sema 的表达式解析** ⇒ 回归面大 ⇒ 分步 ship。

### 任务 2 —— `fn(...)` 类型位置

最小方案**不必先实现高阶类型**:只要允许函数类型出现在**参数、变量和返回值**位置,
并强制其 **ABI / 是否 `#[naked]`** 匹配。
⚠️ **「效果」那一维本版不做**(见下面的定案)—— 效果系统在 v4.10.5(OS-7),晚半格。

```jhyy
fn register_handler(cb: fn(ctx: &TrapCtx) -> u64) { ... }
```
⚠️ 报错要指路:
```text
E0801: 函数指针类型不兼容
   = 目标期望：extern "sysv" fn(ctx: &TrapCtx) -> u64
   = 实际签名：fn()
   = 建议：使用完整函数类型，不要将裸地址转为不透明函数指针
```

#### `fn` 类型的**效果行 = 格顶（全部效果）** —— 本版定案

**为什么必须在这一版定**（编译器侧 §3.2 的同一决定）:
完整效果系统在 **v4.10.5(OS-7)**,晚半格。若 `fn` 类型在本版没有效果行、
且默认取 **bottom（无效果）**,则

```jhyy
let f: fn() = sleep;
f();          // ← 调用点无效果信息 ⇒ OS-7 的禁令被绕开
```

是一次**洗白** ⇒ **整条效果系统从这一处漏掉**。

⇒ **本版定案:`fn` 类型的默认效果 = 效果格的顶（全部效果）**。
经函数指针的调用一律**假定被调者可能 sleep / alloc / 中断**
⇒ OS-7 的禁令与后续 P3.5 的锁序、`may_alloc` 规则**都仍拦得住**。
`asm!` 块的效果签名**同样默认格顶**。

代价：间接调用**过度保守**（合法的 `f()` 在 `irq_ctx` 里也会被拒）——
但这是**误拒**不是**漏拒**，且 P3.5 的完整效果格会把它收窄。

⚠️ 本版**还没有** `with { ... }` 显式标注（那是 v4.10.5 的语法）
⇒ 效果行**恒为格顶**；v4.10.5 起可显式收紧。

#### `fn` 调用点必须申报栈预算

本版引入**间接调用** ⇒ 调用图出现断边 ⇒ P2 的 `call_path_max` 从「全程序上界」
退化成**下近似** ⇒ 链接期断言会被绕过。

⇒ **`fn` 类型的调用点必须显式申报栈预算，否则链接期拒绝**
（复用 P0.5 / `v4.7-plan.md` 任务 3 的「递归 / 动态调用显式标记」机制）。

### 任务 3 —— 闭包捕获

⚠️ **W-115 的教训**:闭包捕获外层变量在 MVP 范围外,
旧实现**没有任何检查** ⇒ 生成坏代码(env 压根没传进合成 fn)⇒ 运行时炸。
⇒ **要么实现,要么编译期明确报错** —— 绝不能静默生成坏代码。

### 任务 4 —— `()` 类型位置 + `defer` 覆盖末表达式

消除「函数体末表达式返回不触发 defer」的断裂。

### 任务 5 —— 结构化内联汇编

目标:**类型化操作数、显式 clobber、效果签名**。
```jhyy
asm!("...", in(reg) x, out(reg) y, clobber("cc"), volatile);
```
⚠️ **clobber 未声明即报错** —— 这是「汇编破坏 ABI 假设却无法静态发现」的正解
(OS 需求清单第 22 项)。

⚠️ **效果签名本版恒为格顶**（任务 2 的同一定案）—— 显式 `with { ... }` 是
v4.10.5(OS-7)的语法 ⇒ 本版 asm 块的效果 = 全部效果（假定它可能 sleep / alloc / 中断）。

⚠️ 与 v4.9(OS-5)的 IL 节点承接:本版把 IL 节点的类型化信息真正用起来。

| Risk | Impact | Mitigation |
|---|---|---|
| **闭包捕获生成坏代码** ⇒ 运行时炸 | 极难查 | ⚠️ W-115 的教训:实现不了就**编译期报错**,绝不静默 |
