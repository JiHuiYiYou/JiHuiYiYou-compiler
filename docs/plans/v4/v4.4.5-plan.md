## Context

**这两版是从 v4.2.2 / v4.3.0 降级下来的** —— 降级理由是**实测**,不是判断:

| 版本 | 声称价值 | **实测机会数** |
|---|---|---|
| v4.2.2 peephole | 折叠 no-op | **54** 条 / 407386 行(**0.002%**) |
| v4.3.0 常量折叠 | `2+3` → `5` | 语料 A **0** / 语料 B **84** —— ⚠️ **前端本来就不折叠** |
| v4.3.0 代数化简 | `x+0` → `x` | 54 / 424 |
| v4.3.0 DCE | 删死指令 | 42(0.1%)/ 193 —— 前端产出的 SSA 本来就干净 |

⇒ **性能价值 ≈ 0**,所以降级到 v4.4 之后。
但**降级不等于取消** —— 这一版接住的是两样**非性能**的东西:

**① peephole 的 4096 限制是「.s 级工具的可信度」问题,不是性能问题。**
`.s` 超过 4096 字节就整段跳过 peephole(`peephole.jhyy:545`)
⇒ 真实程序(自举产物 10.4MB)**永远跳过**
⇒ **peephole 只在 hello-world 级输入上跑过**。
不修这条,v4.4 之后任何 **.s 级 pass 的验证都缺一个可信的 .s 级工具**。
根因:`peephole_concat_loop` 静默崩(W-074.6.1 PARTIAL)。

**② IR 层优化框架是 `-O` 开关的载体。**
CLI 现在**完全没有 `-O`**;默认 `-O0` ⇒ 现有 byte-equal 门全绿,零风险。
且 IR 层优化的真实价值不是「省几条指令」,而是 **temp 数下降 ⇒ 帧进一步变小**
(与 v4.2.1 叠加)—— 「**少算**」比「算得更巧」值钱。

---

## Goal

1. **peephole 在真实产物上真的跑**(可观测:fold 计数 > 0)且回归不退步
2. **`.s` 级 pass 有一个可信的工具链**(为后续 .s 级优化铺路)
3. **`-O0` / `-O1` 开关落地** —— 默认 `-O0`,现有 byte-equal 门全部保持绿
4. **IR pass 框架** —— 常量折叠 / 代数化简 / DCE / 不可达代码消除,**默认关**

---

## Scope

### 任务 1 —— peephole 4096 限制真修(W-074.6.1)

- 修 `peephole_concat_loop` 静默崩
- 去掉「`.s` > 4096 字节整段跳过」的限制,或改为分块处理
- **可观测**:peephole 的 fold 计数要能打出来(证明它真的跑了)

⚠️ 自举产物的 `.s` 是 **10.4MB** ⇒ peephole 在这个规模上跑,
必须确认它**不爆内存、不爆时间**。

### 任务 2 —— `-O0` / `-O1` 开关

- CLI 加 `-O0`(默认)/ `-O1`
- `-O0` ⇒ **产物逐字节不变** ⇒ 现有门全绿

### 任务 3 —— IR pass 框架

⚠️ **IR 已经是 SSA**(前端一直产的)—— 框架要建在 SSA 上,不是「先转 SSA」。
pass 清单(默认全关):
- 常量折叠
- 代数化简
- DCE(删除死指令)
- 不可达代码消除

每个优化 pass 必须**声明它保留哪些 metadata**(类型 / 效果 / cap origin / layout /
stack / naked / clobber)—— per
[`docs/coordination/JHYY_编译器侧设计终版.md`](../../coordination/JHYY_编译器侧设计终版.md) § 4.3。

### 任务 4 —— 与寄存器分配的顺序关系

⚠️ **IR 层优化与寄存器分配有耦合**:IR 层少算 ⇒ temp 数下降 ⇒
寄存器分配器的压力模型要能吃这个变化 ⇒ **顺序上 IR 优化在寄存器分配之后**
(所以排在 v4.4.5 而不是 v4.4.0 之前)。

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| peephole 在 10.4MB 上跑爆内存 / 时间 | 构建卡死 | 先量;必要时分块 |
| IR pass 破坏 metadata | 静默错(布局 / cap 事实对不上) | 每个 pass 声明保留哪些 metadata + **`-O1` 与 `-O0` 语义等价**门 |
| `-O1` 与 `-O0` 输出不同 ⇒ 语义变了 | 破坏正确性 | 逐字相同作硬门 |
| 性能价值仍 ≈ 0 | 白干 | **这一版的真实价值是「可信的 .s 级工具」,不是速度** ⇒ 验收门按此定,不按速度定 |
