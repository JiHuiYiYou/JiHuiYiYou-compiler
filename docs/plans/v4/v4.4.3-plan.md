## Context

**这一版是寄存器分配线的收尾** —— 前三版改后端,这一版**把改动的成果变成可长期依赖的门**。

**核心问题:`artifact_checks.sh` 的 14 条门里有 4 条是汇编文本断言** ——
它们认死寄存器名 / 栈槽编号 / 帧布局的**字面形状**:

| 门 | 认死什么 |
|---|---|
| `holds_bitmap` | `%r8` + `%tN` 注释格式 |
| `sysv_memory_class` | `movq %r10, 0(%rsp)` |
| `sysv_arg_spill` | `r8d` / `r9d` / `16(%rbp)` |
| `per_fn_frame` | `subq $N, %rsp` 的形状 |

⇒ 寄存器分配器会**同时**改寄存器名、栈槽编号、帧布局 ⇒ **这 4 条会红**。

⚠️ **改门和改后端混在一起会掩盖真实回归** —— 这是本版单独存在的理由:
门必须**先**去耦合(独立成 v4.3.1 那一格),**再**让寄存器分配改后端。
否则「门红了 → 改门」和「后端错了 → 门红了」分不清。

---

## Goal

1. **4 条文本耦合门改成语义判定** —— 不再认死寄存器名 / 栈号 / 字面形状
2. **寄存器分配的效果变成常驻门** —— 覆盖率 / 访存数 / 产物不变,三条都进 CI
3. **perf 数字每版记录** —— 形成时间序列,让「有没有变快」可追
4. **寄存器分配可以默认开**(可选)—— 前置是三条门都绿

---

## Scope

### 任务 1 —— 4 条门去文本耦合

做法:
- **能改语义判定的改语义判定** —— 例如「base temp id > 65536」而不是「某一行含 `, %r8`」
- **改不动的登记成 expected-FAIL 风格** —— 明确标注「暂时无法语义化」,而不是留一条会红的门

### 任务 2 —— 寄存器分配的常驻门

| 门 | 内容 |
|---|---|
| **`-O0` 产物逐字节不变** | 分配器默认关时,现有门全绿 |
| **访存指令数不回升** | `runtime_perf.py` 静态指标 `mem` —— **静态指标硬门**(跨机器逐字节相同) |
| **产物可复现** | 同一编译器连编两次 `.s` 逐字节相同(W-121 已修,不许回退) |
| **分配了寄存器但走槽位路径 ⇒ 编译失败** | v4.4.0 起的响亮失败,不许被绕过 |
| **volatile / XMM / red zone 三条约束** | v4.4.0 起,常驻 |

⚠️ **CI 里的性能门是静态指标硬门**(指令数 / 访存数 / 帧大小 / chkstk 次数,
确定性 ⇒ 跨机器逐字节相同),**墙钟只报告** —— 共享 runner 的宿主负载不可控。

### 任务 3 —— perf 数字时间序列

每版记录 `runtime_perf.py` 的静态指标 + 墙钟,写进
[`docs/perf`](../../perf/) 下的基线文档 ⇒ 让「有没有变快」可追、可对比。

### 任务 4 —— 分配器默认开的评估(可选)

前置:三条门都绿 + 产物可复现门绿。
⚠️ 默认开会让**所有**现有 byte-equal 门失效(产物变了)⇒ 需要重新 baseline。
⇒ 这一步**默认不做**,除非用户明确拍板。
