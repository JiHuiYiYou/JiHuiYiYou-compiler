# v4.0.1 — W-074.6 multifn silent-fail 真修 → promote v4.0.0-rc1 → v4.0.0

## Context

v4.0.0-rc1 shipped 2026-09-30 with `jhyy_selfhost_check N≥3 src0/main.jhyy byte-equal` documented as **KNOWN-LIMITATION** (pre-existing W-074.6 multifn silent-fail bug per `feedback_codegen_amd64_multifn`). This plan closes that gap so v4.0.0-rc1 can be promoted to v4.0.0 final.

**Bug pattern** (verified 2026-09-30 on both axis-v2 v2.16.0 baseline + v4.0.0-rc1 main):
- 1-function `.jhyy` (e.g. `hello.jhyy`, `fmod_basic.jhyy`): self-host compile ✅ → .s + .exe produced
- 2+ function `.jhyy` (e.g. `fib_renamed.jhyy`, `struct_val_pass.jhyy`, `src0/main.jhyy`): self-host compile → exit=0 but **.s missing some functions** (main_jhyy dropped silently)
- `src0/main.jhyy` self-compile: gcc link fails with `ld returned 5 exit status` because main_jhyy not in .o

**Root cause family** (per W-074.6 ACTIVE state at v2.16.0 CHANGELOG):
- `codegen_amd64.jhyy` `parse_and_emit` state machine has bugs that surface on multi-function .il
- `emit_binop cnew` + `emit_jnz loop body entry silent-skip` (per v2.11.10 CHANGELOG)
- `emit_ret` 不 `mov %t1 → %eax` (pre-existing)
- Multi-func body 0-byte pre-existing (per `feedback_codegen_amd64_run_zerobyte`)
- `extsw` silent-skip + `idiv` sign-extend + `rem` keyword (per v2.11.9) — QBE side ✅ closed, self-side NOT yet

**Scope estimate**: ~500+ LOC across `codegen_amd64.jhyy` + `codegen_amd64_emit_sse.jhyy` + `codegen_amd64_xmm_argalloc.jhyy` + `codegen_amd64_inmem.jhyy` + `codegen_amd64_lexer.jhyy`. Multi-sprint per `feedback_codegen_amd64_multifn` + `feedback_codegen_amd64_run_zerobyte`.
