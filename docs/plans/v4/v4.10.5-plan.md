## Context

**这一版只做两个效果:`irq_ctx` 与 `may_sleep`。**

**为什么把它排在完整效果系统(P3.5 / v4.13)之前** —— 这是自审的一条修正:

第一轮称效果系统为「最高价值项」,但排到了 P3.5(依赖 P3 的函数类型与闭包)。
这个依赖链**是真的**,但**低估了一件事**:

> **「穷人版」效果系统不需要等。**

只做两个效果 `irq_ctx` 和 `may_sleep`,机制是:
- 函数签名上写 `with { irq_ctx }` / `with { may_sleep }`
- 调用点做**直接禁止检查**(**不做全推导、不做多态效果、不做效果变量**)

这就足以拦住 Linux 最高频的两类 bug —— `might_sleep()` 现在守的那两个位置。
**成本极低,不需要块表达式或 `fn` 类型。**

⚠️ **它是完整效果系统的安全网**:如果完整系统迟迟不来,
至少「持锁睡眠」「中断中非法 sleep」这两类已经编译不过。

---

## Goal

1. **`irq_ctx` 内调用 `may_sleep` / `may_alloc` 编译失败**
2. **语法可用**:`with { irq_ctx }` / `with { may_sleep }` 写在函数签名上
3. **不需要完整推导** —— 只做直接禁止规则(不做全推导、不做效果多态)
4. **不影响 `-O0` 产物**(除非函数真用了 `with`)

---

## Scope

### 任务 1 —— 语法

```jhyy
fn wait_event() -> Event
    with { may_sleep };

fn handle_page_fault(ctx: &mut TrapCtx)
    with { irq_ctx = handler, preempt_disabled }
{ ... }
```

⚠️ 这是**签名上的附属语法**,不是类型系统的参数 ⇒ 解析与 sema 都要改。

### 任务 2 —— 效果传播(最小版)

- 缺省时 Sema 从函数体**自底向上**计算效果格上确界
- 调用时,被调者的效果**必须是当前允许效果的子集**
- 进入 `irq_ctx` / 持锁 / `preempt_disabled` 后,调用点只允许
  `may_sleep = false`、`may_alloc = false`

⚠️ **本版只做「直接禁止」** —— 不做效果变量、不做多态效果、不做 handler。

### 任务 3 —— 禁止规则

| 当前上下文 | 禁止调用 |
|---|---|
| `irq_ctx` | 声明 `may_sleep` 的函数 |
| `irq_ctx` | 声明 `may_alloc` 的函数 |
| `preempt_disabled` | 声明 `may_sleep` 的函数 |

### 任务 4 —— 错误信息要给路

```text
E0510: 在禁止睡眠的上下文中调用可能睡眠的函数
  --> kernel/src/fault.jhyy:60:13
   |
60 |         wait_event();
   |         ^^^^^^^^^^^
   |
   = 当前上下文：irq_ctx = handler, preempt_disabled
   = 被调函数声明：{ may_sleep }
   = 建议：把等待移到可睡眠上下文，或使用非阻塞 try 路径
```

⚠️ **报错必须指出迁移路径**,不能只说「不匹配」——
这是 OS 需求清单反复强调的:错误信息要能直接指导修法。
