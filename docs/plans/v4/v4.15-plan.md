## Context

**这一版的定位:不是「避免静默越权」,而是「发现更多错误」。**

⚠️ **排序理由(明确的)**:
> KCFI、shadow stack 和 WCET **不应与 P2 栈分析同权**。
> 它们重要,却依赖函数类型、调用图、ABI 稳定和实时模型。
> **P2 必须先保证最坏栈不会溢出**;插桩工具是「发现更多错误」,不是「避免静默越权」。

⇒ 所以它们排在 OS 线的最后一格,而不是 P1 / P2。

**为什么需要它** —— 内核**无栈展开**:
没有 unwinding ⇒ 故障与越界**更难恢复** ⇒ 需要工具在**故障发生前**就把它们抓出来。

**四个插桩 + 两项元数据**:

| # | 工具 | 拦什么 | 依赖 |
|---|---|---|---|
| 1 | **KASAN** | 越界 + use-after-scope | address space、unsafe 边界 |
| 2 | **KMSAN** | 未初始化来源传播 | **def/use** |
| 3 | **KCFI** | 函数指针目标 type id 不匹配 | **函数类型**(v4.12)+ 调用图(v4.7) |
| 4 | **shadow stack** | 返回地址被改(ROP) | call graph、noreturn |
| 5 | **WCET class** | 实时路径无上界 | loop bound、cache/ILP 模型 |
| 6 | **panic 分类 + layout 差分** | 故障不可区分 / 布局漂移 | noreturn / 字段指纹 |

⚠️ **实现顺序有依赖**:KASAN → KMSAN → KCFI → shadow stack,
因为**前两者依赖更强的 def/use/SSA,后两者依赖函数类型和调用图**。

## Scope

### 任务 1 —— 插桩框架

**可组合的 instrumentation group**:
- 插桩在 **IL 层**插入(不是在汇编层文本匹配)
- **保留 source mapping**
- 在汇编发射时生成符号
- 每个插桩 pass **声明它保留哪些 metadata**(类型 / 效果 / cap origin / layout / stack / naked / clobber)

⚠️ **插桩 pass 默认关** —— 与「优化 pass 默认关闭,正确性 pass 默认开启」是同一条纪律。

### 任务 2 —— KASAN

- 越界检测(红区 / shadow memory)
- use-after-scope
- ⚠️ **依赖 address space 信息** ⇒ 依赖 v4.13(OS-12)的 `ptr<user>` / `ptr<kernel>`

### 任务 3 —— KMSAN

- 未初始化值的来源传播
- ⚠️ **依赖 def/use** ⇒ 依赖 SSA 强度(v4.4.2 的 dominance / def-use)
⇒ **这是本版排在最后的原因之一**。

### 任务 4 —— KCFI

- 函数指针的 type id 校验
- ⚠️ **依赖函数类型**(v4.12 OS-9)与**调用图**(v4.7 OS-2)
- 与 v4.14(OS-14)的 `#[ipc_handler]` 契约互补:契约查**编译期**,KCFI 查**运行期**

### 任务 5 —— shadow stack

- 返回地址备份 / 检查
- ⚠️ 依赖 call graph 与 noreturn 判定

### 任务 6 —— WCET class

- bounded class + 假设 + 局部上界
- ⚠️ **WCET 上界是「二等事实」(分析结论,不是类型)** ⇒ 不参与泛型单态化
- ⚠️ 规范**没有**记载目标架构的 timing model / cache / 流水线参数 ⇒ **需要先定义**

### 任务 7 —— panic 分类 + 终止面

**无栈展开不是「没有错误处理」,而是必须定义错误终止面。**
内核至少区分三类事件:
1. 普通错误 → 返回值传播
2. 可恢复 fault → 投递到 capability endpoint
3. 不可恢复 fault → 线程终止 / namespace revoke / kernel oops

**必须明确「oops 之后能否继续运行」** —— 若继续,哪些全局状态需要 quiesce;
若不能,哪些子系统可以独立重启。
⇒ **分类必须由内核与编译器共同冻结**(规范当前无 panic / unwind)。

### 任务 8 —— layout 差分测试

- 每次 CI 生成 layout 指纹
- 与 baseline 比对
- 报 first differing field
⇒ ⚠️ **指纹不含字段名**(重命名不改 ABI)。

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| **def/use 强度不够** ⇒ KMSAN / KCFI 做不了 | 本版缩水 | ⚠️ 本版排在最后就是为此 ⇒ 启动时先评估 |
| 插桩改变语义 ⇒ 测出来的问题是插桩的 | 误判 | 「插桩前后行为语义一致」作硬门 |
| shadow region 布局与内核不一致 | 运行期崩 | 需要内核侧协作接口 ⇒ 规范未记载 ⇒ 要新设计 |
| WCET 模型不现实 ⇒ 报的上界无意义 | 无效约束 | 标注假设;不要假装是证明 |
| panic 分类单方面定 ⇒ 与内核不一致 | 语义冲突 | **必须与内核侧共同冻结** |
