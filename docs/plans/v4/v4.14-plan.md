## Context

**当前状态**:`Cap<T>` 的 `T` **不被解析**,inner 硬编码成 `i32`
⇒ `Cap<i32>` 与 `Cap<i64>` **是同一个类型**
⇒ **wire 已具备对象身份,语言层却还不能把对象身份对应到对象类型。**

**这一版要做的**:
把授权链从 **wire 提升到类型** —— 让「frame cap 不能进 endpoint 接口」
成为**编译不过**,而不是运行时的意外。

**这是 JHYY 相对 Rust/C 最值得固化的结构优势** ——
Rust 里 `PhysAddr` 通常只是一个整数,或 `NonNull` / `*mut` 加上文档约定;
JHYY 已有 capability 底座,可以让物理指针**天然带授权溯源**。

## Scope

### 任务 1 —— `Cap<T>` 真 T

**编译器侧影响清单**:

| 阶段 | 改动 | 复杂度 |
|---|---|---|
| Lexer | 新增 8 个保留字(`R`/`W`/`G`/`RW`/…) | 低 |
| Parser | 解析 `Cap<T, R>` 双参数 | 中 |
| **Sema** | **8 项 rights 常量表 + 类型等价加掩码比较 + derive 子集检查 + `as` 转换表禁止规则** | **中(核心)** |
| Mangling | `<Base>$<T1>$<T2>` 直接扩展 | 低 |
| IL | **不新增 IR 概念** —— 8 字节标量走 `l` | 低 |
| 后端 | 无特殊处理;`ptr<io>` 需禁重排/合并/投机 | 中 |
| 链接 / `.jhyynb` | cap_init 生成 + provenance_seed 填充 + contract 输出 | 中 |

### 任务 2 —— 8 个内置 rights 类型

```
None · R · W · G · RW · RG · WG · RWG
```

**为什么不用 const generic 位集 / 依赖类型**:
- const generic 位集:与名义类型系统冲突(常量不是声明名);单态化上界 2^16 失控
- 依赖类型(`where new_rights <= src.rights`,`new_rights` 是**运行时值**):
  JHYY **没有 trait、没有 const 泛型、没有任何约束表达机制** ⇒ 不可实现

**子集检查 = 编译期一条位运算**:`TargetR.mask & !SrcR.mask == 0`。

### 任务 3 —— 派生 API 与四条规则

```jhyy
fn derive<T, SrcR, DstR>(src: &Cap<T, SrcR>) -> Cap<T, DstR>          // 静态
fn derive_dynamic<T, SrcR>(src: &Cap<T, SrcR>, want: u16) -> Option<Cap<T, RWG>>
fn narrow<DstR>(c: &Cap<T, RWG>) -> Option<Cap<T, DstR>>
```

| # | 规则 | 检查阶段 |
|---|---|---|
| R1 | 派生只能清位,不能置位 | 编译期 |
| R2 | root 的 rights ⊆ 对象类型允许集 | 编译期(manifest 驱动) |
| R3 | 映射类操作可附加 VM rights,但不产生新 capability rights | 编译期 |
| R4 | G 不能由 R/W 派生得到 | 编译期 + 运行期 |

### 任务 4 —— `ptr<phys>` 派生 + `as` 禁止规则 ⭐

**性价比最高的一条**:sema 的 `as` 转换表里加一行禁止规则
—— **改动量一行,收益是堵死一整类物理地址越权**。

```jhyy
整数 / 任意指针  --as-->  ptr<phys>     ❌ E0603
```

### 任务 5 —— `as Cap` 收敛

⚠️ **注意:版本轴表里写的是「`unsafe` + `from_raw`」,但已定稿的结论是「不引入 `unsafe` 关键字」** ——
本版按**属性方案**走,版本轴那一格文字要同步订正。

| 措施 | 内容 |
|---|---|
| 唯一入口 | `from_raw`;`as Cap` 保留为 **deprecated 别名** |
| 范围限定 | `as Cap` **只在 `#[trusted]` 范围内可用** ⇒ 普通模块里写 ⇒ **编译期报错** |
| 属性 | `#[trusted]`(模块/文件级)+ `#[unsafe_cap_ctor]`(函数/语句级) |
| 可审计 | `unsafe_ctor_count` + `unsafe_ctor_offs` 进 contract section ⇒ CI 可断言 `kernel.efi` 的 count ≤ N 且只在 bootstrap 模块 |

**理由**:内核 bootstrap 阶段**确实需要**手工构造 root cap(先有鸡才有蛋)
⇒ **后门在语义上不可消除,只能让它可审计**。

### 任务 6 —— `#[ipc_handler]` 全契约

编译器在一个 `.jhyynb` 内检查:
tag 唯一(或 `service_version+tag` 复合 key 不冲突)· handler 签名与 message/reply struct **双向一致** ·
每个 `Cap<T>` 字段落在合法对齐槽 · `cap_offsets` 不重叠不越界 · rights 不超 ABI 携带范围 · 栈与效果合法。

### 任务 7 —— contract section(kind=9)

**不能用 "debug" 命名承载安全契约** —— 否则旧 loader 会把能力栈预算当可选调试信息忽略。

```
kind = 9  contract    loader 必须验证,验证失败拒绝加载
kind = 6  debug_group 可选,可剥离
```

承载:栈上界 · 效果表 · 锁序图 · IPC handler version · panic category · WCET class ·
cap_offsets 位图与 type_tag allowlist。
⚠️ 必须带 **version / producer ID / source hash / compatibility policy**。

### 任务 8 —— `.jhyynb` 实装

⚠️ **binary-format v1.0.0 至今是设计稿,未实装**(abi §12.10)⇒ 本版是它第一次落地。

### 任务 9 —— slot generation 的 wire 字段改名

`padding:u8@7` ⇒ `gen:u8`,语义 = slot 复用代数。

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| **wire 布局未定就动手** ⇒ 字节错位 1 | **静默读写错位** | ⚠️ Cap wire 的 rights 偏移必须先确认(v4.9) |
| **对象语义未冻结就改类型** ⇒ 第二次 ABI break | 返工 | manifest 先冻结(v4.13.5) |
| `as Cap` 后门未收敛 | 授权可凭空构造 | `#[trusted]` 限定 + `unsafe_ctor_count` 可审计 |
| **`ptr<io>` 的 volatile 承诺后端给不了** | MMIO 静默失效 | ⚠️ v4.4.0 阶段二接口 A 必须先做完 |
| contract section 被旧 loader 忽略 | 安全契约形同虚设 | **独立 kind + 版本 + compatibility policy**;验证失败拒绝加载 |
| 89 种 type_tag × rights 组合的单态化膨胀 | 编译时间 | 上界可控(11~12 类 × 8 种 = 88~96 种) |
