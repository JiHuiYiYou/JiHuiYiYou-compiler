**v4.1.6 改了什么。**

这一版的主题是「**静默缺陷清零**」—— 台账里那批「**不报错、只是产物是错的**」的条目,
一次全清:**每一条都变成「一条编译期报错」或「一个正确结果」**。

### 编译器:9 条静默缺陷 ⇒ 报错或正确结果

| 缺陷 | 症状 | 现在 |
|---|---|---|
| W-228 | 整数字面量**超出声明类型范围**被静默接受 ⇒ 常量折叠与运行时不一致 | 编译期报错 |
| W-229 | 把**函数名当值**用 ⇒ codegen 崩 + 产物爆栈 | 编译期报错(不再崩编译器) |
| W-230 | 栈位置的实参传 `null` ⇒ caller 只写 4 字节 ⇒ callee 收到带残渣的指针 | 正确结果 |
| W-231 | struct 字面量里的 `null` 字段 ⇒ 误报 `field type mismatch` | 正确结果 |
| W-232 | 顶层 `const` 标量 ⇒ 报错文案指向「语法」而不是「顶层 const 只支持数组」 | 说人话 |
| W-233 | 字符串字面量 `as [*]u8` ⇒ 切片的 len 没填 ⇒ 读元素越界 ⇒ 访问违例 | 正确结果(非字面量的指针→切片 编译期拒绝) |
| W-234 | 顶层 `const` 数组的元素写成 `1 as i32` ⇒ **静默读出 0** | 正确结果 |
| W-235 | 窄类型(`i8`/`u8`/`i16`/`u16`)的局部变量既不截断、也不回绕 | 按窄宽度算(与规范 § 4.2 / § 4.3 一致) |
| W-236 | 调用**不检查实参个数** ⇒ 少传/多传 ⇒ 编译通过 ⇒ 参数**全是垃圾** | 编译期报错(`extern fn` 除外) |

### 顺带修掉的两条

- **W-226** —— 链接失败时 gcc/ld 的**真实原因**被吞掉 ⇒ 用户只看到「ld returned 1 exit status」。
  ⇒ 现在编译器**自己**判定「入口符号缺失」并点名它。
- **W-227** —— AST dump 的 64 位 hex 打印把 `a`..`f` 打成 `W`..`\` ⇒ 浮点位模式全错。
  ⇒ 现在 `bits=0x…` 是合法 hex。

### 编译器自己的两个洞(被新加的「实参个数」检查当场抓出来)

- **W-237** —— `mono.jhyy` 调 `ast_new_slice_lit` **多传一个实参** ⇒ 切片子节点的 array 字段指错。
- **W-238** —— `mono.jhyy` 调 `ast_new_for` **少传一个实参** + 按**旧布局**读 `NodeFor` ⇒ 循环体是残渣。

⇒ ⇒ 新加的检查不是「只会报错的摆设」—— 它第一轮就抓到编译器自己的两处调用错误。

### 门

- 回归 **281 → 290**(新增 **9** 个用例 —— 9 条缺陷的复现件从 `known-bugs/` 搬进正式套件);
- 产物级门 **21 → 23**(新增 `link_entry_diag` / `dump_float_hex`);
- 台账 **ACTIVE 0 → 0**(这批 9 条修完);条目总数 **220 → 234**;
- 基准套件的静态指标基线**重取一次**(窄类型截断要发扩展指令 ⇒ 3 道题指令 +3、帧中位数 +16 字节;
  其余 6 道题一字未变)。

### 配套工具(仓内,不随安装包发布)

- **MCP**:新增 `jhyy_error_lookup`(编译器报错 → 该改哪)、`jhyy_lang_ref` 支持按章节号精确取;
  诊断文本带上「怎么改」的修复线索。
- **IDE 知识包**:从规范与标准库源码生成,随 IDE 安装包发给用户 —— 台账里「还没修的坑」一节
  **自动从台账抽取**,台账一改、重新生成就没了 ⇒ 零人为维护。
