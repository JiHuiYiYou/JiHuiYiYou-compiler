**v4.1.4 改了什么。**

这一版的主题是「**别再静默算错**」—— 把一批**不报错、不崩、只是算错**的缺陷
连根拔掉,再把发布链上那些「绿灯是造出来的」的门改成真的。

### 编译器:算错的那几类

- **调用点的实参上限曾经写死 16** ⇒ 第 17 个及以后的实参被**静默丢弃**
  ⇒ 一个 20 个参数的求和算出 **117**(正确值 210),Win 与 SysV 都错、零诊断。
  ⇒ 现在实参数组按需扩容;「实参装不下」不再静默截断,而是**编译末尾响亮失败**。
- **SysV 的整数/浮点栈实参没有 outgoing 区** ⇒ 栈实参写进**调用者自己帧的最底部**
  ⇒ 一个 14 参数的调用把调用者的 3 个活值全毁 ⇒ 算出错值(EXIT=6,期望 1139)。
- **浮点栈实参借 `%xmm15` 中转** ⇒ SysV 的 XMM8-15 是 **callee-saved**
  ⇒ 我们编出来的函数写坏 `%xmm15` 就是 **ABI 违规**。Win 上永远看不出来
  (XMM 全易失)⇒ 只有 SysV 会坏 ⇒ 改用整数 scratch 搬原始比特。
- **范围模式的端点写成标识符**(`x..y`)⇒ ① 绑定的符号名字变成 `..`
  ② 整个 arm 被编成「**接受一切**」⇒ 静默走错 arm、零诊断
  ⇒ 现在**编译期拒绝**(端点必须是字面量)。
- **整数/浮点字面量越界**以前**静默饱和**成 `LLONG_MAX`
  ⇒ `sizeof([i32; 99999999999999999999])` 算出 **-4** ⇒ 现在编译报错。

### 编译器:崩的那几类

- `for i in <slice>` ⇒ **空指针写**(合法输入让编译器崩);
- OR 模式的第一个 pattern 非法 ⇒ **空指针解引用**;
- 路径缓冲区越界 ⇒ 一个约 1000 字符的 import 名曾把编译器打成 `STATUS_HEAP_CORRUPTION`;
- stderr 管道 **死锁**(4096 字节缓冲);
- 深层嵌套表达式 ⇒ **栈溢出** ⇒ 现在是编译错误。

### 编译器:别再打扰用户的那几类

- **用户程序的 stderr 以前被整个吞掉** ⇒ 现在看得见;
- **每次编译漏 5 个临时文件** ⇒ `%TEMP%` 里一度堆了 **11 万多个**孤儿
  ⇒ 现在一个不留(实测:连续编译 5 次,新增 0 个)。

### CLI 与门面

- `jhyy` 与 `jhyy --help` 现在打同一份 help;`jhyy dump` 真的打印 AST 树
  (以前是 stub);链接交叉目标会被**拒绝**而不是静默产出一个坏的 Windows PE;
  `--no-link` 在命令行任何位置都认;未知选项直接报错。

### 门:把「绿灯是造出来的」改成真的

- **跳过的检查现在算失败** —— 「没跑成」不再等于「通过」;
- **SysV 门真的跑 W-127 那道守卫**(以前静默跳过);
- **发布链钉住 ref、比对 head_sha** ⇒ 不发布与 tag 不符的产物;
- **`SHA256.txt` 真的被验**(以前只打印不比对);
- **winget / scoop manifest 修好**(以前装反了类型)并通过本机 `winget validate`。

### 供应链

- 发布链的 8 个 GitHub Action 全部**钉到 commit SHA**;
  .NET SDK / WiX / vsce 钉到确定版本 ⇒ 同一个 tag 两次发版不会再跑在
  两套不同的工具链上。

### 台账

- **ACTIVE workarounds:0 → 0**(本版修掉的 13 条 + 顺带挖出的 1 条全部 RESOLVED);
  另有 3 条复核后判定**不是缺陷**,连证据一起记进台账。

### 上一版(v4.1.3)的要点

**`u32` / `u64` 的除法与取模按无符号算、有符号 `>>` 改成算术右移、
`u32 → i64` 零扩展、整数字面量按 `u64` 精确求值(越界即编译错误)。**
