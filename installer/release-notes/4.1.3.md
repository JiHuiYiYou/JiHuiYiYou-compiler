**v4.1.3 改了什么。**

### 编译器语义（这一版的主角）

- **`u32` / `u64` 的除法与取模按无符号算** —— 以前一律走有符号的 `div` / `rem`
  ⇒ `2728898079u32 / 761116571u32` 得 `-2`（不是 `3`），`u64::MAX / 2` 得 `-1`
  （不是 `2⁶³−1`）。⇒ 判据是**左操作数**的类型。
- **有符号 `>>` 改成算术右移（补符号）** —— 以前一律是逻辑右移（零填充）
  ⇒ `-16 >> 2` 得 `1073741820`（不是 `-4`）。⇒ 左操作数是**有符号**整型时补符号。
- **`u32 → i64` 的加宽改成零扩展** —— 以前是符号扩展
  ⇒ `4000000000u32 as i64` 得 `-294967296`（不是 `4000000000`）。
- **整数字面量按 `u64` 精确求值** —— 以前走 `strtoll`，量值 ≥ 2⁶³ 时按 C 标准
  **静默饱和成 `LLONG_MAX`** ⇒ 所有 ≥ 2⁶³ 的 `u64` 字面量都变成同一个数。
  ⇒ 现在：越界（≥ 2⁶⁴，或 `i64` 装不下）**编译报错**
  `integer literal out of range`（静默饱和会让「写错了」与「写对了」产出同一个值，
  用户无从察觉）；`-9223372036854775808i64`（`i64::MIN`）**差 1** 的那个洞也一并修掉。
- **模块级 64 位全局的初值不再丢** —— 以前 `let mut g: u64 = 18446744073709551615u64;`
  在数据段里被**从中间切断**（静默错值），负值则直接**编译不过**。

### 标准库

- **`std::fmt` 的有符号打印族**：`fmt_i64(i64::MIN)` 以前只打出一个 `-`
  （不是 `-9223372036854775808`）、`fmt_i32(i32::MIN)` 同理、
  `fmt_hex_u32(v ≥ 0x80000000)` 打出**空串** ⇒ 三个都真修了。

### 测评与门（对外可复现的那张表）

- **新增 `bench/` 测评套件**（9 道题：整数 / 浮点 / 字节 / 堆四个覆盖轴）+
  测量地板口径 + 方法学文档 ⇒ 快照见 `bench/baseline/RESULTS-2026-11-04.md`。
- **随机程序差分对拍**：随机生成 C 与 jhyy 两份程序，逐字比 stdout
  ⇒ 已知缺陷清单**已清空**（两个真缺陷修完了）⇒ 规避开关摘空
  ⇒ 这道门现在是**真正的回归门**。
- 顺带修好了**三道自己坏了的门**：自举闭环门认错了产物名（自 2026-11-01 起就跑不完）、
  事实链变异测试把回归数写死（回归数一变就自己变红）、
  变异测试的整链组缺摘要时「跳过」却仍报「全部被门抓到」。
